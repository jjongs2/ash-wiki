# 린트

주제 전체를 놓고 봐야 드러나는 문제를 찾는다. 린트가 맡는 범위와 용어는 `CONTEXT.md`를 따른다.

먼저 읽는다: `docs/wiki-conventions.md`, `docs/wiki-verification.md`의 출처 상태 절. 린트는 게시된 페이지와 출처만 본다.

## 1. 모으기

- 주제 태그(또는 그 하위 태그)를 단 `content/`의 페이지를 모두 읽는다.
- 위키 전체의 슬러그, `title`, `aliases`를 훑는다. 다른 주제에 같은 개념이 있는지 보기 위해서다.
- `npm run source-status -- --topic <주제 태그>`를 돌린다.

## 2. 찾기

| 항목           | 찾는 것                                                     |
| -------------- | ----------------------------------------------------------- |
| 페이지 간 모순 | 두 페이지가 같은 사실을 다르게 말한다                       |
| 중복 개념      | 두 페이지가 같은 개념을 다룬다                              |
| 용어 불일치    | 같은 개념을 페이지마다 다른 용어나 표기로 부른다            |
| 태그 정합      | 주제에 속하는데 주제 태그가 없거나, 속하지 않는데 달려 있다 |
| 위키링크       | 다른 페이지의 개념이 처음 나오는 자리에 위키링크가 없다     |
| 출처 상태      | `source-status`가 `FAIL`로 찍은 URL과 검증일                |

완료: 주제의 모든 페이지 쌍을 여섯 항목으로 대조했다.

## 3. 가르기

찾은 것마다 둘 중 하나로 가른다. 기준은 **고친 뒤에도 모든 주장의 내용과 인용이 그대로인가**다.

- 그대로면 **수정**: 태그, 위키링크, 이미 정한 용어로 표기 통일
- 아니면 **이슈**: 그 밖의 모든 것. 출처 상태는 재검증이 필요하므로 항상 이슈다.

용어 선택 자체가 갈리면 위키 규약의 용어 절대로 `term:` 이슈를 따로 올린다.

## 4. 수정 PR

수정이 있으면 PR 하나로 올린다. `npm run check:content`가 모두 `OK`여야 한다.

- 제목: `content: <주제> 린트 수정`
- 브랜치, 본문: `CONTRIBUTING.md`를 따른다. 이 린트를 부른 티켓이 있으면 그 번호를 쓰고 `Closes`로 닫는다. 없으면 브랜치는 `content/lint-<주제>-<YYYY-MM-DD>`로 두고 `Closes` 줄을 뺀다.

## 5. 이슈

이슈로 간 것이 있으면 이슈 하나를 올린다.

- 제목: `lint: <주제> <YYYY-MM-DD>`
- 라벨: `needs-triage`
- 본문: 항목마다 `## <항목>` 절. 줄마다 관련 페이지 슬러그(또는 bib 파일)와 한 줄 설명을 적는다.

마지막으로 PR과 이슈 링크를 소유자에게 알린다.
