# 회고

위키 스킬을 실행한 세션의 기록을 읽어 스킬의 개선점을 찾는다. 용어는 `CONTEXT.md`를 따른다.

회고는 보강이나 주제 계획 한 번이 낸 티켓의 재조사 PR이 머지된 뒤에 돌리기를 권한다. 그 티켓이 인제스트와 재조사에서 어떻게 쓰였는지 한 회고 안에서 잴 수 있고, 세션들이 대개 같은 스킬 판으로 돈다. 그런 실행 둘의 티켓이 겹쳐 돌았으면 함께 묶는다.

먼저 읽는다: 분석할 세션이 실행한 스킬, `docs/adr/0001-isolation-boundary.md`, `CONTRIBUTING.md`.

작업 파일은 저장소 밖, 세션의 scratchpad 디렉터리(없으면 `mktemp -d`)에 쓴다.

## 1. 입력

**보관 폴더**는 `~/documents/ash-wiki-retro/`다. 세션마다 요약본과 분석 보고서를 `<uuid>/`에 두고, 회고가 분석한 세션을 `analyzed.tsv`(세션 uuid, 회고 세션 uuid, 날짜)에 적는다. 회고 세션 자리의 `-`는 분석 없이 넣은 세션이다(목록을 처음 만들 때의 옛 세션, 소유자가 뺀 세션). Claude Code가 오래된 세션 기록을 지워도 무엇을 분석했고 무엇이 나왔는지 남기기 위해서다.

**후보 세션**은 위키 스킬을 부른 세션 가운데 `analyzed.tsv`에 없는 것이다. 이 세션은 뺀다. 아래 명령은 스킬을 부른 줄과 핸드오프를 쓴 줄만 잡는다. 이 명령을 글자로 담거나 핸드오프를 읽기만 한 기록은 걸리지 않는다(JSON에서 따옴표가 escape된다).

```sh
grep -l -E '"content":"<command-message>(wiki-[a-z]+|reader-testing)</command-message>|"name":"Skill","input":\{"skill":"(wiki-[a-z]+|reader-testing)"' \
  ~/.claude/projects/*ash-wiki*/*.jsonl > <scratchpad>/skill.txt
cut -f1 ~/documents/ash-wiki-retro/analyzed.tsv
xargs grep -l -E '"name":"(Write|Edit)","input":\{"file_path":"[^"]*/documents/ash-wiki-handoff[-/][^"]*\.md"' < <scratchpad>/skill.txt
```

후보를 표로 대화에 보이고, 세션마다 지금 분석, 나중에, 뺌 가운데 무엇으로 할지 소유자에게 묻는다. 세션이 끝났는지, 넘긴 일의 결과가 나왔는지는 소유자가 가장 잘 알기 때문이다. 열은 판단 거리다.

| 열                 | 채우는 법                                                                                                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 스킬, 시작일, 제목 | 스킬을 부른 줄, 기록의 첫 `timestamp`, `custom-title` 줄                                                                                                                     |
| PR과 상태          | 아래 티켓과 리뷰 요약 항목의 PR                                                                                                                                              |
| 넘긴 일과 상태     | 기록에서 `gh issue create`, `gh issue comment`, `gh pr comment`가 돌려준 URL(`verify:` 코멘트, `lint:` 이슈, `범위 밖` 이슈, 모음 이슈 코멘트, 발행한 티켓)과 그 이슈의 상태 |
| 핸드오프           | 위 셋째 명령에 걸리는가                                                                                                                                                      |

- **지금 분석**이 대상 세션이다.
- **나중에**는 목록에 적지 않아 다음 회고에 다시 나온다.
- **뺌**은 분석할 거리가 없는 세션(중간에 끊긴 세션 등)이고, 바로 `python3 -B .claude/skills/wiki-retro/digest.py --mark - <uuid>...`로 목록에 적는다.

대상 세션마다 아래를 찾는다.

- **서브에이전트 기록**: 세션 기록 옆 `<uuid>/subagents/`
- **세션 판**: 세션이 실제로 따른 스킬 판의 커밋. `git worktree add`로 만든 worktree에서 돌았으면 그 base(`grep -o -m1 'HEAD is now at [0-9a-f]*' <세션 기록>`의 첫 줄)이고, 그 줄이 없으면(`-q`로 만들었거나 main에서 돎) 세션을 시작할 때의 main(`git rev-list -1 --before=<기록의 첫 `timestamp`> origin/main`)이다. 로컬 main이 낡았을 수 있으니, 기록에서 스킬을 부른 줄(`Base directory for this skill:`)의 본문을 그 커밋의 SKILL.md와 견주어, 다르면 `git log origin/main -- <SKILL.md 경로>`에서 본문이 같은 커밋으로 고친다. 견줄 때 SKILL.md의 frontmatter와 기록 본문 끝의 `ARGUMENTS:` 줄은 뺀다.
- **티켓과 리뷰 요약**: 세션의 PR은 기록에서 `gh pr create`가 돌려준 PR URL이고, 없으면 기록의 세션 URL(`"remote_session_change","url":"<세션 URL>"`)의 `session_…`을 본문에 담은 PR이다(`gh pr list --state all --search '<session_…> in:body'`). PR마다 본문의 `Closes #<티켓>`과 코멘트의 리뷰 요약을 읽는다. PR이 없는 세션(보강, 주제 계획 등)의 받은 티켓은 발행한 티켓의 `## Parent`다.
- **핸드오프**: 세션이 쓴 핸드오프(위 셋째 명령이 잡은 기록의 파일). 기록의 경로가 옛 꼴 `~/documents/ash-wiki-handoff-<이름>`이면 `~/documents/ash-wiki-handoff/<이름>`에서 읽는다. 머리 정보가 가리키는 앞 세션의 핸드오프(예: 받은 티켓을 발행한 세션)도 읽는다. 앞 세션이 남긴 회고 질문에 이번 기록이 답하기 때문이다.

완료: 후보마다 소유자의 답이 있고, 뺀 세션은 목록에 적었다. 대상 세션마다 세션 판이 정해졌고, 티켓과 리뷰 요약, 넘긴 일, 핸드오프는 있는 것을 모두 찾았다.

## 2. 요약본

```sh
python3 -B .claude/skills/wiki-retro/digest.py <세션 기록>...
```

수 MB인 기록과 서브에이전트 기록을 분석할 수 있는 크기로 줄여 보관 폴더의 `<uuid>/`에 쓴다. 이미 요약했고 그 뒤 기록과 `ASH_WIKI_NOTES`의 값이 바뀌지 않은 세션은 다시 만들지 않는다. `ASH_WIKI_NOTES`가 비어 멈추면 소유자에게 설정을 요청하고, 다른 값을 넣어 돌리지 않는다. 다른 값으로는 세션이 실제로 연 노트를 가리지 못한다.

출력의 `지움`은 소스 노트를 연 도구 호출의 수다. 요약본에서는 그 입력과 결과를 지우고, 입력은 `<이름>-notes.txt`에 모은다. `지움`이 0이 아닌 기록이 하나라도 있으면 3단계와 6단계의 노트 줄을 따른다. 지우기는 노출을 줄일 뿐이고 빠지는 것이 있다(노트 디렉터리로 옮긴 뒤 상대 경로로 연 결과 등). 격리 경계는 6단계의 대조로 지킨다.

완료: 기록마다 요약본이 있고, 노트를 연 기록이 있는지 정해졌다.

## 3. 분석

세션마다 분석 에이전트 하나를 Agent 도구(`general-purpose`)로 띄워 병렬로 돌린다. 프롬프트는 [analyst.md](analyst.md)를 채워 쓰고, `<세션 판>`은 1단계의 것, `<요약본 폴더>`는 보관 폴더의 `<uuid>/`, `<작업 폴더>`는 scratchpad 아래 에이전트마다 다른 하위 폴더로 채운다. 노트를 연 기록의 에이전트에는 프롬프트의 노트 줄을 넣는다. 반환은 보관 폴더의 `<uuid>/report.md`에 저장하고, 첫 줄에 세션의 PR, 받은 티켓, 넘긴 일의 번호를 적는다. 뒤 회고가 `grep -l '#<번호>' ~/documents/ash-wiki-retro/*/report.md`로 그 세션의 보고서를 찾게 하기 위해서다.

세션이 넘긴 일의 이슈 번호가 이번 대상인 다른 세션의 PR `Closes #`에 있으면, 그 세션의 반환이 온 뒤에 띄운다. 넘긴 일을 처리한 세션의 `report.md` 경로는 프롬프트에 준다. 지난 회고가 분석한 세션의 것도 보관 폴더에 있다.

완료: 대상 세션마다 `report.md`가 있고, 넘긴 일을 처리한 세션이 대상에 있던 세션은 그 보고서를 받은 뒤에 분석했다.

## 4. 재확인

반환의 측정 가운데 개선안이 기대는 것은 메인 세션이 요약본, 기록, `origin/main`에서 직접 다시 잰다. 건수, "돌지 않았다", "main에 남았다" 같은 주장이다. 분석 에이전트가 기록에서 센 수는 셈법에 따라 달라지고, 핸드오프의 진술도 측정과 다를 수 있다.

다시 재지 못한 것은 `[추론]`으로 내리거나 뺀다. 측정이 핸드오프와 다르면 적어 둔다.

완료: 개선안마다 근거가 다시 잰 측정이거나 `[추론]` 표시가 있다.

## 5. 거르기

발견마다 남길지 정하고 이유를 적는다. 남기는 것은 둘이다.

- 두 세션 이상에서 되풀이된 것
- 한 번이라도 **조용히 실패**한 것: 틀린 것이 main에 들어갔거나, 점검이 돌지 않았는데 끝난 것으로 넘어간 것

남긴 발견의 개선안은 아래 순서로 고른다. 규칙을 더할수록 스킬이 불어나고, 불어난 스킬은 일부만 지켜진다.

1. 이미 있는 규칙 절을 가리키게 한다. 규칙은 있는데 스킬이 다른 절을 가리켜 놓친 경우다.
2. 실행을 명령이나 검사로 옮긴다. 규칙이 있는데 거듭 돌지 않은 경우다.
3. 규칙을 더한다. 규칙의 정본은 하나이고(`CONTRIBUTING.md`의 원칙), 스킬은 그 정본을 가리킨다.

규칙이나 사용자 지침이 이미 정한 것을 한 번 어긴 것과, 분석 에이전트의 추론으로만 선 규칙 확장은 뺀다. 지금 판이 이미 고친 발견(`[지금 판: 고침 <커밋>]`)은 그 커밋을 사유로 뺀다. 그 발견 때문에 main에 들어간 틀린 산출물(페이지 문장, 링크, 티켓 본문 등)이 아직 남아 있으면 **main에 남은 산출물**로 따로 적는다.

완료: 모든 발견에 남김이나 뺌과 이유가 있다. 지금 판이 고친 발견마다 main에 남은 산출물이 있는지 보았다.

## 6. 보이기

대화에 아래를 보이고 소유자의 답을 기다린다.

- **개선안**: 대상 파일과 단계별로, 개선안마다 근거(측정), 제안, 크기(파일, 줄 수)
- **뺀 발견**과 이유
- **main에 남은 산출물**: 5단계에서 따로 적은 것과 그 자리
- 핸드오프의 진술과 다르게 나온 측정
- 앞 세션의 회고 질문 가운데 이번 기록이 답한 것

소유자가 개선안을 고르면 `/mattpocock-skills:to-tickets`로 티켓을 만든다. 노트를 연 기록이 있었으면, 내보낼 글(티켓 본문, 코멘트)을 `-notes.txt`가 가리키는 노트와 대조한다. 방법은 [인제스트](../wiki-ingest/SKILL.md) 격리 자기 점검의 글 대조와 식별 정보 점검이다. 걸린 곳을 고친 뒤 내보낸다.

티켓이 나갔거나 소유자가 멈추라고 하면, 분석한 세션을 `analyzed.tsv`에 적는다. 이 세션의 uuid는 scratchpad 경로에 있다.

```sh
python3 -B .claude/skills/wiki-retro/digest.py --mark <이 세션 uuid> <대상 세션 uuid>...
```

완료: 소유자가 고른 개선안이 티켓으로 나갔거나 소유자가 멈추라고 했고, 대상 세션이 모두 `analyzed.tsv`에 있다.
