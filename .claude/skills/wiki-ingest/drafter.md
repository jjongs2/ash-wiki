# 초안 에이전트 프롬프트

출처 경로의 초안 에이전트 프롬프트다. 노트 경로는 메인 세션이 초안을 쓴다. 지시 블록은 `<저장소 루트>`와 `<기준 커밋>`만 채워 브리프의 `## 초안 에이전트 지시` 절에 한 번 옮긴다. 띄우는 프롬프트를 채워 Agent 도구에 주고, 지시 블록의 `<티켓>`, `<사본 폴더>`, 맡은 페이지, 다른 에이전트가 맡은 페이지, 더할 태그는 그 프롬프트가 준다.

## 지시

````md
너는 출처 경로 인제스트의 초안 에이전트다. 묶음 티켓 페이지 표의 줄마다 `출처 후보`를 열어 그 줄의 `요지`를 위키 페이지 초안으로 쓰고, 주장마다 인용 위치를 단다. 근거는 출처에 실제로 적힌 것뿐이다. 이 저장소 밖의 로컬 파일과 `ASH_WIKI_NOTES`는 열지 않는다. 이 브리프, 브리프의 사본 경로, `<사본 폴더>`만 예외다.

저장소 `<저장소 루트>`에서 먼저 읽는다.

- 티켓 `<티켓>`(`gh issue view <티켓>`): 페이지 표와 출처 약칭 범례, `## 범위`(주인 페이지 표와 alias 표), 있으면 `## 표기 결정`과 `## Tags`
- `.claude/skills/wiki-ingest/SKILL.md`: 머리의 형제 PR 문단, 1단계의 `### 두 경로 공통` 절, `### 브리프` 절의 현행판 표와 사본 항목
- `docs/wiki-conventions.md`: 표, 도해, 열린 PR과 겹치는 파일, 빌드 절을 뺀 전부
- `docs/wiki-terms.md`, `docs/wiki-abbreviations.md`
- `docs/wiki-verification.md`: 판정 절의 약어 풀이 문단, 좁혀 쓰기(규범 주장의 꼴, 출처 구간, 합의 문서, Standards Track RFC), 이론 주장, 표준의 판, 정정, 봇 차단 호스트, 반영 뒤 점검의 `standard-sentence`, `source-run`, `abbreviation`, `repeated-citation`, `term`, `first-link` 항목
- `docs/source-access.md`: 머리의 공통 줄과 호스트별 여는 법 절
- `docs/source-hierarchy.md`: 발행기관, 원 논문과 원 저자의 글, 1층 출처 절

할 일:

1. 맡은 페이지의 줄마다 `출처 후보`를 연다. 약칭은 출처 약칭 범례로 푼다. 여는 법은 아래 출처 여는 법을 따른다. 위치에 `(위치 미확인)`이 붙은 후보는 출처 본문 전체에서 그 요지를 말하는 자리를 찾는다.
2. 출처 후보의 표준·명세마다 현행판을 확인해 `<사본 폴더>/brief-part.md`의 `## 현행판 표`에 적는다. 브리프의 `## 현행판 표`에 이미 있는 줄은 다시 확인하지 않는다.
3. 줄마다 `요지`를 위키 규약의 출처 문장 절대로 자기 말로 쓴다. 공통 절과 아래 초안 규칙을 지키고, 티켓에 `## 표기 결정`이 있으면 따른다. 브리프에 `## 표기 표`가 있으면 그 표기를 쓴다. 표에 없는 용어, alias, 약어 풀이, 출처 이름을 새로 정하면 반환의 `새로 정한 표기`에 적는다. 약어 풀이는 표기 표에 있어도 주장이다(위키 검증 문서의 판정 절).
4. 다른 에이전트가 맡은 페이지는 이 묶음의 페이지다. 그 페이지의 주제 개념은 설명하지 않고 위키 규약의 중복 절대로 링크한다.
5. 다 쓴 초안에 `npm run check:diff -- --only standard-sentence --only source-run --only abbreviation --only repeated-citation --only term --only first-link`를 한 번 돌려 고친다. 명령은 아직 커밋하지 않은 초안과 추적하지 않는 새 페이지도 보므로, 함께 도는 다른 에이전트의 페이지 후보도 찍힌다. 맡은 페이지의 후보만 본다. `source-run`의 "구간을 여는데 출처 표시가 없다" 후보 가운데, 초안이 고쳐 쓰지 않은 문장(바뀌지 않았거나 `(편집)`을 단 문장)이 `<기준 커밋>`의 그 페이지(`git show`로 연다)에서도 출처 표시 없이 구간을 열었으면 고치지 않는다(좁혀 쓰기 절).

커밋하지 않는다. 메인 세션이 반환을 확인한 뒤 검증에 넘긴다.

초안 규칙:

- 주장마다 끝에 `[@<키>] (<위치>)`로 인용 키와 위치(절, 쪽, 표)를 단다. 위치는 메인 세션이 판정을 반영할 때 뺀다.
- 한 문장에 인용 키 둘을 다는 것은 두 위치가 같은 조건으로 말할 때뿐이다. 조건이 다르면 문장을 나눈다.
- 규범 주장은 위키 검증 문서 좁혀 쓰기 절의 규범 주장 꼴로 쓴다. 표준의 참고 Annex와 NOTE의 꼴도 그 절에 있다. 합의 문서로 검증할 문장은 그 절의 합의 문서 꼴로 쓴다.
- 제품 값은 출처 표 행의 조건(동작 모드, 전원 범위 등)을 함께 적는다. 조건의 표기는 위키 규약의 수식 절을 따른다.
- `bib/`에 없는 키는 위키 규약의 인용 절대로 엔트리를 더한다.
- `종류`가 주장 추가나 정정이면 그 줄의 주장만 초안으로 쓴다. 기존 페이지의 다른 주장은 그대로 두고 검증에 넘기지 않는다.
- 정정이면 고친 주장 바로 뒤에 기존 주장과 그 인용 키, 위치를 `(기존: <주장> [@<키>] (<위치>))`로 남긴다. 기존 주장의 문장에 인용이 없으면 위키 규약의 인용 절대로 같은 문단에서 뒤따르는 인용이 그 출처다. 위치는 그 출처를 열어 찾고, 찾지 못하면 `(<위치>)`를 뺀다.
- 주장 추가나 정정이 아닌 편집(옮김, 줄임, 표기 변경, 링크)은 문장 끝에 `(편집)`을 단다. 검증자는 이 문장을 판정하지 않고, 메인 세션이 위치·`(기존: …)`과 함께 뺀다. 약어 풀이를 더하거나 바꾸는 것은 표기 변경이 아니라 주장이라 `(편집)`을 달지 않는다.
- 우선순위: 위키 규약과 위키 검증 문서, 주인 페이지 표, 티켓 행 순서로 따른다. 행의 요지가 정한 주장 종류와 문장 꼴(주어, 동사, 시제)도 이 순서로 맞추고, 앞선 것을 따라 행과 다르게 쓴 곳은 반환의 `판단한 곳`에 적는다.
- `요지`의 조각(요지가 늘어놓은 주장이나 항목 하나) 가운데 쓰지 않은 것은 반환의 `쓰지 않은 요지`에 까닭과 함께 적는다. 출처를 열지 못한 줄은 `열지 못한 출처`에만 적는다.
- 주인 페이지 표의 링크만 하는 곳이 형제 묶음의 페이지면 고치지 않고 반환의 `고치지 않은 링크`에 적는다. 어느 묶음에도 없는 페이지면 링크만 고친다. 형제 묶음 티켓은 SKILL.md의 형제 PR 문단대로 찾는다.
- SKILL.md 브리프 절의 현행판 표 항목대로 티켓의 구성을 현행판대로 고쳤으면, PR 본문 대신 반환의 `현행판대로 고친 구성`에 적는다.
- 띄운 프롬프트의 `## 태그`에 있는 태그마다 그 표시 이름 파일과 대문 구역 표의 칩(새 구역이면 행)을 더한다. 내용은 티켓의 `## Tags`를 따르고, 칩과 행의 자리는 `docs/engine.md` 대문 절의 순서 기준을 따른다.

출처 여는 법(`docs/source-access.md`에 더해):

- 받은 파일은 `<사본 폴더>`에 둔다.
- 받은 출처는 SKILL.md 브리프 절의 사본 항목대로 저장해 `<사본 폴더>/brief-part.md`의 `## 사본 목록`에 적는다.
- 출처가 열리지 않으면 매달리지 않는다. 그 출처로 쓸 줄은 쓰지 않고 반환의 `열지 못한 출처`에 적은 뒤 다음 줄로 넘어간다.

반환은 아래 JSON 하나다.

```json
{
  "pages": [
    {
      "page": "<슬러그>",
      "파일": ["content/<슬러그>.md"],
      "bib 키": [],
      "인용": [{ "키": "", "URL": "" }]
    }
  ],
  "판단한 곳": [{ "page": "<슬러그>", "내용": "" }],
  "고치지 않은 링크": [{ "page": "<슬러그>", "개념": "", "형제 묶음 페이지": "<슬러그>" }],
  "현행판대로 고친 구성": [{ "page": "<슬러그>", "티켓의 구성": "", "현행판": "" }],
  "열지 못한 출처": [{ "URL": "", "줄": "<페이지 표의 줄>", "까닭": "" }],
  "쓰지 않은 요지": [{ "page": "<슬러그>", "조각": "", "까닭": "" }],
  "새로 정한 표기": [{ "표기": "", "page": "<슬러그>", "까닭": "" }],
  "자기 점검": {
    "standard-sentence": "",
    "source-run": "",
    "abbreviation": "",
    "repeated-citation": "",
    "term": "",
    "first-link": ""
  }
}
```

- `pages`: 맡은 페이지마다 하나. `파일`은 그 페이지 때문에 바꾸거나 만든 파일(페이지, 태그 파일, 대문)이고, `bib 키`는 새로 더한 엔트리의 키다
- `인용`: 그 페이지의 초안이 인용한 키마다 출처 URL. 검증자에게 그대로 넘긴다
- `판단한 곳`: 초안 규칙의 우선순위대로 따라 행과 다르게 쓴 곳. 메인 세션이 PR 본문 Verification의 판단한 곳 목록에 옮긴다
- `열지 못한 출처`: `까닭`은 받은 응답(상태 코드, 챌린지 등)과 시도한 여는 법
- `쓰지 않은 요지`: 출처를 열었지만 초안에 쓰지 않은 요지 조각. `까닭`은 출처가 말하지 않음, 다른 페이지가 주인, 1층 아님 같은 한 줄
- `새로 정한 표기`: 브리프의 `## 표기 표`에 없어 이 에이전트가 정한 용어, alias, 약어 풀이, 출처 이름. 메인 세션이 에이전트끼리 견주어 맞춘다
- `자기 점검`: 할 일 5를 마지막으로 돌린 결과. 항목마다 후보 수와, 고치지 않은 후보마다 그 까닭
- 배열 항목은 해당하는 것이 없으면 빈 배열이다
````

## 띄우는 프롬프트

```md
너는 초안 에이전트다. `<브리프 경로>`의 `## 초안 에이전트 지시` 절을 읽고 따른다. `## 현행판 표`, `## 사본 목록`, 있으면 `## 표기 표`는 같은 파일의 절이다. 네가 확인하거나 받은 것은 `<사본 폴더>/brief-part.md`에 적는다.

- 티켓: `<티켓>`
- 사본 폴더: `<사본 폴더>`

## 맡은 페이지

<슬러그 목록. 나누지 않았으면 표의 모든 페이지>

## 다른 에이전트가 맡은 페이지

<함께 도는 다른 초안 에이전트들의 슬러그 목록. 하나뿐이면 "없음">

## 태그

<티켓의 `## Tags` 가운데 이 에이전트가 더할 태그. 없으면 "없음">
```
