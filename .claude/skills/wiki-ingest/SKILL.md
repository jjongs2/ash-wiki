# 인제스트

인제스트 티켓 하나가 PR 하나가 된다. 용어는 `GLOSSARY.md`를 따른다.

먼저 티켓을 읽는다(`docs/agents/issue-tracker.md`의 이슈 읽기). 규칙 문서는 한꺼번에 읽지 않는다. 단계와 절마다 "읽는다:"가 적은 문서와 절을 그 자리에서 읽는다. 브랜치와 커밋은 `CONTRIBUTING.md`의 브랜치, PR 제목 절을 따르고, 타입은 `content`다.

티켓에 `## 출처` 절이 있으면 **출처 경로**, 없으면 **노트 경로**다. 출처 경로 티켓은 보강이 발행한 것으로, `ASH_WIKI_NOTES`를 열지 않고 그 절의 출처로 쓴다. 두 경로가 다른 단계는 따로 적는다.

출처를 열기 전에 출처 여는 법 문서의 접속 확인을 한다. 읽는다: `docs/source-access.md`의 접속 확인 절과 호스트별 여는 법 표, 위키 검증 문서의 봇 차단 호스트 표. 대상은 출처 후보의 호스트와 Wayback이다. 출처 경로는 1단계를 시작할 때, 노트 경로는 1단계에서 출처 후보를 적은 뒤 2단계 전에 한다. 접속 확인에서 멈추면 소유자의 답을 기다린다.

**`verify:` 이슈**는 인제스트 티켓이 막는 이슈 가운데 제목이 `verify:`로 시작하는 것이다: `gh api repos/<owner>/<repo>/issues/<인제스트 티켓>/dependencies/blocking --jq '[.[] | select(.title | startswith("verify:")) | .number]'`. 인제스트 티켓이 다른 이슈도 막을 수 있어 제목으로 거르고, 티켓 본문은 번호를 적지 않는다.

**형제 PR**은 같은 `verify:` 이슈를 막는 다른 인제스트 티켓의 열린 PR이다. 인제스트 티켓은 `gh api repos/<owner>/<repo>/issues/<verify 이슈>/dependencies/blocked_by --jq '.[].number'`로 찾고, 티켓마다 열린 PR은 `gh pr list --state open --json number,closingIssuesReferences --jq '.[] | select(any(.closingIssuesReferences[]; .number == <티켓>)) | .number'`로 찾는다. **머지된 형제 PR**은 같은 명령을 `--state merged`로 돌려 찾은 PR 가운데, `git fetch origin` 뒤 `git log --format=%s <기준 커밋>..origin/main`(`<기준 커밋>`은 [브리프](#브리프)의 것)의 제목 끝 `(#<PR>)`에 있는 것이다. 이 세션이 시작한 뒤 머지된 형제 묶음이다.

**준비**: worktree에서 일하면 시작할 때 `npm ci`를 한다. 작업 파일은 모두 작업 트리 루트(worktree면 그 루트)의 `.work/`(`.gitignore`에 있다)에 둔다. 브리프, 사본, 반영 뒤 점검의 로그와 메모, 에이전트별 `<작업 폴더>`와 `<사본 폴더>`다. 재시작에 지워지지 않고, 에이전트가 브라우저로 받은 본문도 저장할 수 있는 자리다. 에이전트에게 주는 폴더는 띄우기 전에 메인 세션이 `mkdir -p`로 만든다. `npm run check`는 출력을 파일로 받아(`npm run check > .work/check.log 2>&1; echo "exit $?"; tail -n 20 .work/check.log`) 종료 코드와 마지막 요약 줄로 결과를 본다. 출력이 길어 화면에서 요약 줄이 잘리기 때문이다.

## 1. 초안

노트 경로는 메인 세션이 초안을 쓰고, 출처 경로는 초안 에이전트가 쓴다.

### 두 경로 공통

읽는다: 위키 규약의 용어, 중복 절, `docs/wiki-terms.md`. 출처 경로에서는 메인 세션 대신 초안 에이전트가 읽는다.

두 경로 모두 쓰기 전에 티켓의 `## 범위` 절과 주인 페이지 표를 읽고, 쓰는 동안 다음을 지킨다.

- 주인 페이지 표에서 이 묶음의 페이지가 링크만 하는 곳인 개념은 위키 규약의 중복 절을 따라 쓴다.
- 표에 없는 개념도 `content/`를 grep해 주인 페이지가 이미 있으면 같은 절을 따라 그 페이지로 링크한다.
- 용어는 `docs/wiki-terms.md`에 결정이 있으면 따른다. 결정이 없는 용어는 위키 규약 용어 절의 순서로 고른다. `content/`를 grep한 기존 표기는 그 순서에 맞을 때만 따르고, 어긋나면 표기 선택이 갈렸으니 위키 규약 용어 절을 따라 `term:` 이슈로 올린다. 기호는 쓰기 전에 `content/`를 grep해 기존 표기를 따른다. grep은 main만 보므로, 병렬로 도는 형제 묶음과 맞출 표기는 범위 절의 alias 표를 따른다.
- 위키링크는 이미 있는 페이지와 이 묶음의 페이지로만 건다. 형제 묶음의 페이지로 가는 링크는 걸지 않는다. 위키 규약 약어 절의 계획만 된 페이지 규칙대로 재조사가 건다. 나머지 자리는 린트가 채운다.
- 도해와 표는 아직 넣지 않는다. 표는 4단계, 도해는 5단계의 일이다.

### 노트 경로

읽는다: `docs/adr/0001-isolation-boundary.md`, 위키 규약의 페이지 타입과 프론트매터, 절, 슬러그, 출처 문장, 인용, 약어 절, `docs/wiki-abbreviations.md`, 출처 위계 문서의 1층 출처 절.

티켓의 페이지 표에 있는 페이지마다 `ASH_WIKI_NOTES`의 노트를 읽고, 자기 말로 초안을 쓴다. 표기는 위키 규약을 따른다. 인용은 아직 달지 않는다.

- 페이지마다 출처 후보를 적어 둔다. 노트가 가리키는 공개 자료 가운데 1층일 만한 것이다.

### 출처 경로

읽는다: [drafter.md](drafter.md).

메인 세션은 출처를 열지 않는다. 접속 확인을 마치면 브리프를 만들어 지시 절을 쓰고, 초안 에이전트를 Agent 도구(`general-purpose`)로 띄운다. 출처 원문과 그것을 따지는 추론을 메인 세션의 컨텍스트 밖에 두기 위해서다. 프롬프트는 [drafter.md](drafter.md)의 띄우는 프롬프트를 채워 쓰고, `<사본 폴더>`는 `.work/` 아래 에이전트마다 다른 하위 폴더로 채운다.

- 제안 항목(새 페이지 하나, 기존 페이지의 `<종류>. 자리:` 줄 하나)이 15개 이하면 초안 에이전트는 하나다. 15개를 넘으면 페이지 단위로 나누고, 제안 항목이 적은 페이지끼리는 15개를 넘지 않게 에이전트 하나에 묶는다. 둘 이상이면 한 메시지에 모두 띄워 병렬로 돌린다.
- 에이전트가 둘 이상이면 띄우기 전에 브리프의 `## 표기 표`에 묶음이 함께 쓸 표기를 적는다: 용어, alias, 약어 풀이, 출처 이름. 티켓의 alias 표와 `## 표기 결정`, `docs/wiki-terms.md`에서 옮긴다. 결정은 줄 끝의 조건이나 예외까지 옮겨, 조건 붙은 결정을 조건 없이 적지 않는다(예: failure를 어디서나 "장애"로). 두 페이지 이상이 쓸 것 가운데 결정이 없는 것은 위 공통 절의 용어 규칙대로 정해 적는다. 에이전트끼리 표기가 갈리지 않게 하기 위해서다. 결정 없이 적은 약어 풀이는 판정의 근거가 아니다(위키 검증 문서의 판정 절).
- 묶음 밖 파일(맡은 페이지가 아닌 파일)은 파일마다 에이전트 하나에만 준다. 새 태그 파일, 대문, README의 다루는 주제 표는 초안 에이전트 하나에 모아 `## 태그`로 준다. 주인 페이지 표의 링크만 하는 곳 가운데 묶음 밖 페이지는 그 개념의 주인 페이지를 맡은 에이전트(여러 개념이면 그 가운데 한 주인 페이지의 에이전트)에게 `## 링크만 고칠 페이지`로 준다. 주인 페이지도 묶음 밖이면 아무 에이전트 하나에 준다. 나누지 않으면 같은 파일을 둘이 고치거나 아무도 고치지 않는다.

반환을 3단계처럼 확인한다. 초안 diff를 처음부터 끝까지 읽지 않고, 명령으로 볼 수 있는 것은 명령으로 본다. 기존 페이지에 끼운 문장만 아래 [이음매 읽기](#이음매-읽기)대로 읽는다. `<기준 커밋>`은 아래 브리프의 것이다.

- `## Pages` 표의 슬러그마다 초안이 있다. 반환의 `pages`가 맡긴 페이지를 모두 담고, `git status --short content/`에 그 파일이 있다. 초안이 없는 슬러그는 `열지 못한 출처`에 있다.
- 주장마다 인용 키와 위치가 있다. 인용 없는 블록은 `npm run check:diff -- --only uncited-block`, 위치 없는 인용은 `git diff -U0 <기준 커밋> -- content/ | grep -P '^\+(?!\+\+).*\[@[^\]]+\](?! \()'`과 새 페이지에 `git ls-files -o --exclude-standard content/ | xargs -r grep -HnP '\[@[^\]]+\](?! \()'`로 후보를 찾아 그 줄만 읽는다. `(기존: …)` 안에서 위치가 빠진 것은 찾지 못한 위치일 수 있다.
- 에이전트마다 `<사본 폴더>/brief-part.md`에 `## 현행판 표`와 `## 사본 목록`이 있고, 반환의 `인용` URL마다 사본 목록에 짝이 있다.
- 요지의 조각마다 초안에 있거나 반환의 `쓰지 않은 요지`나 `열지 못한 출처`에 있다. 조각은 [보강의 발행 단계](../wiki-enrich/SKILL.md#6-발행)가 정한다.
- 반환 JSON의 키가 모두 있다.

빠진 것은 SendMessage로 그 초안 에이전트에게 돌려보내 채우게 한다.

에이전트마다 `brief-part.md`의 두 절을 [merge_brief.py](merge_brief.py)로 브리프의 같은 절에 합친다: `python3 -B .claude/skills/wiki-ingest/merge_brief.py <브리프> <사본 폴더>/brief-part.md…`. 스크립트가 출력한 이름이 같은 표준은 메인 세션이 브리프에서 줄 하나로 정하고, 현행판이 갈리면 그 에이전트들에게 확인한 주소를 견주게 해 정한다. 에이전트가 둘 이상이면 반환의 `새로 정한 표기`를 견주어, 같은 것을 다르게 적은 곳은 공통 절의 용어 규칙대로 하나로 맞춘다. 맞추며 주장의 내용은 바꾸지 않는다.

`판단한 곳`, `고치지 않은 링크`, `현행판대로 고친 구성`, `쓰지 않은 요지`는 PR 본문 초안에 옮긴다. `열지 못한 출처`의 호스트가 접속 확인에서 멈추는 경우에 해당하면 접속 확인처럼 소유자에게 묻고, 아니면 PR 본문 Verification에 적는다.

### 이음매 읽기

기존 페이지에 넣은 문장은 메인 세션이 그 자리에서 앞뒤 문단과 함께 읽고 연결, 자리, 되풀이를 고친다. 에이전트는 띄우지 않는다. 검증자는 원문과 맞는지를, 표기 검토는 규칙을 지키는지를 볼 뿐 넣은 자리에서 읽히는지는 보지 않기 때문이다. 새 부분이 쓸모 있고 제자리에 있는지는 8단계의 독자 검토가, 게시된 페이지를 처음부터 읽는 경험은 Reader Testing이 본다.

- 읽는 때는 2단계 검증 전이다. 출처 경로에서는 초안 에이전트가 기존 페이지에 끼운 문장과 그 앞뒤 문단만 읽고, 새 페이지와 초안 diff 전체는 읽지 않는다.
- 검증 뒤에 들어가는 문장(3단계의 `고쳐 쓸 문장`, 4단계에서 빈 자리를 잇는 문장)은 넣은 뒤에 읽는다. 읽고 고친 것이 문장의 뜻(위키 검증 문서의 반영 뒤 재판정 절)을 바꾸면 3단계의 재판정을 거친다.
- 자리를 옮길 때 출처 표시와 출처 구간은 위키 검증 문서의 좁혀 쓰기 절을 따른다.

### 브리프

읽는다: 검증자 agent(노트 경로는 [`note-verifier`](../../agents/note-verifier.md), 출처 경로는 [`source-verifier`](../../agents/source-verifier.md))와 [diagrammer.md](diagrammer.md)의 지시 블록. 노트 경로는 위키 검증 문서의 표준의 판 절과 봇 차단 호스트 표도.

출처 후보가 정해지면(출처 경로는 1단계를 시작할 때, 노트 경로는 출처 후보를 적은 뒤) **브리프**를 준비한다. 검증자, 도해 에이전트, 출처 경로의 초안 에이전트가 함께 읽는 파일 하나로, `.work/`에 둔다. 저마다 따로 하면 판단이 갈리거나 서로 덮고, 같은 출처를 거듭 받기 때문이다. 절마다 쓰는 쪽이 정해져 있다. 담을 것:

- **지시**(메인 세션): `## 도해 에이전트 지시` 절에 [diagrammer.md](diagrammer.md)의 지시 블록을 옮긴다. 출처 경로는 `## 초안 에이전트 지시` 절에 [drafter.md](drafter.md)의 지시 블록도 옮긴다. 채울 자리는 프롬프트 파일이 정한다. 검증자의 지시는 agent 파일에 있어 옮기지 않는다. `<기준 커밋>`은 1단계를 시작할 때의 `git merge-base origin/main HEAD`다.
- **현행판 표**(`## 현행판 표`, 노트 경로는 메인 세션, 출처 경로는 초안 에이전트가 쓰고 메인 세션이 합친다): 출처 후보의 표준·명세마다 발행기관의 판 목록에서 현행판을 확인해, 이름과 현행판, 확인한 주소를 표로 적는다. 현행판의 뜻과 판 목록을 내지 않는 발행기관의 확인은 위키 검증 문서의 표준의 판 절에 있다. 티켓 범위가 적은 구성(모듈 등)이 현행판에 없으면 초안을 현행판대로 고치고, PR 본문에 적는다.
- **사본**(`## 사본 목록`, 노트 경로는 메인 세션, 출처 경로는 초안 에이전트가 쓰고 메인 세션이 합친다): 출처를 받은 쪽이 받은 출처마다 본문을 텍스트로 `.work/` 아래에 저장한다. 텍스트 층 없는 미리보기(openstd 등)는 쪽 스크린숏을 사본으로 두고, 검증자가 그 이미지를 읽어 판정한다. 봇 차단 호스트(위키 검증 문서의 봇 차단 호스트 표)의 출처 후보는 초안에 쓰지 않았어도 출처 여는 법 문서의 호스트별 여는 법대로 한 번 열어 저장한다. 출처마다 원래 URL과 사본 경로를 짝지어 목록으로 적는다.
- **표기 표**(`## 표기 표`, 메인 세션): 출처 경로에서 초안 에이전트가 둘 이상일 때만 둔다. 담을 것은 출처 경로 절에 있다.
- **bib 키**(`## bib 키`, 메인 세션): 노트 경로에서만 둔다. `bib/`의 기존 키 목록과, 형제 PR이 더한 bib 키와 그 url이다. 형제 PR이 더한 bib는 PR마다 `gh pr view <PR> --json files --jq '.files[].path | select(startswith("bib/"))'`로 찾고, `git fetch origin pull/<PR>/head`와 `git show FETCH_HEAD:<파일>`로 url을 본다.

완료: 표의 모든 페이지에 초안과 출처 후보가 있다. 출처 경로에서는 초안 에이전트마다 반환이 위 확인을 통과해, 초안의 주장마다 인용 키와 위치가 있고 뜻을 바꾸지 않는 편집마다 `(편집)`이 있다. 브리프에 지시, 현행판 표, 사본 목록이 있고, 출처 경로에서는 에이전트마다의 `brief-part.md`와 `새로 정한 표기`를 합쳤다. 에이전트가 둘 이상이면 띄우기 전에 브리프에 `## 표기 표`가 있었다. 기존 페이지에 넣은 문장의 이음매 읽기를 마쳤다.

## 2. 검증

읽는다: 검증자 agent 파일의 띄우는 프롬프트 절.

페이지마다 검증자를 하나씩 Agent 도구(노트 경로는 `note-verifier`, 출처 경로는 `source-verifier`)로 띄운다. 한 메시지에 모두 띄워 병렬로 돌린다. 프롬프트는 agent 파일의 띄우는 프롬프트를 채워 쓴다. `<브리프 경로>`는 1단계의 브리프이고, `<작업 폴더>`는 `.work/` 아래 검증자마다 다른 하위 폴더로 채운다.

검증자에게는 브리프 경로와 자기 몫만 준다. 노트 경로의 몫은 초안과 출처 후보이고, 출처 경로의 몫은 슬러그와 초안이 인용한 키마다 URL(초안 에이전트 반환의 `인용`)이다. 노트 경로와 노트의 표현은 주지 않는다. 검증자가 출처에 적힌 것만 인정하게 하기 위해서다.

완료: 페이지마다 검증자의 반환이 있다.

## 3. 반환 확인

읽는다: 출처 위계 문서의 1층 출처 절, 위키 검증 문서의 좁혀 쓰기 절. 노트 경로는 위키 규약의 인용 절도.

검증자마다 반환 JSON이 프롬프트의 계약을 지키는지 확인한다.

- 주장마다 `주장`, `종류`, `판정`, `사유`, `인용 키`가 판정에 맞게 채워져 있다.
- 출처 경로에서 `고쳐 쓸 문장`이 있으면 페이지의 `원래 문장`을 `고친 문장`으로 재판정 없이 바꾸고, 1단계의 이음매 읽기를 한다. 바꾼 문장의 용어와 약어 풀이는 `docs/wiki-terms.md`와 `content/`에 다시 grep해 1단계 공통 절의 용어 규칙에 맞춘다. 맞추며 약어 풀이나 조직 약어의 소개를 더하거나 바꾸면 위키 검증 문서의 판정 절을 따라 재판정을 거친다.
- `종류`가 `규범`인 검증 완료 주장은 인용 키의 출처가 출처 위계 문서의 규범 주장 1층이고, 위키 검증 문서의 좁혀 쓰기 절이 정한 규범 주장의 꼴이다. 같은 절의 참고 Annex와 NOTE의 꼴도 여기에 든다. 인용 키가 합의 문서면 같은 절의 합의 문서 꼴이다. 꼴은 노트 경로에서는 `주장`으로, 출처 경로에서는 `고쳐 쓸 문장`까지 반영한 페이지 문장으로 보고, 그 문장이 출처 구간을 잇는 문장이면 구간을 여는 문장의 꼴도 함께 본다. 같은 절의 Standards Track RFC 꼴도 여기에 든다. 어긋나면 그 검증자에게 돌려보내 다시 판정하게 한다. 구간을 여는 문장이 검증자가 판정하지 않은 문장(바뀌지 않았거나 뜻이 그대로인 `(편집)` 문장)이고 `<기준 커밋>`에서도 출처 표시 없이 구간을 열었으면(`git show <기준 커밋>:content/<슬러그>.md`) 돌려보내지 않는다(좁혀 쓰기 절).
- 새 엔트리의 url이 형제 PR의 엔트리에 이미 있으면 그 키로 바꾼다. 검증자끼리 새 엔트리의 url이 같으면 키 하나로 합친다.
- 초안의 문장마다 판정된 주장이 하나 이상 있다. 판정하지 않은 `(편집)` 문장은 빼고 센다.

빠진 것은 SendMessage로 그 검증자에게 돌려보내 채우게 한다.

**재판정**: 이 단계 뒤에 메인 세션이 다른 이유(도해, 중복 정리, 리뷰 반영)로 주장의 내용을 바꾸면, 바꾼 문장을 SendMessage로 그 페이지의 검증자에게 보내 다시 판정받는다.

완료: 모든 페이지의 모든 주장이 계약을 지키고, 같은 url에 키가 하나다.

## 4. 판정 반영

읽는다: 위키 검증 문서의 판정, 정정, 게시 기준, 표준의 판, `verify:` 이슈, 반영 뒤 점검 절. 위키 규약의 페이지 타입과 프론트매터, 인용, 중복 절. `docs/adr/0001-isolation-boundary.md`. 출처 경로는 빈 자리를 잇는 문장을 쓰려고 위키 규약의 출처 문장, 용어, 약어 절과 `docs/wiki-terms.md`, `docs/wiki-abbreviations.md`도.

위키 검증 문서의 판정 표대로 페이지를 고친다. 새 엔트리는 위키 규약의 인용 절을 따라 더하고, 미검증 주장은 `verify:` 코멘트 목록에 옮긴다.

미검증 주장을 코멘트 목록에 옮기기 전에 둘을 grep한다. 같은 출판물의 다른 자리나 위키의 기존 문장으로 풀리는 항목이 재조사까지 넘어가지 않게 하기 위해서다.

- 그 주장을 대조한 출처(검증자 반환 `사유`의 URL)의 사본 전체를 주장의 핵심어로 grep한다. 스크린숏 사본은 grep 대신 쪽 이미지를 읽는다. 다른 위치에서 찾으면 그 위치를 SendMessage로 그 페이지의 검증자에게 보내 재판정받은 뒤 반영한다.
- `content/`를 같은 핵심어와 alias로 grep한다. 같은 주장이 이미 있으면 위키 규약의 중복 절을 따라 그 주인 페이지로 링크한다.

코멘트에는 두 grep으로 풀리지 않은 부분만 올린다.

출처 경로에서는 초안의 인용 위치, `(기존: …)`, `(편집)`을 뺀다. 정정 줄은 위키 검증 문서의 정정 절을 따라 반영하고, 가리지 못한 것은 `(게시됨)`을 붙여 코멘트 목록에 옮긴다.

출처를 다시 볼 때는 브리프 사본 목록의 사본에서 필요한 구간만 연다(`grep -n`으로 찾아 `sed -n`으로, 스크린숏 사본은 그 쪽 이미지만). 사본 전체를 읽거나 다시 받지 않는다.

빈 자리를 이을 때는 이미 검증된 주장만 쓰고, 기존 페이지에 이은 문장은 넣은 뒤 1단계의 이음매 읽기를 한다. 표도 이때 ADR 0001대로 새로 구성해 넣는다. 어디를 표로 쓸지는 위키 규약의 표 절, 표에 인용을 다는 자리는 인용 절을 따른다. 새 페이지의 `verified`는 오늘 날짜로 두고, 기존 페이지의 `verified`는 위키 규약대로 둔다. 위키 검증 문서의 게시 기준에 못 미치는 페이지는 그 절을 따라 처리하고, PR 본문에 그 페이지를 적는다.

표준 페이지를 만들거나, 반영이 위키 검증 문서의 표준의 판 절이 정한 판을 바꾸는 PR에 들면, 그 절의 대조를 한다. 이 묶음 밖의 페이지도 대상이다.

반영을 마치면 셋을 한다.

- **범위 대조**: 대조 단위는 주인 페이지 표의 줄과, 노트 경로는 `## 범위`의 페이지별 줄, 출처 경로는 슬러그 절의 요지 조각이다. 단위마다 결과를 검증 완료로 게시, 미검증, 제외, 쓰지 않음, 이름만 가운데 하나로 적는다. 쓰지 않음은 초안 에이전트 반환의 `쓰지 않은 요지`와 `열지 못한 출처`다. "이름만"인 개념(주인이 아직 계획 없는 주제인 줄 등)은 이름 이상 쓰지 않는다. 게시하지 않은 단위(미검증, 제외, 쓰지 않음)는 그 까닭과 함께 PR 본문 Verification에 적는다.
- **반영 뒤 점검**: `npm run check:diff -- --ticket <인제스트 티켓> > .work/check-diff.log`를 돌려 위키 검증 문서의 반영 뒤 점검 절을 따라, 받는 쪽이 메인 세션인 항목의 후보를 모두 본다. 받는 쪽이 검토인 항목은 8단계에서 그 검토자에게 준다. **주인 페이지 판정**은 `owner-page`와 `first-link` 후보를 줄마다 그 문단까지 읽어 위키 규약의 중복 절과 위키링크 절을 따라 판정하고, 링크가 없다고 나온 페이지는 개념의 이름과 alias로 grep해 설명이 남았는지 본다. 메인 세션이 받는 후보마다 위키 검증 문서 검토 절의 처리 줄을 `.work/처리.md`에 남긴다. `source-run`의 "구간을 여는데 출처 표시가 없다" 후보가 `<기준 커밋>`에서도 출처 표시 없이 구간을 열던 문단이면 오탐이고, 좁혀 쓰기 절의 그 줄을 근거로 적는다. `owner-page`에서 고치지 않은 후보의 처리 줄은 주인 페이지에서 그 개념을 싣는 문장을 인용하고, 검사가 보인 문단이 2문장 이상이면 그 문장들도 인용한다. 주인 페이지에 그 문장이 없으면 위키 규약의 중복 절을 따라 설명을 주인 페이지로 옮긴다. PR 본문 Verification에는 위키 검증 문서 검토 절의 Verification의 수를 적는다.

완료: 초안의 모든 주장이 인용을 달고 게시되거나, 제외로 빠지거나, 코멘트 목록에 있다. 코멘트 목록의 주장마다 사본 대조와 `content/`의 grep을 마쳤다. 범위 대조, 주인 페이지 판정을 포함한 반영 뒤 점검을 마쳤다. 표준 페이지를 만들었거나 판을 바꾸는 PR에 들면 그 대조를 마쳤다.

## 5. 도해

읽는다: [diagrammer.md](diagrammer.md)의 띄우는 프롬프트 절. 도해 규칙은 도해 에이전트가 읽는다.

도해 에이전트 하나를 Agent 도구(`general-purpose`)로 띄운다. 프롬프트는 [diagrammer.md](diagrammer.md)의 띄우는 프롬프트를 채워 쓰고, `<작업 폴더>`는 `.work/` 아래 도해 에이전트의 하위 폴더로 채운다.

도해 에이전트에게는 브리프 경로, 묶음의 슬러그 목록, 페이지가 인용한 키마다 출처 URL만 준다. 4단계를 마친 페이지는 검증 완료 주장과 인용 키만 담는다. 노트 경로, 노트의 표현, 노트에 어떤 도해가 있는지는 주지 않는다. 노트를 읽은 컨텍스트는 노트의 도해 구성을 닮게 그리기 쉬워서, 도해는 노트를 모르는 쪽이 그린다.

반환의 `diagrams`마다 파일이 있고 `pages`의 페이지에 들어갔는지, `skipped`와 합쳐 묶음의 모든 페이지가 나오는지 확인한다. `revised`의 도해는 PR 본문에 적는다. `text_changes`는 메인 세션이 고치고, 주장의 뜻(위키 검증 문서의 반영 뒤 재판정 절)이 바뀌면 3단계의 재판정을 거친다. 빠진 것은 SendMessage로 도해 에이전트에게 돌려보낸다.

완료: 묶음의 모든 페이지가 `diagrams`나 `skipped`에 있고, `text_changes`마다 고쳤거나(주장의 뜻이 바뀌었으면 재판정을 거쳐) 고치지 않은 까닭이 있다.

## 6. 격리 자기 점검

읽는다: 노트 경로는 `docs/adr/0001-isolation-boundary.md`의 식별 정보 목록.

출처 경로는 노트를 읽지 않았으니 이 단계를 건너뛰고, PR 본문에 건너뛴 사실을 적는다.

노트 경로는 산출물 전부를 노트와 대조한다: 페이지, `bib/` 엔트리, 도해 에이전트가 그린 SVG, PR 본문 초안, `verify:` 코멘트 초안.

- 노트의 문장이나 표현이 그대로거나 거의 그대로인 곳
- 식별 정보(ADR 0001의 목록)
- 노트의 도해나 표와 구성이 같은 도해와 표

대조는 아래 방법으로 한다. 눈으로 읽어서는 검증 반영 뒤 표 셀에 들어간 겹침 같은 것을 놓친다.

- 글: 산출물마다 노트와 어절 4-gram으로 대조한다. SVG는 `<text>`의 글자를 쓴다. 인용(`[@…]`)과 위키링크 대상은 빼고 토큰화한다(`[[대상|표시]]`는 표시만 남긴다). 걸린 것 가운데 규격의 고유 이름 나열(모듈 이름 목록 등)은 넘기고, 한국어 구절이 겹친 곳을 고친다.
- 도해: 구성은 4-gram으로 잡히지 않는다. 도해 에이전트의 SVG와 노트의 SVG에서 `<text>`를 좌표순(위에서 아래, 왼쪽에서 오른쪽)으로 뽑아 배치를 견준다.

찾은 곳은 고쳐 쓴다. 도해는 SendMessage로 도해 에이전트에게 배치나 요소 묶음을 바꿔 다시 그리게 하고, 노트의 구성은 알리지 않는다. 찾은 내용과 대조 결과는 어디에도 인용하지 않고, PR 본문에는 점검했다는 사실만 적는다.

완료: 산출물 파일마다 4-gram 대조를, 도해마다 배치 비교를 마쳤다.

## 8. 검토 1회차

읽는다: 위키 검증 문서의 검토 절.

그 절의 1회차를 돈다. 표기 검토(`style-reviewer`), 도해를 더하거나 고쳤으면 도해 검토(`diagram-reviewer`), 그리고 독자 검토(`external-reader`)다. 같은 커밋에서 한 메시지에 모두 띄운다. 지적을 모아 반영하고, 독자 검토의 지적은 소유자의 답을 받아 반영한다. 도해의 지적은 SendMessage로 도해 에이전트에게 고치게 한다.

완료: 1회차의 지적마다 처리 줄이 있고, 독자 검토의 승인과 반영 뒤 재판정 절의 단계를 마쳤다.

## 9. PR과 코멘트

읽는다: 위키 규약의 열린 PR과 겹치는 파일 절, 위키 검증 문서의 `verify:` 이슈, 검토 절, `CONTRIBUTING.md`의 PR 본문, 리뷰 절.

1. 위키 검증 문서 검토 절의 2회차를 돈다. 8단계의 검토가 1회차 커밋과의 diff를 보고, `CONTRIBUTING.md`의 리뷰 절대로 두 축 리뷰를 함께 돌린다. 2회차에서 나온 것만 반영하고 멈춘다.
2. push 직전에 머지된 형제 PR을 찾는다. 있으면 main으로 rebase하고, 그 PR이 더한 페이지의 alias로 이 묶음 페이지의 용어를 맞춘다. 맞추며 주장의 내용이 바뀌면 3단계의 재판정을 거친다. PR을 연 뒤 소유자 리뷰를 반영해 다시 push할 때도 이 확인을 한다.

   이어서 위키 규약의 열린 PR과 겹치는 파일 절을 따라, 더한 bib 엔트리와 도해가 열린 PR과 겹치는지 본다. 형제 PR이 바꾼 페이지에도 4단계의 주인 페이지 판정을 하고, 걸린 곳은 그 PR에 코멘트로 알린다. 명령은 작업 트리의 페이지만 읽으므로, 형제 PR의 페이지는 `git fetch origin pull/<PR>/head`와 `git show FETCH_HEAD:<파일>`로 열어 같은 규칙으로 본다.

3. PR을 올린다. 제목은 `content: <묶음 이름>`, 본문은 `CONTRIBUTING.md`의 PR 본문 절을 따른다. 인제스트 티켓에는 인수 기준이 없어, Spec의 결론은 그 문서의 리뷰 절을 따른다. `Closes #<인제스트 티켓>`.
4. 위 `verify:` 이슈 문단대로 찾은 이슈에 이 묶음의 코멘트 하나를 단다. 꼴은 위키 검증 문서를 따른다.
5. 소유자 리뷰를 반영하면 4단계의 반영 뒤 점검을 다시 돌린다. 소유자 리뷰 반영으로 미검증 주장이나 슬러그가 바뀌면 `verify:` 코멘트를 고쳐(`gh api -X PATCH repos/<owner>/<repo>/issues/comments/<id>`) 위키 검증 문서의 꼴을 다시 맞춘다. 새 코멘트를 더하지 않는다. 리뷰 대응에서 출처를 다시 볼 때는 4단계처럼 사본에서 필요한 구간만 연다.

완료: push마다 머지된 형제 PR을 확인했다. PR과 `verify:` 코멘트가 있고, PR 본문 Verification에 Spec의 결론이 있다.
