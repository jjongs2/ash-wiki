# 인제스트

묶음 티켓 하나가 PR 하나가 된다. 용어는 `CONTEXT.md`를 따른다.

먼저 읽는다: 티켓(`gh issue view <n> --comments`), `docs/adr/0001-isolation-boundary.md`, `docs/source-hierarchy.md`, `docs/wiki-conventions.md`, `docs/wiki-abbreviations.md`, `docs/wiki-verification.md`. 브랜치와 커밋은 `CONTRIBUTING.md`를 따르고, 타입은 `content`다.

티켓의 페이지 표에 `출처 후보` 열이 있으면 **출처 경로**, 없으면 **노트 경로**다. 출처 경로 티켓은 보강이 발행한 것으로, `ASH_WIKI_NOTES`를 열지 않고 표의 출처로 쓴다. 두 경로가 다른 단계는 따로 적는다.

출처를 열기 전에 위키 검증 문서의 접속 확인을 한다. 대상은 출처 후보의 호스트와 Wayback이다. 출처 경로는 1단계를 시작할 때, 노트 경로는 1단계에서 출처 후보를 적은 뒤 2단계 전에 한다. 접속 확인에서 멈추면 소유자의 답을 기다린다.

## 1. 초안

두 경로 모두 쓰기 전에 티켓의 `## 범위` 절과 주인 페이지 표를 읽고, 쓰는 동안 다음을 지킨다.

- 주인 페이지 표에서 이 묶음의 페이지가 링크만 하는 곳인 개념은 용어집의 주인 페이지 정의대로 쓴다.
- 표에 없는 개념도 `content/`를 grep해 주인 페이지가 이미 있으면 같은 정의대로 그 페이지로 링크한다.
- 새 용어나 기호를 쓰기 전에 `content/`를 grep해 기존 표기를 따른다. grep은 main만 보므로, 병렬로 도는 형제 묶음과의 표기는 범위 절의 alias 표를 따른다.
- 표기가 갈리면 위키 규약의 용어 절대로 닫힌 이슈의 소유자 결정을 먼저 찾는다.

노트 경로에서는 티켓의 페이지 표에 있는 페이지마다 `ASH_WIKI_NOTES`의 노트를 읽고, 자기 말로 초안을 쓴다. 표기는 위키 규약을 따른다. 인용은 아직 달지 않는다.

- 위키링크는 이미 있는 페이지와 이 묶음의 페이지로만 건다. 나머지 자리는 린트가 채운다.
- 도해와 표는 아직 넣지 않는다. 표는 4단계, 도해는 5단계의 일이다.
- 노트 경로에서는 페이지마다 출처 후보를 적어 둔다. 노트가 가리키는 공개 자료 가운데 1층일 만한 것이다.

출처 경로에서는 노트 대신 표의 줄마다 `출처 후보`를 열어 `요지`를 위키 규약의 출처 문장 절대로 자기 말로 쓴다. 출처 여는 법은 [verifier.md](verifier.md)를 따른다.

- 주장마다 끝에 `[@<키>] (<위치>)`로 인용 키와 위치(절, 쪽, 표)를 단다. 위치는 4단계에서 뺀다.
- `bib/`에 없는 키는 위키 규약의 인용 절대로 엔트리를 더한다.
- `종류`가 주장 추가나 정정이면 그 줄의 주장만 초안으로 쓴다. 기존 페이지의 다른 주장은 그대로 두고 검증에 넘기지 않는다.
- 정정이면 고친 주장 바로 뒤에 기존 주장과 그 인용 키, 위치를 `(기존: <주장> [@<키>] (<위치>))`로 남긴다. 기존 주장의 문장에 인용이 없으면 위키 규약의 인용 절대로 같은 문단에서 뒤따르는 인용이 그 출처다. 위치는 그 출처를 열어 찾고, 찾지 못하면 `(<위치>)`를 뺀다.
- 티켓에 `## Tags`가 있으면 그 태그의 표시 이름 파일과 대문 목록 줄을 더한다.

완료: 표의 모든 페이지에 초안과 출처 후보가 있다. 출처 경로에서는 초안의 주장마다 인용 키와 위치가 있다.

## 2. 검증

페이지마다 검증자를 하나씩 Agent 도구(`general-purpose`)로 띄운다. 한 메시지에 모두 띄워 병렬로 돌린다. 프롬프트는 [verifier.md](verifier.md)를 채워 쓴다.

검증자에게는 초안, 출처 후보, `bib/`의 기존 키 목록만 준다. 노트 경로와 노트의 표현은 주지 않는다. 검증자가 출처에 적힌 것만 인정하게 하기 위해서다.

출처 경로에서는 프롬프트를 [source-verifier.md](source-verifier.md)로 채워 쓴다. 검증자에게는 초안과, 초안이 인용한 키마다 URL만 준다. 검증자는 초안에 달린 인용 위치만 대조한다.

완료: 페이지마다 검증자의 반환이 있다.

## 3. 반환 확인

검증자마다 반환 JSON이 프롬프트의 계약을 지키는지 확인한다.

- 주장마다 `주장`, `종류`, `판정`, `사유`, `인용 키`가 판정에 맞게 채워져 있다.
- `종류`가 `규범`인 검증 완료 주장은 인용 키의 출처가 출처 위계 문서의 규범 주장 1층이고, `주장`이 위키 검증 문서의 좁혀 쓰기 절이 정한 규범 주장의 꼴이다. 어긋나면 그 검증자에게 돌려보내 다시 판정하게 한다.
- 노트 경로에서는 새 엔트리마다 `key`, `type`, `fields`가 있고, `fields`에 위키 규약의 `bib-fields` 표 필드가 모두 있다. 키는 위키 규약의 키 꼴을 따른다.
- 초안의 문장마다 판정된 주장이 하나 이상 있다.

빠진 것은 SendMessage로 그 검증자에게 돌려보내 채우게 한다.

완료: 모든 페이지의 모든 주장이 계약을 지킨다.

## 4. 판정 반영

위키 검증 문서의 판정 표대로 페이지를 고친다. 새 엔트리는 위키 규약의 인용 절대로 더하고, 미검증 주장은 `verify:` 코멘트 목록에 옮긴다.

출처 경로에서는 초안의 인용 위치와 `(기존: …)`를 뺀다. 정정 줄은 위키 검증 문서의 정정 절대로 반영하고, 가리지 못한 것은 `(게시됨)`을 붙여 코멘트 목록에 옮긴다.

빈 자리를 이을 때는 이미 검증된 주장만 쓴다. 표도 이때 ADR 0001대로 새로 구성해 넣는다. 어디를 표로 쓸지는 위키 규약의 표 절, 표에 인용을 다는 자리는 인용 절을 따른다. 새 페이지의 `verified`는 오늘 날짜로 두고, 기존 페이지의 `verified`는 위키 규약대로 둔다. 위키 검증 문서의 게시 기준에 못 미치는 페이지는 그 절대로 처리하고, PR 본문에 그 페이지를 적는다.

표준 페이지를 만들거나 그 `edition`·`status`를 바꾸면, 위키 검증 문서의 표준의 판 절에 있는 판을 바꾸는 PR의 대조를 한다. 이 묶음 밖의 페이지도 대상이다.

끝으로 주인 페이지 표의 줄마다, 링크만 하는 곳의 페이지를 그 개념의 이름과 alias로 grep해 설명이 다시 들어가지 않았는지 본다. 위키 규약의 중복 절에 걸리는 곳은 고친다.

완료: 초안의 모든 주장이 인용을 달고 게시되거나, 제외로 빠지거나, 코멘트 목록에 있다. 주인 페이지 표의 줄마다 grep 확인을 마쳤다. 표준 페이지를 만들거나 `edition`·`status`를 바꿨으면 판을 바꾸는 PR의 대조를 마쳤다.

## 5. 도해

도해 에이전트 하나를 Agent 도구(`general-purpose`)로 띄운다. 프롬프트는 [diagrammer.md](diagrammer.md)를 채워 쓴다. 도해 규칙은 위키 규약의 도해 절이다.

도해 에이전트에게는 묶음의 슬러그 목록과, 페이지가 인용한 키마다 출처 URL만 준다. 4단계를 마친 페이지는 검증 완료 주장과 인용 키만 담는다. 노트 경로, 노트의 표현, 노트에 어떤 도해가 있는지는 주지 않는다. 노트를 읽은 컨텍스트는 노트의 도해 구성을 닮게 그리기 쉬워서, 도해는 노트를 모르는 쪽이 그린다.

반환의 `diagrams`마다 파일이 있고 `pages`의 페이지에 들어갔는지, `skipped`와 합쳐 묶음의 모든 페이지가 나오는지 확인한다. 빠진 것은 SendMessage로 도해 에이전트에게 돌려보낸다.

완료: 묶음의 모든 페이지가 `diagrams`나 `skipped`에 있다.

## 6. 격리 자기 점검

출처 경로는 노트를 읽지 않았으니 이 단계를 건너뛰고, PR 본문에 건너뛴 사실을 적는다.

노트 경로는 산출물 전부를 노트와 대조한다: 페이지, `bib/` 엔트리, 도해 에이전트가 그린 SVG, PR 본문 초안, `verify:` 코멘트 초안.

- 노트의 문장이나 표현이 그대로거나 거의 그대로인 곳
- 식별 정보(`CONTEXT.md`의 정의)
- 노트의 도해나 표와 구성이 같은 도해와 표

대조는 아래 방법으로 한다. 눈으로 읽어서는 검증 반영 뒤 표 셀에 들어간 겹침 같은 것을 놓친다.

- 글: 산출물마다 노트와 어절 4-gram으로 대조한다. SVG는 `<text>`의 글자를 쓴다. 인용(`[@…]`)과 위키링크 대상은 빼고 토큰화한다(`[[대상|표시]]`는 표시만 남긴다). 걸린 것 가운데 규격의 고유 이름 나열(모듈 이름 목록 등)은 넘기고, 한국어 구절이 겹친 곳을 고친다.
- 도해: 구성은 4-gram으로 잡히지 않는다. 도해 에이전트의 SVG와 노트의 SVG에서 `<text>`를 좌표순(위에서 아래, 왼쪽에서 오른쪽)으로 뽑아 배치를 견준다.

찾은 곳은 고쳐 쓴다. 도해는 SendMessage로 도해 에이전트에게 배치나 요소 묶음을 바꿔 다시 그리게 하고, 노트의 구성은 알리지 않는다. 찾은 내용과 대조 결과는 어디에도 인용하지 않고, PR 본문에는 점검했다는 사실만 적는다.

완료: 산출물 파일마다 4-gram 대조를, 도해마다 배치 비교를 마쳤다.

## 7. 검사

`npm run check:content`를 돌려 고친다.

완료: 모든 검사가 `OK`다.

## 8. PR과 코멘트

1. push 직전에 위키 규약의 열린 PR과 겹치는 파일 절대로, 더한 bib 엔트리와 도해가 열린 PR과 겹치는지 본다.
2. PR을 올린다. 제목은 `content: <묶음 이름>`, 본문은 `CONTRIBUTING.md`의 세 부분이다. `Closes #<묶음 티켓>`.
3. 티켓의 인수 기준에 적힌 `verify:` 이슈에 이 묶음의 코멘트 하나를 단다. 꼴은 위키 검증 문서를 따른다.
4. 티켓 본문의 인수 기준 체크박스를 체크한다.
5. 리뷰는 `CONTRIBUTING.md`를 따른다. 리뷰 반영으로 미검증 주장이나 슬러그가 바뀌면 3의 코멘트를 고쳐(`gh api -X PATCH repos/<owner>/<repo>/issues/comments/<id>`) 위키 검증 문서의 꼴을 다시 맞춘다. 새 코멘트를 더하지 않는다.

완료: PR과 `verify:` 코멘트가 있고, 티켓의 인수 기준이 모두 체크됐다.
