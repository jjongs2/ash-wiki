# 인제스트

묶음 티켓 하나가 PR 하나가 된다. 용어는 `CONTEXT.md`를 따른다.

먼저 티켓을 읽는다(`docs/agents/issue-tracker.md`의 이슈 읽기). 규칙 문서는 한꺼번에 읽지 않는다. 단계와 절마다 "읽는다:"가 적은 문서와 절을 그 자리에서 읽는다. 브랜치와 커밋은 `CONTRIBUTING.md`의 브랜치, PR 제목 절을 따르고, 타입은 `content`다.

티켓의 페이지 표에 `출처 후보` 열이 있으면 **출처 경로**, 없으면 **노트 경로**다. 출처 경로 티켓은 보강이 발행한 것으로, `ASH_WIKI_NOTES`를 열지 않고 표의 출처로 쓴다. 두 경로가 다른 단계는 따로 적는다.

출처를 열기 전에 위키 검증 문서의 접속 확인을 한다. 읽는다: 위키 검증 문서의 접속 확인 절과 그 절이 견주는 봇 차단 호스트, 호스트별 여는 법 표. 대상은 출처 후보의 호스트와 Wayback이다. 출처 경로는 1단계를 시작할 때, 노트 경로는 1단계에서 출처 후보를 적은 뒤 2단계 전에 한다. 접속 확인에서 멈추면 소유자의 답을 기다린다.

**형제 PR**은 같은 `verify:` 이슈를 막는 다른 묶음 티켓의 열린 PR이다. 묶음 티켓은 `gh api repos/<owner>/<repo>/issues/<verify 이슈>/dependencies/blocked_by --jq '.[].number'`로 찾고, 티켓마다 열린 PR은 `gh pr list --state open --json number,closingIssuesReferences --jq '.[] | select(any(.closingIssuesReferences[]; .number == <티켓>)) | .number'`로 찾는다.

## 1. 초안

노트 경로는 메인 세션이 초안을 쓰고, 출처 경로는 초안 에이전트가 쓴다.

### 두 경로 공통

읽는다: 위키 규약의 용어, 위키링크, 중복 절, `docs/wiki-terms.md`. 출처 경로에서는 메인 세션 대신 초안 에이전트가 읽는다.

두 경로 모두 쓰기 전에 티켓의 `## 범위` 절과 주인 페이지 표를 읽고, 쓰는 동안 다음을 지킨다.

- 주인 페이지 표에서 이 묶음의 페이지가 링크만 하는 곳인 개념은 위키 규약의 중복 절대로 쓴다.
- 표에 없는 개념도 `content/`를 grep해 주인 페이지가 이미 있으면 같은 절대로 그 페이지로 링크한다.
- 용어는 `docs/wiki-terms.md`에 결정이 있으면 따른다. 결정이 없는 용어와 기호는 쓰기 전에 `content/`를 grep해 기존 표기를 따른다. grep은 main만 보므로, 병렬로 도는 형제 묶음과의 표기는 범위 절의 alias 표를 따른다.
- 표기 선택이 갈리면 위키 규약의 용어 절을 따른다.
- 위키링크는 이미 있는 페이지와 이 묶음의 페이지로만 건다. 나머지 자리는 린트가 채운다.
- 도해와 표는 아직 넣지 않는다. 표는 4단계, 도해는 5단계의 일이다.

### 노트 경로

읽는다: `docs/adr/0001-isolation-boundary.md`, 위키 규약의 표, 도해, 열린 PR과 겹치는 파일, 빌드 절을 뺀 전부, `docs/wiki-abbreviations.md`, 출처 위계 문서의 1층 출처 절.

티켓의 페이지 표에 있는 페이지마다 `ASH_WIKI_NOTES`의 노트를 읽고, 자기 말로 초안을 쓴다. 표기는 위키 규약을 따른다. 인용은 아직 달지 않는다.

- 페이지마다 출처 후보를 적어 둔다. 노트가 가리키는 공개 자료 가운데 1층일 만한 것이다.

### 출처 경로

읽는다: [drafter.md](drafter.md).

메인 세션은 출처를 열지 않는다. 접속 확인을 마치면 브리프를 만들어 지시 절을 쓰고, 초안 에이전트를 Agent 도구(`general-purpose`)로 띄운다. 출처 원문과 그것을 따지는 추론을 메인 세션의 컨텍스트 밖에 두기 위해서다. 프롬프트는 [drafter.md](drafter.md)의 띄우는 프롬프트를 채워 쓰고, `<사본 폴더>`는 세션의 scratchpad 디렉터리 아래 사본용 하위 폴더로 채운다.

- 초안 에이전트는 묶음당 하나다. 페이지마다 따로 띄우면 묶음 안에서 표기와 alias가 갈리고, 같은 개념을 두 페이지가 설명하고, 같은 출처를 여러 번 받는다.
- 표의 줄이 15개를 넘으면 페이지 단위로 나눠 차례로 띄운다. 줄이 적은 페이지끼리는 15줄을 넘지 않게 에이전트 하나에 묶는다. 뒤의 에이전트에게는 앞 에이전트들이 쓴 슬러그를 주어, 그 페이지를 읽고 표기를 맞추게 한다.

반환을 3단계처럼 확인한다. 초안 diff를 처음부터 끝까지 읽지 않고, 명령으로 볼 수 있는 것은 명령으로 본다. `<기준 커밋>`은 아래 브리프의 것이다.

- 표의 줄마다 초안이 있다. 반환의 `pages`가 맡긴 페이지를 모두 담고, `git status --short content/`에 그 파일이 있다. 초안이 없는 줄은 `열지 못한 출처`에 있다.
- 주장마다 인용 키와 위치가 있다. 인용 없는 블록은 `npm run check:diff -- --only uncited-block`, 위치 없는 인용은 `git diff -U0 <기준 커밋> -- content/ | grep -P '^\+(?!\+\+).*\[@[^\]]+\](?! \()'`과 새 페이지에 `git ls-files -o --exclude-standard content/ | xargs -r grep -HnP '\[@[^\]]+\](?! \()'`로 후보를 찾아 그 줄만 읽는다. `(기존: …)` 안에서 위치가 빠진 것은 찾지 못한 위치일 수 있다.
- 브리프에 `## 현행판 표`와 `## 사본 목록`이 있고, 반환의 `인용` URL마다 사본 목록에 짝이 있다.
- 반환 JSON의 키가 모두 있다.

빠진 것은 SendMessage로 그 초안 에이전트에게 돌려보내 채우게 한다.

`판단한 곳`, `고치지 않은 링크`, `현행판대로 고친 구성`은 PR 본문 초안에 옮긴다. `열지 못한 출처`의 호스트가 접속 확인에서 멈추는 경우에 해당하면 접속 확인처럼 소유자에게 묻고, 아니면 PR 본문 Verification에 적는다.

### 브리프

읽는다: 검증자 프롬프트와 [diagrammer.md](diagrammer.md)의 지시 블록. 노트 경로는 위키 검증 문서의 표준의 판 절과 봇 차단 호스트 표도.

출처 후보가 정해지면(출처 경로는 1단계를 시작할 때, 노트 경로는 출처 후보를 적은 뒤) **브리프**를 준비한다. 검증자, 도해 에이전트, 출처 경로의 초안 에이전트가 함께 읽는 파일 하나로, 세션의 scratchpad 디렉터리에 둔다. 저마다 따로 하면 판단이 갈리거나 서로 덮고, 같은 출처를 거듭 받기 때문이다. 절마다 쓰는 쪽이 정해져 있다. 담을 것:

- **지시**(메인 세션): `## 검증자 지시` 절에 검증자 프롬프트(노트 경로는 [verifier.md](verifier.md), 출처 경로는 [source-verifier.md](source-verifier.md))의 지시 블록을, `## 도해 에이전트 지시` 절에 [diagrammer.md](diagrammer.md)의 지시 블록을 옮긴다. 출처 경로는 `## 초안 에이전트 지시` 절에 [drafter.md](drafter.md)의 지시 블록도 옮긴다. 채울 자리는 프롬프트 파일이 정한다. `<기준 커밋>`은 1단계를 시작할 때의 `git merge-base origin/main HEAD`다.
- **현행판 표**(`## 현행판 표`, 노트 경로는 메인 세션, 출처 경로는 초안 에이전트): 출처 후보의 표준·명세마다 발행기관의 판 목록에서 현행판을 확인해, 이름과 현행판, 확인한 주소를 표로 적는다. 현행판의 뜻과 판 목록을 내지 않는 발행기관의 확인은 위키 검증 문서의 표준의 판 절이다. 티켓 범위가 적은 구성(모듈 등)이 현행판에 없으면 초안을 현행판대로 고치고, PR 본문에 적는다.
- **사본**(`## 사본 목록`, 노트 경로는 메인 세션, 출처 경로는 초안 에이전트): 출처를 받은 쪽이 받은 출처를 모두 본문을 텍스트로 세션의 scratchpad 디렉터리에 저장한다. 봇 차단 호스트(위키 검증 문서의 봇 차단 호스트 표)의 출처 후보는 초안에 쓰지 않았어도 브라우저로 한 번 열어 저장한다. 출처마다 원래 URL과 사본 경로를 짝지어 목록으로 적는다.
- **bib 키**(`## bib 키`, 메인 세션): 노트 경로에서만 둔다. `bib/`의 기존 키 목록과, 형제 PR이 더한 bib 키와 그 url이다. 형제 PR이 더한 bib는 PR마다 `gh pr view <PR> --json files --jq '.files[].path | select(startswith("bib/"))'`로 찾고, `git fetch origin pull/<PR>/head`와 `git show FETCH_HEAD:<파일>`로 url을 본다.

완료: 표의 모든 페이지에 초안과 출처 후보가 있다. 출처 경로에서는 초안 에이전트의 반환이 위 확인을 통과해, 초안의 주장마다 인용 키와 위치가 있고 주장이 아닌 편집마다 `(편집)`이 있다. 브리프에 지시, 현행판 표, 사본 목록이 있다.

## 2. 검증

읽는다: 검증자 프롬프트 파일의 띄우는 프롬프트 절.

페이지마다 검증자를 하나씩 Agent 도구(`general-purpose`)로 띄운다. 한 메시지에 모두 띄워 병렬로 돌린다. 프롬프트는 검증자 프롬프트 파일의 띄우는 프롬프트를 채워 쓴다. `<브리프 경로>`는 1단계의 브리프이고, `<작업 폴더>`는 세션의 scratchpad 디렉터리 아래 검증자마다 다른 하위 폴더로 채운다.

검증자에게는 브리프 경로와 자기 몫만 준다. 노트 경로의 몫은 초안과 출처 후보이고, 출처 경로의 몫은 슬러그와 초안이 인용한 키마다 URL(초안 에이전트 반환의 `인용`)이다. 출처 경로의 검증자는 초안에서 더하거나 고친 줄을 페이지에서 직접 뽑아, 거기 달린 인용 위치만 대조한다. 노트 경로와 노트의 표현은 주지 않는다. 검증자가 출처에 적힌 것만 인정하게 하기 위해서다.

완료: 페이지마다 검증자의 반환이 있다.

## 3. 반환 확인

읽는다: 출처 위계 문서의 1층 출처 절, 위키 검증 문서의 좁혀 쓰기 절. 노트 경로는 위키 규약의 인용 절도.

검증자마다 반환 JSON이 프롬프트의 계약을 지키는지 확인한다.

- 주장마다 `주장`, `종류`, `판정`, `사유`, `인용 키`가 판정에 맞게 채워져 있다.
- 출처 경로에서 `고쳐 쓸 문장`이 있으면 페이지의 `원래 문장`을 `고친 문장`으로 재판정 없이 바꾼다.
- `종류`가 `규범`인 검증 완료 주장은 인용 키의 출처가 출처 위계 문서의 규범 주장 1층이고, 위키 검증 문서의 좁혀 쓰기 절이 정한 규범 주장의 꼴이다. 꼴은 노트 경로에서는 `주장`으로, 출처 경로에서는 `고쳐 쓸 문장`까지 반영한 페이지 문장으로 보고, 그 문장이 출처 구간을 잇는 문장이면 구간을 여는 문장의 표준 주어도 함께 본다. 어긋나면 그 검증자에게 돌려보내 다시 판정하게 한다.
- 노트 경로에서는 새 엔트리마다 `key`, `type`, `fields`가 있고, `fields`에 위키 규약의 `bib-fields` 표 필드가 모두 있고, 보고서와 학위 논문은 `bib-type-fields` 표의 `type` 필드도 있다. 키는 위키 규약의 키 꼴을 따른다.
- 새 엔트리의 url이 `bib/`나 형제 PR의 엔트리에 이미 있으면 그 키로 바꾼다. 검증자끼리 새 엔트리의 url이 같으면 키 하나로 합친다.
- 초안의 문장마다 판정된 주장이 하나 이상 있다. `(편집)`을 단 문장은 빼고 센다.

빠진 것은 SendMessage로 그 검증자에게 돌려보내 채우게 한다.

**재판정**: 이 단계 뒤에 메인 세션이 다른 이유(도해, 중복 정리, 리뷰 반영)로 주장의 내용을 바꾸면, 바꾼 문장을 SendMessage로 그 페이지의 검증자에게 보내 다시 판정받는다.

완료: 모든 페이지의 모든 주장이 계약을 지키고, 같은 url에 키가 하나다.

## 4. 판정 반영

읽는다: 위키 검증 문서의 판정, 정정, 게시 기준, 표준의 판, `verify:` 이슈, 반영 뒤 점검 절. 위키 규약의 페이지 타입과 프론트매터, 인용, 중복, 위키링크, 표 절. `docs/adr/0001-isolation-boundary.md`. 출처 경로는 빈 자리를 잇는 문장을 쓰려고 위키 규약의 출처 문장, 용어, 약어, 수식, 강조 절과 `docs/wiki-terms.md`, `docs/wiki-abbreviations.md`도.

위키 검증 문서의 판정 표대로 페이지를 고친다. 새 엔트리는 위키 규약의 인용 절대로 더하고, 미검증 주장은 `verify:` 코멘트 목록에 옮긴다.

출처 경로에서는 초안의 인용 위치, `(기존: …)`, `(편집)`을 뺀다. 정정 줄은 위키 검증 문서의 정정 절대로 반영하고, 가리지 못한 것은 `(게시됨)`을 붙여 코멘트 목록에 옮긴다.

출처를 다시 볼 때는 브리프 사본 목록의 사본에서 필요한 구간만 연다(`grep -n`으로 찾아 `sed -n`으로). 사본 전체를 읽거나 다시 받지 않는다.

빈 자리를 이을 때는 이미 검증된 주장만 쓴다. 표도 이때 ADR 0001대로 새로 구성해 넣는다. 어디를 표로 쓸지는 위키 규약의 표 절, 표에 인용을 다는 자리는 인용 절을 따른다. 새 페이지의 `verified`는 오늘 날짜로 두고, 기존 페이지의 `verified`는 위키 규약대로 둔다. 위키 검증 문서의 게시 기준에 못 미치는 페이지는 그 절대로 처리하고, PR 본문에 그 페이지를 적는다.

표준 페이지를 만들거나 그 `edition`·`status`를 바꾸면, 위키 검증 문서의 표준의 판 절에 있는 판을 바꾸는 PR의 대조를 한다. 이 묶음 밖의 페이지도 대상이다.

반영을 마치면 셋을 한다.

- **범위 대조**: `## 범위`의 페이지별 줄과 주인 페이지 표의 줄마다 결과를 검증 완료로 게시, 미검증, 제외, 이름만 가운데 하나로 적는다. "이름만"인 개념(주인이 아직 계획 없는 주제인 줄 등)은 이름 이상 쓰지 않는다.
- **반영 뒤 점검**: `npm run check:diff -- --ticket <묶음 티켓>`을 돌려 위키 검증 문서의 반영 뒤 점검 절대로 항목마다 후보를 모두 본다.
- **주인 페이지 점검**: 반영 뒤 점검의 `owner-page` 후보를 줄마다 하나도 빼지 않고 그 문단까지 읽어, 위키 규약의 중복 절과 위키링크 절대로 판정한다. 링크가 없다고 나온 페이지는 개념의 이름과 alias로 grep해 설명이 남았는지 본다.

완료: 초안의 모든 주장이 인용을 달고 게시되거나, 제외로 빠지거나, 코멘트 목록에 있다. 범위 대조, 반영 뒤 점검, 주인 페이지 점검을 마쳤다. 표준 페이지를 만들거나 `edition`·`status`를 바꿨으면 판을 바꾸는 PR의 대조를 마쳤다.

## 5. 도해

읽는다: [diagrammer.md](diagrammer.md)의 띄우는 프롬프트 절. 도해 규칙은 도해 에이전트가 읽는다.

도해 에이전트 하나를 Agent 도구(`general-purpose`)로 띄운다. 프롬프트는 [diagrammer.md](diagrammer.md)의 띄우는 프롬프트를 채워 쓰고, `<작업 폴더>`는 세션의 scratchpad 디렉터리 아래 도해 에이전트의 하위 폴더로 채운다. 도해 규칙은 위키 규약의 도해 절이다.

도해 에이전트에게는 브리프 경로, 묶음의 슬러그 목록, 페이지가 인용한 키마다 출처 URL만 준다. 4단계를 마친 페이지는 검증 완료 주장과 인용 키만 담는다. 노트 경로, 노트의 표현, 노트에 어떤 도해가 있는지는 주지 않는다. 노트를 읽은 컨텍스트는 노트의 도해 구성을 닮게 그리기 쉬워서, 도해는 노트를 모르는 쪽이 그린다.

반환의 `diagrams`마다 파일이 있고 `pages`의 페이지에 들어갔는지, `skipped`와 합쳐 묶음의 모든 페이지가 나오는지 확인한다. `revised`의 도해는 PR 본문에 적는다. `text_changes`는 3단계의 재판정을 거쳐 메인 세션이 고친다. 빠진 것은 SendMessage로 도해 에이전트에게 돌려보낸다.

완료: 묶음의 모든 페이지가 `diagrams`나 `skipped`에 있고, `text_changes`마다 재판정을 거쳐 고쳤거나 고치지 않은 까닭이 있다.

## 6. 격리 자기 점검

읽는다: 노트 경로는 `docs/adr/0001-isolation-boundary.md`의 식별 정보 목록.

출처 경로는 노트를 읽지 않았으니 이 단계를 건너뛰고, PR 본문에 건너뛴 사실을 적는다.

노트 경로는 산출물 전부를 노트와 대조한다: 페이지, `bib/` 엔트리, 도해 에이전트가 그린 SVG, PR 본문 초안, `verify:` 코멘트 초안.

- 노트의 문장이나 표현이 그대로거나 거의 그대로인 곳
- 식별 정보(ADR 0001의 목록)
- 노트의 도해나 표와 구성이 같은 도해와 표

대조는 아래 방법으로 한다. 눈으로 읽어서는 검증 반영 뒤 표 셀에 들어간 겹침 같은 것을 놓친다.

- 글: 산출물마다 노트와 어절 4-gram으로 대조한다. SVG는 `<text>`의 글자를 쓴다. 인용(`[@…]`)과 위키링크 대상은 빼고 토큰화한다(`[[대상|표시]]`는 표시만 남긴다). 걸린 것 가운데 규격의 고유 이름 나열(모듈 이름 목록 등)은 넘기고, 한국어 구절이 겹친 곳을 고친다.
- 도해: 구성은 4-gram으로 잡히지 않는다. 도해 에이전트의 SVG와 노트의 SVG에서 `<text>`를 좌표순(위에서 아래, 왼쪽에서 오른쪽)으로 뽑아 배치를 견준다.

찾은 곳은 고쳐 쓴다. 도해는 SendMessage로 도해 에이전트에게 배치나 요소 묶음을 바꿔 다시 그리게 하고, 노트의 구성은 알리지 않는다. 찾은 내용과 대조 결과는 어디에도 인용하지 않고, PR 본문에는 점검했다는 사실만 적는다.

완료: 산출물 파일마다 4-gram 대조를, 도해마다 배치 비교를 마쳤다.

## 8. PR과 코멘트

읽는다: 위키 규약의 열린 PR과 겹치는 파일 절, 위키 검증 문서의 `verify:` 이슈 절, `CONTRIBUTING.md`의 PR 본문, 리뷰 절.

1. push 직전에 위키 규약의 열린 PR과 겹치는 파일 절대로, 더한 bib 엔트리와 도해가 열린 PR과 겹치는지 본다. 형제 PR이 바꾼 페이지에도 4단계의 주인 페이지 점검을 하고, 걸린 곳은 그 PR에 코멘트로 알린다. 명령은 작업 트리의 페이지만 읽으므로, 형제 PR의 페이지는 `git fetch origin pull/<PR>/head`와 `git show FETCH_HEAD:<파일>`로 열어 같은 규칙으로 본다.
2. PR을 올린다. 제목은 `content: <묶음 이름>`, 본문은 `CONTRIBUTING.md`의 세 부분이다. `Closes #<묶음 티켓>`.
3. 티켓의 인수 기준에 적힌 `verify:` 이슈에 이 묶음의 코멘트 하나를 단다. 꼴은 위키 검증 문서를 따른다.
4. 티켓 본문의 인수 기준 체크박스를 체크한다.
5. 리뷰는 `CONTRIBUTING.md`를 따른다. 리뷰를 반영하면 4단계의 반영 뒤 점검을 다시 돌려, 고친 곳만이 아니라 브랜치 diff 전체의 후보를 본다. 리뷰 반영으로 미검증 주장이나 슬러그가 바뀌면 3의 코멘트를 고쳐(`gh api -X PATCH repos/<owner>/<repo>/issues/comments/<id>`) 위키 검증 문서의 꼴을 다시 맞춘다. 새 코멘트를 더하지 않는다. 리뷰 대응에서 출처를 다시 볼 때는 4단계처럼 사본에서 필요한 구간만 연다.

완료: PR과 `verify:` 코멘트, 리뷰 요약 코멘트가 있고, 티켓의 인수 기준이 모두 체크됐다.
