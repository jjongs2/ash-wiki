# 조사 브리프

[소식 조사](SKILL.md)의 [3. 찾기](SKILL.md#3-찾기)와 [4. 고르기](SKILL.md#4-고르기)를 맡은 조사 에이전트용 브리프다. 무엇을 찾고 싣는지는 그 두 단계와 거기서 가리키는 문서가 정한다. 이 브리프는 찾는 요령과 내는 꼴만 적는다.

## 부르는 쪽이 알려 주는 값

- 그룹 이름(한 글자. 출력 파일 이름이 된다)과 맡은 매체·검색 질의
- 조사할 주차와 주차마다의 월요일·일요일, 소급 조사인지
- 작업 폴더(절대 경로)

## 먼저 읽는다

1. [SKILL.md](SKILL.md)의 3, 4단계와 [5. 중복](SKILL.md#5-중복)의 첫 두 문단(사건 키)
2. [outlets.md](outlets.md): 맡은 매체의 줄, 열·접속·검색 질의 절
3. `docs/source-access.md`(호스트별 여는 법)
4. `docs/weekly-news.md`의 필드 표
5. 작업 폴더의 `past.tsv`: 지난 호의 소식 항목(탭 구분: 주차, 원어 제목, URL, 매체, 발행일, 요약)
6. 구역의 뜻: `content/tags/<구역>.md`와 그 아래 파일

## 찾는 요령

**지난 기간으로 거슬러 보기**: 피드가 기간의 첫 월요일까지 닿지 않으면 다음 순서로 찾는다.

1. 피드의 `?paged=N`, HTML 목록의 쪽 넘김, 연도별·월별 보관 목록, WordPress REST(`/wp-json/wp/v2/posts?after=…&before=…`)
2. Google News로 그 매체의 그 기간 글: `https://news.google.com/rss/search?q=site:<호스트>+after:<월요일>+before:<다음 월요일>&hl=…`
3. Wayback(`https://web.archive.org/cdx/search/cdx?…`)이나 사이트맵

어디로도 닿지 않으면 접속 기록의 `shallow`에 가장 오래 닿은 글의 날짜를 적는다.

**Google News**: 질의의 비ASCII 낱말은 퍼센트 인코딩한다. 요청 사이를 2초 이상 띄우고, 503이 나면 1분 쉬고 다시 한다. 계속 막히면 DuckDuckGo를 브라우저로 열어 날짜 필터(`df=<월요일>..<일요일>`)를 쓰고, 한국어는 Naver 뉴스 검색(기간 지정)을 쓴다. 그 밖의 요령은 [outlets.md의 검색 질의 절](outlets.md#검색-질의)에 있다.

**1차 발표 찾기**: 제3자 기사를 싣기로 하기 전에 1차 발표를 끝까지 찾는다. 찾지 못한 것은 열리지 않은 것이 아니다([4. 고르기](SKILL.md#4-고르기)).

1. 기사가 가리키는 보도자료 링크
2. 낸 곳의 뉴스룸과 사이트 검색(사이트 안 검색, Google News `site:` 질의). 정부 발표는 정책브리핑(korea.kr) 같은 정부 포털도 본다.
3. 낸 곳의 WordPress REST
4. 배포본(PR Newswire, Business Wire, GlobeNewswire, PR TIMES)
5. Wayback

열리지 않는다고 정하기 전에 `docs/source-access.md`의 여는 법을 모두 써 본다. 그래도 열리지 않으면 `primary_outlet`에 낸 곳을, `note`에 HTTP 코드나 캡차 같은 까닭과 해 본 방법을 적는다.

**리콜**(리콜 그룹)

- NHTSA: 리콜 평면 파일([6. 주요 소식](SKILL.md#6-주요-소식)의 주소, 필드는 `https://static.nhtsa.gov/odi/ffdd/rcl/RCL.txt`)에서 접수일 `RCDATE`가 기간 안인 캠페인을 뽑아 4단계의 리콜 기준으로 고른다. 평면 파일이 아직 기간의 접수분을 담지 못했으면 API(`https://api.nhtsa.gov/recalls/campaignNumber?campaignNumber=<번호>`)로 보충한다. 원문 URL은 `https://www.nhtsa.gov/recalls?nhtsaId=<캠페인 번호>`이고, 제목은 `past.tsv`의 NHTSA 리콜 항목(`Recall 26V…`)과 같은 꼴로 쓴다.
- 싣기로 한 리콜마다 [recall.py](recall.py)로 대수와 새 결함 유형을 세어 `note`에 적는다. 6단계의 주요 판정에 쓴다.
- 매체 목록의 리콜 매체(KBA, 국토교통부, 国土交通省 등)는 그 줄의 찾는 법을 따른다. 레코드마다 주소가 없으면 목록 주소로 링크한다.
- 그 밖의 나라에서 기간에 보도된 소프트웨어·전장 원인 리콜을 Google News로 한 번 훑는다.

## 출력

작업 폴더의 `out/` 아래에 그룹 이름으로 두 파일을 쓴다. 원문 사본 같은 작업 파일은 `out/<그룹>-tmp/` 아래에 두고, 그 밖의 파일은 만들지 않는다. 저장소의 추적 파일은 읽기만 한다.

### 후보: `out/<그룹>.jsonl`

후보마다 한 줄이다. 한 줄에 줄바꿈이나 탭을 넣지 않고, 같은 원문을 두 번 쓰지 않는다.

<!-- prettier-ignore -->
```jsonl
{"week":"2026-w37","title":"원문 제목 그대로","url":"https://…","outlet":"매체 이름","date":"2026-09-08","image":"https://… 또는 빈 문자열","regions":["network"],"kind":"1차","inlist":true,"verdict":"싣기","reason":"","threshold":"새 사양","primary_outlet":"","event":{"org":"Vector","subject":"CANoe 19"},"digest":"한국어 요약","same_event_seen_at":[],"dup_of":"","note":""}
```

| 필드                 | 값                                                                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `week`               | 발행일이 드는 ISO 주차                                                                                                                             |
| `title`, `url`       | 원문의 제목 그대로와 실제 원문 주소(Google News 링크가 아닌 것)                                                                                    |
| `outlet`             | [매체 목록의 열](outlets.md#열)의 매체 이름                                                                                                        |
| `date`, `image`      | `docs/weekly-news.md` 필드 표의 발행일과 이미지. 페이지의 메타 날짜는 수정일일 수 있으니 본문, 주소의 날짜와 맞춰 본다. 이미지 주소의 공백은 `%20` |
| `regions`            | [7. 쓰기](SKILL.md#7-쓰기)의 구역 규칙대로 구역 이름의 배열. 기타는 `["기타"]`                                                                     |
| `kind`               | `1차` 또는 `제3자`([3. 찾기](SKILL.md#3-찾기)의 두 갈래)                                                                                           |
| `inlist`             | 3단계의 목록 밖이면 `false`                                                                                                                        |
| `verdict`, `reason`  | `싣기`나 `빼기`. 빼면 `reason`에 4단계 기준 이름(기간, 1차 발표 우선, 유료, 광고성 기사, 루머, 문턱)이나 `범위 밖`과 한 줄 설명                    |
| `threshold`          | 제품·인증 발표 문턱을 넘었으면 넘은 조건. 문턱 대상이 아니면 빈 문자열                                                                             |
| `primary_outlet`     | 1차 발표가 열리지 않아 제3자 기사를 실을 때 1차 발표를 낸 곳                                                                                       |
| `event`              | 사건 키. `org`는 발표하거나 결함이 난 회사·기관, `subject`는 리콜 번호(NHTSA 캠페인 번호가 있으면 그것), 표준 번호(판 포함), 결함이나 제품 이름    |
| `digest`             | 싣기일 때만 쓰는 요약. 7단계의 요약 규칙을 따른다                                                                                                  |
| `same_event_seen_at` | 같은 사건을 다룬 다른 원문의 주소. 같은 사건을 여러 주소로 찾았으면 1차 발표 하나만 후보로 쓰고 나머지를 여기에 둔다                               |
| `dup_of`             | `past.tsv`에 같은 사건이 있으면 그 줄의 주차와 원어 제목. 새 진전인지는 `note`에 적는다                                                            |
| `note`               | 판정의 근거, 확인하지 못한 값의 까닭, 리콜의 대수와 새 결함 유형                                                                                   |

### 접속 기록: `out/<그룹>-access.jsonl`

맡은 매체·질의마다, 그리고 자유 검색마다 한 줄이다. [절차 검사](procedure.ts)가 이 파일을 매체 목록과 검색 질의에 대 본다.

<!-- prettier-ignore -->
```jsonl
{"source":"Vector","week":"","opened":true,"how":"피드, ?paged=3까지","seen":14,"reason":"","shallow":"","differs":""}
```

| 필드      | 값                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `source`  | 매체 목록의 매체 이름이나 검색 질의 절의 질의 이름(굵은 글씨) 그대로. 자유 검색은 `자유 검색 <구역>`                                                               |
| `week`    | 소급 조사에서 찾는 법이 그 주의 날짜(`<월요일>`)를 채우는 검색 질의인 곳은 주차마다 한 줄씩 쓰고 그 주차를 적는다. 그 밖에는 빈 문자열(조사 기간 전체)             |
| `opened`  | 그 기간의 글 목록이나 질의 결과를 실제로 열어 봤으면 `true`                                                                                                        |
| `how`     | 연 방법(피드, 쪽 넘김, Google News 등)                                                                                                                             |
| `seen`    | 그 기간의 글이나 결과 수                                                                                                                                           |
| `reason`  | `opened`가 `false`일 때 열지 못한 까닭과 해 본 방법. 비우면 절차 검사가 실패한다                                                                                   |
| `shallow` | 기간의 첫 월요일까지 거슬러 가지 못했으면 가장 오래 닿은 글의 날짜                                                                                                 |
| `differs` | 접속 결과가 비고와 다르면(막힘, 주소 이전, 쪽 넘김, 끊긴 분류, 유료 전환, 광고성 글만 남음, 질의 결과의 결함) 무엇이 다른지와, 실행 환경 탓인지 사이트 쪽 변화인지 |

## 주의

- 요청 간격, User-Agent, 여는 순서, 브라우저 쓰는 법은 [outlets.md의 접속 절](outlets.md#접속)을 따른다.
- 셸 명령이 복잡하다고(변수, 반복문, heredoc) 거부되면 파이썬 스크립트를 `out/<그룹>-tmp/`에 써서 `python3 -I <경로>`로 돌린다.
- 확인하지 못한 값은 지어내지 않는다. 빈 문자열로 두고 `note`에 까닭을 적는다.
- 마지막 응답에는 두 파일의 경로, 후보 수(싣기/빼기), 열지 못한 곳과 얕은 피드만 짧게 적는다.
