# 재조사

`verify:` 이슈 하나가 PR 하나가 된다. 절차의 정본은 위키 검증 문서의 재조사 절이고, 이 스킬은 그것을 실행 단계로 옮긴다. 용어는 `CONTEXT.md`를 따른다.

먼저 읽는다: 이슈(`gh issue view <n> --comments`), `docs/wiki-verification.md`, `docs/source-hierarchy.md`, `docs/wiki-conventions.md`. 브랜치와 커밋은 `CONTRIBUTING.md`를 따르고, 타입은 `content`다.

`ASH_WIKI_NOTES`는 열지 않는다. 재조사는 이슈에 모인 주장과 출처, 게시된 페이지만 본다.

## 판정 라벨

재조사 에이전트의 반환과 이슈 본문의 항목 메모는 아래 다섯 라벨을 쓴다. 라벨은 위키 검증의 세 판정을 처리별로 나눈 것이고, 새 판정이 아니다.

| 라벨      | 언제                                                                   | 판정                                                   | 처리                                                                                              |
| --------- | ---------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 고쳐 씀   | 1층 출처가 주장을 뒷받침하거나, 다르게 말하고 출처 쪽이 분명하다       | 검증 완료                                              | 출처대로 고친 주장을 게시한다                                                                     |
| 일부만    | 출처가 주장의 일부만 뒷받침한다                                        | 뒷받침된 부분은 검증 완료, 남은 부분은 미검증이나 제외 | 뒷받침된 부분만 게시하고, 남은 부분을 메모에 적는다                                               |
| 좁혀 씀   | 표준 원문이 아닌 발행기관 하나의 자료만 뒷받침해, 그 범위로 좁혀 쓴다  | 검증 완료                                              | 좁혀 쓰기 꼴로 게시한다                                                                           |
| 이미 있음 | 주장이나 고친 주장이 대상 페이지나 주인 페이지에 인용과 함께 이미 있다 | 검증 완료                                              | 페이지 글을 고치지 않고 체크한다. 대상 페이지에 주인 페이지 링크가 없으면 한 문장과 링크만 더한다 |
| 미검증    | 다시 시도해도 뒷받침하는 1층 출처를 찾지 못했다                        | 미검증                                                 | 사유와 시도한 출처를 메모에 적는다                                                                |

- 제외는 판정 이름을 그대로 라벨 자리에 쓴다. 반환의 `라벨`은 `제외`이고, 이슈 본문에는 취소선을 긋고 이유를 적는다.
- 한 항목에 라벨은 하나다. 둘 이상에 걸리면 `일부만`, `이미 있음`, `좁혀 씀`, `고쳐 씀` 순으로 앞선 것을 고르고, 나머지 사정은 메모에 적는다. 예: 뒷받침된 부분이 이미 있고 남은 부분이 있으면 `일부만`이고, 메모에 이미 있는 페이지를 적는다.
- `(게시됨)` 항목은 위키 검증의 정정 절대로 `고쳐 씀`, `제외`, `미검증` 가운데 하나다.

이슈 본문의 항목은 이 꼴로 적는다. 체크는 검증 완료, 취소선은 제외다.

```md
- [x] <슬러그>: <주장> — 고쳐 씀: <게시한 주장>
- [x] <슬러그>: <주장> — 일부만: <게시한 주장>. 남은 부분: <뒷받침하지 못한 주장>
- [x] <슬러그>: <주장> — 좁혀 씀: <게시한 주장>
- [x] <슬러그>: <주장> — 이미 있음: `<슬러그>`의 <주장>
- [ ] <슬러그>: <주장> — 미검증: `<사유>`. 시도한 출처: <URL>
- [ ] ~~<슬러그>: <주장>~~ — 제외: <이유>
```

## 1. 시작

1. `gh api repos/<owner>/<repo>/issues/<n> --jq .issue_dependencies_summary.blocked_by`가 0인지 본다. 아니면 열린 blocker를 `docs/agents/issue-tracker.md`의 Blocking 절대로 찾아 번호를 알리고 멈춘다.
2. 위키 검증 재조사 1단계대로 코멘트를 모아 이슈 본문을 `## <미검증 사유>` 절로 다시 쓴다.
   - `## Parent`와 `## What to build`는 남기고, What to build 끝에 "시도한 출처는 묶음 코멘트에 있다."를 더한다. 시도한 출처는 본문에 옮기지 않는다.
   - 항목이 없는 사유 절은 뺀다. 항목의 주장은 코멘트의 글 그대로 옮긴다.
3. 이슈가 열린 뒤 출처 위계가 넓어졌는지 `git log --since=<이슈 생성일> -- docs/source-hierarchy.md docs/adr/`로 본다. 1층을 더한 커밋만 세고, 문서를 옮기거나 문구만 고친 커밋은 세지 않는다. 넓어졌으면 위키 검증 재조사 절의 마지막 문단대로 모든 항목을 새 위계로 본다.

PR이 머지되기 전에 위계가 넓어지면 main으로 rebase하고, 남은 미검증 항목만 2단계부터 다시 돌린다.

완료: blocked-by가 0이고, 이슈 본문이 사유별 절로 다시 쓰였고, 위계를 넓힌 커밋이 있는지 확인했다.

## 2. 재조사 에이전트

사유 절마다 재조사 에이전트를 하나씩 Agent 도구(`general-purpose`)로 띄운다. 한 절의 항목이 열 개를 넘으면 묶음 코멘트 단위로 나눈다. 한 메시지에 모두 띄워 병렬로 돌린다. 프롬프트는 [reinvestigator.md](reinvestigator.md)를 채워 쓴다.

에이전트에게는 맡은 항목 줄과 그 항목의 시도한 출처만 준다. `<작업 폴더>`는 세션의 scratchpad 디렉터리 아래 에이전트마다 다른 하위 폴더로 채운다. 1단계에서 위계를 넓힌 커밋을 찾았으면 더한 1층을 한 줄로 함께 준다.

완료: 에이전트마다 반환이 있다.

## 3. 반환 확인

에이전트마다 반환 JSON이 프롬프트의 계약을 지키는지 확인한다.

- 맡긴 항목마다 `라벨`과 `메모`가 있고, 라벨이 [판정 라벨](#판정-라벨) 표의 값이나 `제외`다.
- `고쳐 씀`, `좁혀 씀`의 항목은 `반영안`이 있고, 문장마다 인용 키와 위치가 있다. `일부만`도 같고, 뒷받침된 부분이 이미 있으면 반영안이 비고 메모에 그 페이지가 있다.
- `grep`이 대상 페이지 밖까지 본 결과다.
- 반영안의 문장이 항목의 주장 범위 안이다. 항목에 없는 사실을 더한 문장은 빼고, 그것이 게시된 페이지의 틀린 곳이면 `범위 밖`으로 옮긴다.

빠진 것은 SendMessage로 그 에이전트에게 돌려보낸다.

완료: 모든 항목이 계약을 지킨다.

## 4. 원문 재대조

반영안의 문장마다 인용 위치를 원문과 다시 대조한다. 표본이 아니라 반영하는 모든 문장이 대상이다. 대조는 반영안을 쓰지 않은 빈 컨텍스트의 에이전트가 한다.

반영안을 페이지별로 모아, 페이지마다 출처 경로 검증자를 하나씩 Agent 도구(`general-purpose`)로 띄운다. 프롬프트는 인제스트의 [source-verifier.md](../wiki-ingest/source-verifier.md)를 그대로 쓴다.

- `<초안>`: 첫 줄에 "재조사 반영안이다. `(기존: …)`가 없는 문장은 새로 더하는 문장이다."를 두고, 그 페이지의 반영안 문장을 `[@<키>] (<위치>)`와 함께 넣는다. `(게시됨)` 항목의 문장에만 `(기존: <기존 문장> [@<키>])`를 붙인다.
- `<키와 URL 목록>`: 반영안이 인용한 키마다 URL. 새 키는 반환의 `entries`에서 가져온다.

검증자가 문장을 주장으로 쪼개 돌려주면, 쪼갠 주장이 모두 검증 완료일 때 그 문장이 검증 완료다. 사유가 위치를 고쳐 적었으면 반영안의 위치를 고친다. 검증 완료가 아닌 주장이 든 문장은 그 항목의 라벨을 다시 정한다. 문장을 출처대로 고쳐 다시 대조하거나, 그 부분을 남은 부분으로 돌려 `일부만`으로, 남는 것이 없으면 `미검증`으로 둔다.

완료: 반영하는 모든 문장이 대조를 거쳐 검증 완료다.

## 5. 반영

- 반영안을 페이지에 넣고 인용 위치를 뺀다. 인용 자리와 묶음은 위키 규약의 인용 절, 출처 표시와 그 절 단위 묶음은 위키 검증의 좁혀 쓰기를 따른다.
- 새 엔트리는 위키 규약의 인용 절대로 `bib/`에 더한다.
- `verified`는 위키 규약의 페이지 타입과 프론트매터 절대로 둔다.
- 항목의 페이지가 없으면(게시 기준에 못 미쳐 만들지 않은 페이지) 위키 검증의 게시 기준을 넘을 때만 만들고, PR 본문에 적는다.
- 이슈 본문의 항목마다 [판정 라벨](#판정-라벨)의 꼴로 체크, 취소선, 메모를 단다.
- `범위 밖`은 모아 새 이슈로 낸다. 제목은 `CONTRIBUTING.md`의 이슈 절대로 `content: <주제>` 꼴이고, 라벨은 `needs-triage`다(`docs/agents/triage-labels.md`).

완료: 이슈 본문의 모든 항목에 라벨과 메모가 있고, 검증 완료 항목의 반영안이 페이지에 있다.

## 6. 사후 점검

- 항목 대응: 체크한 항목마다 diff나 메모에 적은 기존 페이지에 그 주장이 있고, diff의 문장마다 체크한 항목이 있다.
- 새 bib 엔트리: `url`마다 `curl -sIL`로 위키 검증 출처 상태 절의 `url` 기준(리다이렉트 뒤 2xx이고 WAF 챌린지가 아님)을 본다. 막히면 브라우저 User-Agent로 다시 묻고, 봇 차단 호스트는 브라우저로 연다.
- 표준 문장: 더하거나 고친 줄에서 `(ISO|IEC|IEEE|SAE|AUTOSAR|RFC|ITU-T|Bosch|OSEK|POSIX|표준|규격|명세)([^.]|\.[0-9])*(에서|에 따르면) `를 grep한다. 걸린 문장 가운데 표준 원문이 뒷받침하는 문장만 위키 검증의 표준의 판 꼴로 고친다.
- 페이지 사이 중복: 더한 문장의 핵심어로 `content/` 전체를 grep해, 위키 규약의 중복 절에 걸리는 곳을 고친다.
- `npm run check:content`를 돌려 고친다. 여러 인용의 순서도 여기서 잡힌다.

완료: 위 점검이 모두 끝났고 `check:content`가 모두 `OK`다.

## 7. PR과 마무리

검증 완료 항목이 없으면 PR 없이 이슈를 닫는다(위키 검증 재조사 4단계).

1. bib 엔트리를 더했으면 push 직전에 위키 규약의 인용 절대로 열린 PR과 키가 겹치는지 본다.
2. PR을 올린다. 제목은 `content: <주제> 미검증 주장 재조사`, 본문은 `CONTRIBUTING.md`의 세 부분이고 `Closes #<verify 이슈>`를 적는다.
   - Changes: 라벨별 항목 수, `출처와 어긋남` 항목의 결과, 더한 bib 수. 항목별 결과는 이슈 본문을 가리킨다.
   - Verification: 6단계의 점검과 결과, 원문 재대조에서 고친 문장 수, "재조사는 이슈에 모인 주장과 출처만 보고 했고, 소스 노트는 읽지 않았다."
3. 리뷰는 `CONTRIBUTING.md`를 따른다.

완료: PR이 있고, 이슈 본문의 모든 항목이 체크, 취소선, 미검증 메모 가운데 하나다. `범위 밖`이 있었으면 새 이슈가 있다.
