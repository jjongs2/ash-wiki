# 재조사

`verify:` 이슈 하나가 PR 하나가 된다. 절차의 정본은 위키 검증 문서의 재조사 절이고, 이 스킬은 그것을 실행 단계로 옮긴다. 용어는 `GLOSSARY.md`를 따른다.

먼저 읽는다: 이슈(`docs/agents/issue-tracker.md`의 이슈 읽기), `docs/wiki-verification.md`, `docs/source-hierarchy.md`, `docs/wiki-conventions.md`. 브랜치와 커밋은 `CONTRIBUTING.md`를 따르고, 타입은 `content`다.

`ASH_WIKI_NOTES`는 열지 않는다. 재조사는 이슈에 모인 주장과 출처, 게시된 페이지만 본다.

준비(`npm ci`, 에이전트의 작업 폴더, `npm run check` 결과 보기)는 [인제스트](../wiki-ingest/SKILL.md) 머리의 준비 문단을 따른다.

## 판정 라벨

재조사 에이전트의 반환과 이슈 본문의 항목 메모는 아래 여섯 라벨을 쓴다. 라벨은 위키 검증의 세 판정을 처리별로 나눈 것이고, 새 판정이 아니다.

| 라벨      | 언제                                                                                                                           | 판정                                                   | 처리                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 보류      | 검증 완료이나 대상 페이지가 위키 검증의 게시 기준에 못 미쳐 게시하지 않는다                                                    | 검증 완료                                              | 페이지를 만들지 않고 체크하지 않는다. 이어받는 길은 위키 검증의 게시 기준 절이다                  |
| 고쳐 씀   | 1층 출처가 주장을 뒷받침하거나, 다르게 말하고 출처 쪽이 분명하다                                                               | 검증 완료                                              | 출처대로 고친 주장을 게시한다                                                                     |
| 일부만    | 출처가 주장의 일부만 뒷받침한다                                                                                                | 뒷받침된 부분은 검증 완료, 남은 부분은 미검증이나 제외 | 뒷받침된 부분만 게시하고, 남은 부분을 메모에 적는다                                               |
| 좁혀 씀   | 표준 원문이 아닌 발행기관 하나의 자료만 뒷받침해, 그 범위로 좁혀 쓴다. 합의 문서는 위키 검증의 합의 문서 절이 좁혀 쓰는 문장만 | 검증 완료                                              | 좁혀 쓰기 꼴로 게시한다                                                                           |
| 이미 있음 | 주장이나 고친 주장 전체가 대상 페이지나 주인 페이지에 인용과 함께 이미 있다                                                    | 검증 완료                                              | 페이지 글을 고치지 않고 체크한다. 대상 페이지에 주인 페이지 링크가 없으면 한 문장과 링크만 더한다 |
| 미검증    | 다시 시도해도 뒷받침하는 1층 출처를 찾지 못했다                                                                                | 미검증                                                 | 사유와 시도한 출처를 메모에 적는다                                                                |

- 제외는 판정 이름을 그대로 라벨 자리에 쓴다. 반환의 `라벨`은 `제외`이고, 이슈 본문에는 취소선을 긋고 이유를 적는다.
- 한 항목에 라벨은 하나다. 둘 이상에 걸리면 `보류`, `일부만`, `이미 있음`, `좁혀 씀`, `고쳐 씀` 순으로 앞선 것을 고르고, 나머지 사정은 메모에 적는다. 예: 뒷받침된 부분이 이미 있고 남은 부분이 있으면 `일부만`이고, 메모에 이미 있는 페이지를 적는다.
- 일부는 이미 있고 나머지를 새로 게시하면 새로 게시한 부분의 라벨(`좁혀 씀`, `고쳐 씀`)을 쓰고, 메모에 이미 있는 부분을 적는다. `이미 있음`은 새로 게시하는 것이 없는 항목의 라벨이다.
- 검증 완료이나 같은 페이지의 기존 문장과 겹쳐 따로 쓰지 않은 항목도 `이미 있음`이고, 메모는 아래 꼴 블록대로 겹친 문장을 적는다. 고친 주장과 겹친 문장이 다르면 `겹친 문장:` 꼴이다. 다른 반영안과 겹친 항목은 3단계대로 한다.
- 주장을 출처대로 고쳐 판정한 `이미 있음`, `일부만` 항목은 메모의 라벨 뒤에 `(고쳐 씀)`을 붙이고, 메모의 주장은 고친 주장이다. 반환의 `라벨`은 그대로 하나다.
- `보류`는 5단계에서 메인 세션이 정한다. 에이전트는 다른 라벨로 판정하고, 대상 페이지가 없으면 메모에 적는다.
- `(게시됨)` 항목은 위키 검증의 정정 절대로 `고쳐 씀`, `제외`, `미검증` 가운데 하나다.

이슈 본문의 항목은 이 꼴로 적는다. 체크는 게시한 검증 완료, 취소선은 제외다.

```md
- [x] <슬러그>: <주장> — 고쳐 씀: <게시한 주장>
- [x] <슬러그>: <주장> — 고쳐 씀: <게시한 주장>. 이미 있는 부분: `<슬러그>`의 <주장>
- [x] <슬러그>: <주장> — 일부만: <게시한 주장>. 남은 부분: <뒷받침하지 못한 주장>
- [x] <슬러그>: <주장> — 좁혀 씀: <게시한 주장>
- [x] <슬러그>: <주장> — 이미 있음: `<슬러그>`의 <주장>
- [x] <슬러그>: <주장> — 이미 있음(고쳐 씀): `<슬러그>`의 <고친 주장>
- [x] <슬러그>: <주장> — 이미 있음(고쳐 씀): <고친 주장>. 겹친 문장: `<슬러그>`의 <주장>
- [ ] <슬러그>: <주장> — 보류: <이유>
- [ ] <슬러그>: <주장> — 미검증: `<사유>`. 시도한 출처: <URL>
- [ ] ~~<슬러그>: <주장>~~ — 제외: <이유>
```

## 1. 시작

1. `gh api repos/<owner>/<repo>/issues/<n> --jq .issue_dependencies_summary.blocked_by`가 0인지 본다. 아니면 열린 blocker를 `docs/agents/issue-tracker.md`의 Blocking 절대로 찾아 번호를 알리고 멈춘다.
2. 위키 검증 재조사 1단계대로 코멘트를 모아 이슈 본문을 `## <미검증 사유>` 절로 다시 쓴다.
   - `## Parent`와 `## What to build`는 남기고, What to build 끝에 "시도한 출처는 묶음 코멘트에 있다."를 더한다. 시도한 출처는 본문에 옮기지 않는다.
   - 항목이 없는 사유 절은 뺀다. 항목의 주장은 코멘트의 글 그대로 옮긴다.
3. 이슈가 열린 뒤 출처 위계가 넓어졌는지 `git log --since=<이슈 생성일> -- docs/source-hierarchy.md docs/adr/`로 본다. 1층을 더한 커밋만 세고, 문서를 옮기거나 문구만 고친 커밋은 세지 않는다. 넓어졌으면 위키 검증 재조사 절의 마지막 문단대로 모든 항목을 새 위계로 본다.

PR이 머지되기 전에 위계가 넓어지면 main으로 rebase하고, 남은 미검증 항목만 2단계부터 다시 돌린다.

완료: blocked-by가 0이고, 이슈 본문이 사유별 절로 다시 쓰였고, 위계를 넓힌 커밋이 있는지 확인했다.

## 2. 재조사 에이전트

사유 절마다 재조사 에이전트를 하나씩 Agent 도구(`general-purpose`)로 띄운다. 한 메시지에 모두 띄워 병렬로 돌린다. 프롬프트는 [reinvestigator.md](reinvestigator.md)를 채워 쓴다.

- 한 절의 항목이 15개를 넘으면 그 절은 페이지 단위로 나눈다.
- 항목이 적은 절끼리는 에이전트 하나에 합쳐도 된다.
- 에이전트 수가 Agent 도구의 동시 실행 한도(지금 20)를 넘으면 한도 안에서 나눠 띄운다.

에이전트에게는 맡은 항목 줄과 그 항목의 시도한 출처만 준다. `<작업 폴더>`는 `.work/` 아래 에이전트마다 다른 하위 폴더로 채운다. 1단계에서 위계를 넓힌 커밋을 찾았으면 더한 1층을 한 줄로 함께 준다.

완료: 에이전트마다 반환이 있다.

## 3. 반환 확인

에이전트마다 반환 JSON이 프롬프트의 계약을 지키는지 확인한다.

- 맡긴 항목마다 `라벨`과 `메모`가 있고, 라벨이 [판정 라벨](#판정-라벨) 표의 값이나 `제외`다.
- 라벨이 반영안·메모와 맞고 우선순위를 따른다. 남은 부분이 있으면 `일부만`, 발행기관·제품 이름으로 좁혔으면 `좁혀 씀`이다.
- `고쳐 씀`, `좁혀 씀`의 항목은 `반영안`이 있고, 문장마다 인용 키와 위치가 있다. `일부만`도 같고, 뒷받침된 부분이 이미 있으면 반영안이 비고 메모에 그 페이지가 있다.
- `grep`이 대상 페이지 밖까지 본 결과다.
- 반영안의 문장이 항목의 주장 범위 안이다. 항목에 없는 사실을 더한 문장은 빼고, 그것이 게시된 페이지의 틀린 곳이면 `범위 밖`으로 옮긴다.

빠진 것은 SendMessage로 그 에이전트에게 돌려보낸다.

에이전트끼리 같은 인용으로 같은 주장을 반영안으로 냈으면, 위키 규약의 중복 절대로 주인 페이지의 반영안 하나만 남긴다. 나머지 항목의 라벨은 `이미 있음`으로 바꾸고 메모에 그 주인 페이지를 적는다.

**이음매 읽기**: 인제스트 1단계의 이음매 읽기를 재조사의 단계에 맞춰 한다. 4단계 대조 전에, 메인 세션이 에이전트 없이 반영안마다 대상 페이지의 `자리`를 열어 반영안을 그 자리에 둔 것으로 앞뒤 문단과 함께 읽고, 연결, 자리, 되풀이를 반영안에서 고친다. 대조는 그렇게 고친 반영안으로 받는다. 4단계 뒤에 들어가는 `고쳐 쓸 문장`은 5단계에서 넣은 뒤에 읽고, 읽고 고친 것이 뜻(범위, 값, 조건, 주어)을 바꾸면 4단계 끝 문단대로 다시 대조받는다.

완료: 모든 항목이 계약을 지키고, 같은 주장의 반영안이 하나다. 반영안마다 이음매 읽기를 마쳤다.

## 4. 원문 재대조

반영안의 문장마다 인용 위치를 원문과 다시 대조한다. 표본이 아니라 반영하는 모든 문장이 대상이다. 대조는 반영안을 쓰지 않은 빈 컨텍스트의 에이전트가 한다.

반영안을 페이지별로 모아, 페이지마다 출처 경로 검증자를 하나씩 Agent 도구(`general-purpose`)로 띄운다. 같은 원문을 인용하는 페이지끼리나 반영안이 한두 문장인 페이지끼리는 검증자 하나에 묶어도 된다. 프롬프트는 인제스트의 [source-verifier.md](../wiki-ingest/source-verifier.md)를 그대로 쓴다. 지시 블록은 `<저장소 루트>`를 채우고 `<기준 커밋>`은 "없음"으로 두어 `.work/`의 브리프 파일에 `## 검증자 지시` 절로 두고, `## 현행판 표`와 `## 사본 목록` 절은 "없음"으로 둔다. 띄우는 프롬프트의 `<브리프 경로>`는 이 파일이고, `<슬러그>`는 맡긴 페이지(묶었으면 슬러그 목록)다.

- `## 초안` 절: 띄우는 프롬프트 끝에 더한다. 첫 줄에 "재조사 반영안이다. `(기존: …)`가 없는 문장은 새로 더하는 문장이다."를 두고, 그 페이지의 반영안 문장을 `[@<키>] (<위치>)`와 함께 넣고, 문장마다 다음 줄에 `항목의 주장: <이슈 본문 항목의 주장>`을 붙인다. 페이지를 묶었으면 페이지마다 슬러그를 제목으로 둔다. `(게시됨)` 항목의 문장에만 `(기존: <기존 문장> [@<키>])`를 붙인다.
- 인용 키와 출처: 반영안이 인용한 키마다 URL. 새 키는 반환의 `entries`에서 가져온다.
- `<작업 폴더>`: 2단계처럼 검증자마다 다른 하위 폴더.

검증자가 문장을 주장으로 쪼개 돌려주면, 쪼갠 주장이 모두 검증 완료일 때 그 문장이 검증 완료다. 사유가 위치를 고쳐 적었으면 반영안의 위치를 고치고, `고쳐 쓸 문장`은 인제스트 3단계대로 반영안에 넣는다. 검증 완료가 아닌 주장이 든 문장은 그 항목의 라벨을 다시 정한다. 문장을 출처대로 고쳐 다시 대조하거나, 그 부분을 남은 부분으로 돌려 `일부만`으로, 남는 것이 없으면 `미검증`으로 둔다. `항목 밖`이 `true`인 주장은 3단계의 범위 줄대로 반영안에서 빼고, 남은 주장이 모두 검증 완료면 다시 대조하지 않는다.

이 단계 뒤에 리뷰나 다듬기로 반영 문장의 뜻(범위, 값, 조건, 주어)이 바뀌면, 바뀐 문장을 이 단계대로 다시 대조받는다. 게시 문장이 바뀐 항목은 이슈 본문의 메모도 고친다.

완료: 반영하는 모든 문장이 대조를 거쳐 검증 완료다.

## 5. 반영

- 반영안을 페이지에 넣고 인용 위치를 뺀다. 인용 자리와 묶음은 위키 규약의 인용 절, 출처 표시와 그 출처 구간은 위키 검증의 좁혀 쓰기를 따른다. 4단계의 `고쳐 쓸 문장`으로 바뀐 문장은 넣은 뒤 3단계의 이음매 읽기를 한다.
- 새 엔트리는 위키 규약의 인용 절대로 `bib/`에 더한다.
- `verified`는 위키 규약의 페이지 타입과 프론트매터 절대로 둔다.
- 항목의 페이지가 없으면(게시 기준에 못 미쳐 만들지 않은 페이지) 위키 검증의 게시 기준을 넘을 때만 만들고, PR 본문에 적는다. 넘지 못하면 그 페이지의 검증 완료 항목은 라벨을 `보류`로 바꾸고 반영안을 넣지 않는다.
- 이슈 본문의 항목마다 [판정 라벨](#판정-라벨)의 꼴로 체크, 취소선, 메모를 단다.
- `범위 밖`은 모아 새 이슈로 낸다. 제목은 `CONTRIBUTING.md`의 이슈 절대로 `content: <주제>` 꼴이고, 라벨은 `needs-triage`다(`docs/agents/triage-labels.md`).

완료: 이슈 본문의 모든 항목에 라벨과 메모가 있고, `보류`가 아닌 검증 완료 항목의 반영안이 페이지에 있다.

## 6. 사후 점검

- 항목 대응: 체크한 항목마다 diff나 메모에 적은 기존 페이지에 그 주장이 있고, diff의 문장마다 체크한 항목이 있다.
- 새 bib 엔트리: 반영 뒤 `npm run source-status -- --url <URL> --url <URL> …`로 새 엔트리의 `url`을 모두 묻고 `url` 줄만 본다. `SKIP url-blocked`면 `docs/source-access.md`의 호스트별 여는 법대로 연다.
- 위키 검증 문서의 반영 뒤 점검.
- 형제 묶음 링크: 위키 검증 재조사 절의 3과 4. 묶음 티켓은 `gh api repos/<owner>/<repo>/issues/<verify 이슈>/dependencies/blocked_by --jq '.[].number'`로, 그 머지 커밋은 `gh pr list --state merged --json mergedAt,mergeCommit,closingIssuesReferences --jq '.[] | select(any(.closingIssuesReferences[]; .number == <티켓>)) | [.mergedAt, .mergeCommit.oid] | @tsv'`로 찾는다. 기준은 가장 먼저 머지된 PR의 머지 커밋의 부모(`<머지 커밋>^`)로, 묶음 PR의 diff를 모두 덮는다. 돌릴 명령은 `npm run check:diff -- --base <머지 커밋>^ --only first-link`와 묶음 티켓마다의 `npm run check:diff -- --base <머지 커밋>^ --ticket <묶음 티켓> --only owner-page`이고, 출력은 `.work/`에 받는다. 대상이 형제 묶음 페이지인 후보의 메모는 `.work/check-diff-memo.md`에 남긴다. `first-link` 후보는 건 링크나 걸지 않은 근거(규칙 절) 한 줄이고, `owner-page` 후보는 [인제스트](../wiki-ingest/SKILL.md) 4단계 반영 뒤 점검의 주인 페이지 판정과 메모 기준을 따른다. 링크를 걸어 문장이 바뀌면(링크 자리를 옮기거나 안내 문장을 지움) 3단계의 이음매 읽기를 한다.
- `CONTRIBUTING.md`의 PR 전 확인을 돌려 고친다.

완료: 위 점검이 모두 끝났고, 형제 묶음 후보마다 메모가 있고, PR 전 확인이 통과한다.

## 7. 독자 검토

그 절대로 독자 검토를 돌리고, 소유자의 답을 받아 반영한다.

완료: 이 PR이 그 절의 대상이 아니거나, 그 절의 승인과 반영 뒤 단계를 마쳤다.

## 8. PR과 마무리

게시한 검증 완료 항목도 6단계에서 건 형제 묶음 링크도 없으면 PR 없이 이슈를 닫는다(위키 검증 재조사 절의 5). `보류`는 검증 완료로 세지 않는다.

1. bib 엔트리를 더했으면 PR을 올리기 전에 위키 규약의 열린 PR과 겹치는 파일 절대로 열린 PR과 키가 겹치는지 본다.
2. 위키 검증 문서의 독자 검토 절과 `CONTRIBUTING.md`의 리뷰 절대로 두 축 리뷰를 돌려 반영한다.
3. PR을 올린다. 제목은 `content: <주제> 미검증 주장 재조사`, 본문은 `CONTRIBUTING.md`의 세 부분이고 `Closes #<verify 이슈>`를 적는다.
   - Changes: 라벨별 항목 수, `출처와 어긋남` 항목의 결과, 더한 bib 수, 건 형제 묶음 링크 수. 항목별 결과는 이슈 본문을 가리킨다.
   - Verification: 6단계의 점검과 결과(형제 묶음 링크는 후보 수와 건 수), 원문 재대조에서 고친 문장 수, "재조사는 이슈에 모인 주장과 출처만 보고 했고, 소스 노트는 읽지 않았다."
4. 리뷰 요약 코멘트를 단다(`CONTRIBUTING.md`의 리뷰 절). 소유자 리뷰를 반영하면 위키 검증 문서의 반영 뒤 점검을 다시 돌린다.

완료: PR과 리뷰 요약 코멘트가 있고, 이슈 본문의 모든 항목이 체크, 취소선, 미검증 메모, 보류 메모 가운데 하나다. 체크한 항목의 메모가 게시된 문장과 같다. `범위 밖`이 있었으면 새 이슈가 있다.
