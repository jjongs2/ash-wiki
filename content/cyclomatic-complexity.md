**순환 복잡도**(cyclomatic complexity)는 소프트웨어 모듈 하나에 든 결정 논리의 양을 재는 척도이고, 모듈의 [[basis-path-testing#제어 흐름 그래프|제어 흐름 그래프]] 구조만으로 정해진다.[@nist-sp-500-235-1996] McCabe는 1976년 ICSE(International Conference on Software Engineering) 논문에서 프로그램 복잡도를 관리하고 통제하려고 그래프 이론에 기반한 이 복잡도 척도를 제안했다.[@mccabe-complexity-measure-icse-1976]

## 정의

모듈은 입구와 출구가 하나씩인 함수나 서브루틴이고, C에서는 함수다. 제어 흐름 그래프의 간선의 수 $e$와 노드의 수 $n$으로 모듈의 순환 복잡도 $v(G)$를 다음과 같이 정의한다.[@nist-sp-500-235-1996]

$$
v(G) = e - n + 2
$$

그래프 이론의 순환수는 다음과 같다.[@nist-sp-500-235-1996]

$$
e - n + 1
$$

$v(G)$는 제어 흐름 그래프에 출구 노드에서 입구 노드로 가는 가상 간선을 하나 더한 그래프의 순환수다. 순환수 식에 이 가상 간선 몫 1을 더한 것이 위의 정의이므로, 정의의 $e$에는 가상 간선을 세지 않는다. 기호의 $v$는 순환수를, $G$는 값이 그래프의 함수라는 것을 나타낸다.[@nist-sp-500-235-1996]

## 세는 법

같은 값을 그래프를 그리지 않고 셀 수도 있다. 판정이 모두 두 갈래이고, 나가는 간선이 정확히 둘인 판정 노드가 $p$개면 $v(G) = p + 1$이다. 소스 코드에서 셀 때도 1에서 시작해 `if` 문이나 `while` 문 같은 두 갈래 판정마다 1을 더한다.[@nist-sp-500-235-1996]

흐름 그래프가 간선이 교차하지 않는 평면 그래프면, $v(G)$는 그래프가 평면을 나누는 영역의 수와 같다. 그래프 바깥의 무한 영역도 하나로 센다. 이는 오일러 공식에서 나온다.[@nist-sp-500-235-1996]

Boolean 연산자는 단락 평가를 하면 하나마다 1을 더하고(C의 `&&`, Ada의 `and then`), 완전 평가를 하면 더하지 않는다(Ada의 `and`). 단락 연산자를 그래프에서 감추고 세는 방식도 있지만, 이렇게 만든 그래프는 단락 식에 부작용이 없음을 확인하지 않는 한 테스트에 쓰지 않는다. 소스에서 셀 때는 언어 구문을 해석하는 방식을 일관되게 지킨다.[@nist-sp-500-235-1996]

## 독립 경로의 수

$v(G)$는 모듈을 지나는 [[basis-path-testing#기본 경로 집합|선형 독립 경로]]의 최대 개수다. 그래서 그래프의 경로를 모두 어떤 입력으로든 실행할 수 있으면, [[basis-path-testing|기본 경로 테스트]]가 테스트할 경로의 수는 $v(G)$다.[@nist-sp-500-235-1996]

## 모듈 여럿의 복잡도

모듈 여럿으로 된 설계에서 호출되는 모듈의 코드를 호출하는 모듈 안에 펼치지 않고 모듈마다 제어 흐름 그래프를 따로 두면, 설계 전체는 모듈의 그래프를 연결 요소로 갖는 그래프 하나가 된다. 연결 요소마다 가상 간선을 하나씩 더해야 하므로, 연결 요소가 $c$개인 이 그래프의 순환 복잡도는 가상 간선을 세지 않은 간선의 수 $e$와 노드의 수 $n$으로 다음과 같다.[@nbs-sp-500-99-1982]

$$
v(G) = e - n + 2c
$$

모듈이 하나면 $c = 1$이어서 위의 정의와 같다. 이 값은 모듈마다의 순환 복잡도를 더한 값과 같고, 모듈 하나의 순환 복잡도와 달리 상한을 두어 통제하지 않는다.[@nbs-sp-500-99-1982]

## 상한

McCabe가 처음 제안한 상한은 모듈마다 순환 복잡도 10이다. Watson과 McCabe는 NIST SP 500-235에서 상한 10을 뒷받침하는 근거가 많고, 15까지의 상한도 성공적으로 쓰였다고 보았다. 두 사람은 10을 넘는 상한을 숙련된 인력, 형식적 설계, 현대적 프로그래밍 언어, 구조적 프로그래밍, 코드 워크스루, 포괄적인 테스트 계획 같은 이점을 갖춘 프로젝트에만 쓰기를 권했다.[@nist-sp-500-235-1996]

Klocwork는 순환 복잡도 임곗값을 아래 네 범주로 둔다.[@perforce-klocwork-cyclomatic-complexity-2024]

| 순환 복잡도          | 리스크 평가                                  |
| -------------------- | -------------------------------------------- |
| $1 \le v(G) \le 10$  | 리스크가 크지 않은 단순한 모듈               |
| $11 \le v(G) \le 20$ | 리스크가 보통인 더 복잡한 모듈               |
| $21 \le v(G) \le 50$ | 리스크가 높은 복잡한 모듈                    |
| $v(G) \ge 51$        | 리스크가 매우 높은 테스트할 수 없는 프로그램 |
