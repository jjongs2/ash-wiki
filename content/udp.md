**UDP**(User Datagram Protocol)는 IP 위에서 응용 프로그램이 최소한의 프로토콜 절차로 메시지를 보내게 하는 프로토콜이다. RFC 768이 정하며, 전달과 중복 없음을 보장하지 않는다.[@ietf-rfc-768-1980] 전송 계층 프로토콜이다.[@ietf-rfc-1122-1989] UDP는 IP 헤더의 Protocol 값 17로 표시된다.[@ietf-rfc-768-1980][@iana-protocol-numbers-2026]

## 헤더

UDP 헤더는 8바이트로, 16비트 필드 넷으로 이루어진다.[@ietf-rfc-768-1980]

| 필드             | 뜻                                                      |
| ---------------- | ------------------------------------------------------- |
| Source Port      | 보내는 프로세스의 포트. 쓰지 않으면 0                   |
| Destination Port | 특정 목적지 IP 주소 안에서 뜻을 갖는 포트               |
| Length           | 헤더와 데이터를 합친 길이. 바이트 단위이고 최솟값은 8   |
| Checksum         | 의사 헤더, UDP 헤더, 데이터에 대한 [[checksum\|체크섬]] |

![[diagrams/udp-header-layout.svg]]

UDP가 IP 위에 더하는 서비스는 데이터 체크섬과 [[port-number|포트 번호]]에 따른 다중화뿐이다.[@ietf-rfc-1122-1989]

## 체크섬

RFC 768은 체크섬을 계산할 때 UDP 헤더 앞에 놓는 의사 헤더가 발신 주소, 목적 주소, 프로토콜, UDP 길이를 담도록 정한다. 이 정보는 잘못 배달된 데이터그램을 막는다. 계산한 체크섬이 0이면 1의 보수 산술에서 같은 값인 모두 1로 보낸다.[@ietf-rfc-768-1980]

[[ipv4|IPv4]]에서는 UDP 체크섬을 생략할 수 있으며, 이때 Checksum 필드는 0이다.[@ietf-rfc-768-1980][@ietf-rfc-1122-1989] 받은 Checksum 필드가 0이면 보낸 쪽이 체크섬을 만들지 않았다는 뜻이다.[@ietf-rfc-768-1980] [[ipv6|IPv6]]에서는 기본적으로 UDP 체크섬을 생략할 수 없고, 받는 쪽은 체크섬이 0인 UDP 패킷을 버린다. 다만 UDP를 터널 캡슐화에 쓰는 프로토콜은 특정 포트에 체크섬 0 모드를 쓸 수 있다.[@ietf-rfc-8200-2017]

체크섬이 0이 아니면서 틀린 데이터그램은 조용히 버린다.[@ietf-rfc-1122-1989]

## 비연결형 전송

UDP는 데이터그램 방식의 패킷 교환 통신을 제공하고, 전달과 중복 방지를 보장하지 않는다.[@ietf-rfc-768-1980] 재전송, 흐름 제어, 혼잡 회피 같은 기능이 필요하면 UDP 위의 응용이 맡는다. UDP는 [[tcp|TCP]]에 없는 멀티캐스트나 브로드캐스트 전달이 필요한 응용도 쓴다.[@ietf-rfc-1122-1989]

RFC 8095에 따르면 UDP는 [[osi-model#연결형과 비연결형|연결]]을 맺지 않고 데이터그램이라 부르는 독립된 메시지 단위로 보내며, 송신과 수신은 메시지 경계를 지킨다. 데이터그램은 순서가 바뀌거나 잃거나 중복되어 닿을 수 있다. 브로드캐스트 데이터그램은 IPv4에서, 멀티캐스트 데이터그램은 IPv4와 IPv6에서 보낼 수 있다.[@ietf-rfc-8095-2017]

[[some-ip-sd|SOME/IP-SD]] 메시지는 UDP로 보낸다.[@autosar-fo-prs-someipservicediscoveryprotocol-2025] [[autosar|AUTOSAR]]의 [[doip|DoIP]] 모듈은 차량 식별 요청을 UDP로 받는다.[@autosar-cp-sws-diagnosticoverip-2025]

## 메시지 크기

RFC 8085는 응용이 목적지까지 경로의 [[mtu|MTU]]를 넘는 IP 패킷이 되는 UDP 데이터그램을 보내지 않도록 권한다(SHOULD NOT). 그 까닭의 하나는 단편 하나만 잃어도 나머지 단편을 모두 제대로 받았더라도 원래 패킷을 재조립할 수 없어, 단편화된 패킷 전체를 잃는다는 것이다.[@ietf-rfc-8085-2017]

## TCP와의 차이

TCP는 연결을 맺고, 잃은 데이터를 다시 보내 순서대로 전달하며, 흐름 제어와 혼잡 제어를 한다.[@ietf-rfc-9293-2022] UDP 헤더는 8바이트이고[@ietf-rfc-768-1980], TCP [[tcp#헤더|헤더]]는 옵션이 없을 때 20바이트로 가장 짧다.[@ietf-rfc-9293-2022]
