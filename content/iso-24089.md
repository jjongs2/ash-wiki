**ISO 24089**는 도로 차량의 소프트웨어 업데이트 엔지니어링에 대한 요구사항과 권고를 정하는 국제 표준이다.[@iso-24089-obp-2023] 정식 제목은 "Road vehicles — Software update engineering"이고, ISO/TC 22/SC 32가 맡는다.[@iso-24089-2023]

이 표준은 다음을 다룬다.[@iso-24089-obp-2023]

- 조직 수준 프로세스의 구현
- 소프트웨어 업데이트 프로젝트마다의 프로젝트 수준 프로세스의 구현
- 이 표준의 활동과 프로세스를 지원하는 차량·인프라 기능의 정의
- 인프라 기능을 써서 소프트웨어 업데이트 패키지를 조립하는 일
- 차량과 인프라 기능을 써서 소프트웨어 업데이트 캠페인을 준비하고 실행하는 일[@iso-24089-obp-2023]

이 표준의 Introduction은 소프트웨어 업데이트 엔지니어링 활동이 차량의 생명주기 내내 일어난다고 제시하고, 소프트웨어 업데이트 캠페인이 잦아지면서 차량마다의 구성 정보를 갖추는 일이 중요하다고 본다.[@iso-24089-obp-2023]

## 범위

ISO 24089:2023은 도로 차량의 소프트웨어 업데이트 엔지니어링에 대해 조직 수준과 프로젝트 수준의 요구사항과 권고를 정한다. 이 요구사항과 권고는 차량, 차량 시스템, ECU, 인프라에 적용되고, 초기 개발 뒤 소프트웨어 업데이트 패키지를 조립하고 배포하는 일에도 적용된다. 소프트웨어를 업데이트할 수 있는 도로 차량과, 차량 제조사와 공급자처럼 소프트웨어 업데이트 엔지니어링에 관여하는 조직이 대상이다. 이 표준은 조직과 관계자 사이에서 활동과 책임을 소통하고 관리하기 위한 공통의 이해를 세운다. 소프트웨어 업데이트 엔지니어링을 뺀 차량 기능 소프트웨어의 개발은 범위 밖이고, 특정 기술이나 솔루션을 정하지 않는다.[@iso-24089-obp-2023]

이 표준은 [[iso-26262|ISO 26262-6]], ISO 26262-8, [[iso-sae-21434|ISO/SAE 21434]]를 인용 표준으로 둔다. 소프트웨어 업데이트 엔지니어링은 소프트웨어 업데이트 패키지를 계획하고 개발하고 배포하는 프로세스에 체계적이고 관리된 접근을 적용하는 일로 정의한다.[@iso-24089-obp-2023]

이 표준은 **소프트웨어 업데이트 패키지**(software update package)를, 하나 이상의 차량, 차량 시스템, ECU에 배포하려는 소프트웨어와 그에 딸린 메타데이터의 묶음으로 정의한다. **소프트웨어 업데이트 캠페인**(software update campaign)은 대상을 식별하고 수신자를 정하는 일, 패키지를 배포하는 일, 소프트웨어 업데이트 작업의 결과를 모니터링하고 기록하는 일로 이어지는 일련의 과정이다. 대상(target)은 차량 구성 정보로 정해지는 차량, 차량 시스템, ECU의 부류이고, 수신자(recipient)는 캠페인 중에 패키지를 받는 개별 차량, 차량 시스템, ECU다.[@iso-24089-obp-2023] 소프트웨어 업데이트 작업의 단계는 [[over-the-air-update#단계|OTA 업데이트의 단계]]에서 다룬다.

이 표준의 3절은 다음 용어도 정의한다.[@iso-24089-obp-2023]

| 용어                                                               | 정의                                                                                                                                                                                                                              |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 차량 시스템(vehicle system)                                        | 하나 이상의 ECU와 거기 붙은 하드웨어로 이루어진 기능 묶음. 주석은 붙은 하드웨어의 예로 ECU가 아닌 센서, 액추에이터, 조명을 들고, 정의에 딸린 예로 제동 시스템과 인포테인먼트 시스템을 든다.                                       |
| 차량 구성 정보(vehicle configuration information)                  | 차량에 있는 하드웨어 버전, 소프트웨어 버전, 설정 파라미터를 빠짐없이 밝힌 것.                                                                                                                                                     |
| 호환성(compatibility)                                              | 소프트웨어가 차량 시스템에서 충돌 없이 실행될 수 있는 능력. 주석은 호환성을 차량 구성 정보로 확인할 수 있다고 제시한다.                                                                                                           |
| 조건(condition)                                                    | 소프트웨어 업데이트 작업을 성공적으로 마치는 데 필요한 기준. 주석은 호환성, 안전한 차량 상태, 차량 내 자원, 외부 자원을 조건의 예로 들고, 정의에 딸린 예는 작업 중에 숙련자가 있는 것이다.                                        |
| 의존성(dependency)                                                 | 한 차량 시스템의 소프트웨어가 같은 차량 시스템이나 다른 차량 시스템에 주는 영향. 주석은 의존성이 소프트웨어 업데이트 패키지의 메타데이터에 조건을 만들 수 있다고 제시하고, 정의에 딸린 예로 두 ECU 사이의 통신 인터페이스를 든다. |
| 차량 내 자원(in-vehicle resource)                                  | 소프트웨어 업데이트 엔지니어링에 관련된, 차량이나 ECU의 쓸 수 있는 속성. 예로 쓸 수 있거나 남은 연산 능력, 네트워크 용량, RAM 용량, 저장 용량, 배터리 용량을 든다.                                                                |
| 인프라(infrastructure)                                             | 소프트웨어 업데이트 작업, 소프트웨어 업데이트 캠페인, 문서, 차량 구성 정보를 관리하는 프로세스와 정보 시스템으로, 디지털 활동과 수작업을 모두 포함한다. 주석은 인프라에 서버, 도구, 수작업이 들 수 있다고 제시한다.               |
| 숙련자(skilled person)                                             | 소프트웨어 업데이트 작업을 실행할 관련 기술 교육, 훈련이나 경험을 갖춘 사람. 주석은 정비소의 정비사를 숙련자의 예로 들고, 숙련자가 전문 훈련으로 인가나 인증을 받은 사람이거나 숙련된 차량 사용자일 수 있다고 제시한다.           |
| 소프트웨어 업데이트 프로젝트(software update project)              | 하나 이상의 대상에 대한 소프트웨어 업데이트 엔지니어링 활동의 집합. 주석은 프로젝트 하나가 소프트웨어 업데이트 캠페인 여럿을 아우를 수 있다고 제시한다.                                                                           |
| 소프트웨어 업데이트 배포 방법(software update distribution method) | 소프트웨어 업데이트 캠페인 중에 소프트웨어 업데이트 패키지를 전달하는 메커니즘. 주석은 유선(도구, USB 플래시 드라이브), 무선(셀룰러, Wi-Fi), 하드웨어 교체를 예로 든다.                                                           |

이 표준은 1절 범위, 2절 인용 표준, 3절 용어와 정의 다음에 아래 본문 절을 둔다. 4절부터 9절까지는 각각 목적, 일반, 요구사항과 권고, 작업 산출물의 하위 절을 둔다.[@iso-24089-obp-2023]

## UN R156과의 관계

R156 해석 문서는 ISO 24089:2023을 [[un-r156|UN R156]]의 [[software-update-management-system|SUMS]] 요구를 구현하는 데 도움이 되는 예시 표준으로 들고, R156의 문단과 ISO 24089:2023의 절을 표로 잇는다.[@unece-r156-interpretation-2025]
