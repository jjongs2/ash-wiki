**인터넷 프로토콜 스위트**(Internet protocol suite)는 호스트가 인터넷으로 통신하려면 구현해야 하는, 계층을 이룬 프로토콜의 모음이다.[@ietf-rfc-1122-1989] RFC 1180에 따르면 TCP/IP라는 말은 흔히 [[tcp|TCP]]와 IP(Internet Protocol) 두 프로토콜에 관련된 모든 것을 가리키며, [[udp|UDP]], [[arp|ARP]], [[icmp|ICMP]] 같은 다른 프로토콜도 포함할 수 있다.[@ietf-rfc-1180-1991] RFC 1122는 이 모음을 링크, 인터넷, 전송, 응용의 네 계층으로 나눈다.[@ietf-rfc-1122-1989]

## 네 계층

이 RFC가 나눈 네 계층은 아래와 같다.[@ietf-rfc-1122-1989]

- **링크 계층**: 호스트가 직접 연결된 네트워크와 통신하는 프로토콜이다. [[ethernet|이더넷]]이 한 예다.
- **인터넷 계층**: IP가 데이터그램, 곧 비연결형 서비스로 데이터를 발신 호스트에서 목적 호스트까지 나른다. 오류 보고 같은 제어를 맡는 ICMP와, IP 멀티캐스트용 동적 호스트 그룹을 만드는 IGMP(Internet Group Management Protocol)도 이 계층에 속한다.
- **전송 계층**: 응용에 끝과 끝 통신 서비스를 준다. 신뢰성 있는 연결형 서비스를 주는 TCP와, 비연결형 데이터그램 서비스를 주는 UDP가 있다.
- **응용 계층**: 사용자에게 직접 서비스를 주는 사용자 프로토콜(Telnet, FTP(File Transfer Protocol), SMTP(Simple Mail Transfer Protocol) 등)과, 호스트 이름 매핑·부팅·관리 같은 공통 시스템 기능을 주는 지원 프로토콜(DNS(Domain Name System), SNMP(Simple Network Management Protocol) 등)이 속한다.[@ietf-rfc-1122-1989]

![[diagrams/internet-protocol-suite-four-layers.svg]]

IP 주소는 [[ipv4|IPv4]]에서 32비트이고[@ietf-rfc-791-1981], [[ipv6|IPv6]]는 이를 128비트로 늘렸다.[@ietf-rfc-8200-2017] ARP는 IP 주소 같은 프로토콜 주소를 이더넷 주소 같은 링크 계층 주소로 바꾸며[@ietf-rfc-826-1982], RFC 1122는 ARP를 링크 계층 장에서 다룬다.[@ietf-rfc-1122-1989]

## 캡슐화

보내는 쪽에서는 각 계층이 위 계층에서 받은 데이터 앞에 자기 헤더를 붙여 아래 계층으로 넘긴다. TCP 세그먼트는 TCP [[tcp#헤더|헤더]]와 응용 데이터로, IP 데이터그램은 IP 헤더와 전송 계층 메시지로, 프레임은 링크 계층 헤더와 패킷으로 이루어진다.[@ietf-rfc-1122-1989] 받는 호스트에서는 링크 계층 인터페이스가 링크 계층 헤더를 떼어 내고 데이터그램을 IP 모듈에 넘기며, IP 모듈은 데이터를 응용 쪽으로 넘긴다.[@ietf-rfc-791-1981]

![[diagrams/internet-protocol-suite-encapsulation.svg]]

RFC 1122는 계층마다 데이터 단위의 이름을 둔다. **세그먼트**는 TCP의 끝과 끝 전송 단위이고, **메시지**는 전송 계층 프로토콜의 전송 단위로 TCP 세그먼트도 메시지다. **IP 데이터그램**은 IP의 끝과 끝 전송 단위이고, **프레임**은 링크 계층 프로토콜의 전송 단위다.[@ietf-rfc-1122-1989]

## 라우터와 라우팅 테이블

이 RFC는 네트워크를 서로 잇는 패킷 교환 컴퓨터를 게이트웨이 또는 IP 라우터라 부른다.[@ietf-rfc-1122-1989] RFC 1812는 이 장치를 라우터라 부르며, 예전 문서는 이를 게이트웨이라 불렀다.[@ietf-rfc-1812-1995] RFC 1122는 라우터가 연결 상태를 두지 않고 데이터그램을 하나씩 따로 넘겨 주며, 끝과 끝 흐름 제어와 신뢰성에 필요한 상태는 모두 호스트의 전송 계층이나 응용 프로그램에 둔다고 전제한다.[@ietf-rfc-1122-1989]

라우터는 받은 데이터그램의 목적 주소로 라우팅 테이블을 찾아 다음 홉과 내보낼 인터페이스를 정한다.[@ietf-rfc-1812-1995] 라우팅 테이블에서 목적 주소와 맞는 항목이 여럿이면 접두사가 가장 긴 항목을 고른다.[@ietf-rfc-1812-1995][@ietf-rfc-4632-2006]

RFC 1122는 호스트가 주소 마스크로 가려낸 목적 주소의 네트워크·서브넷 번호가 자기 주소의 것과 같으면 목적 호스트에 직접 보내고, 다르면 라우터를 거쳐 보내도록 정한다.[@ietf-rfc-1122-1989]

데이터그램이 라우터를 지날 때 라우터는 링크 계층 헤더를 떼어 내고, 다음 홉으로 보낼 새 링크 계층 프레임에 데이터그램을 다시 담는다.[@ietf-rfc-791-1981][@ietf-rfc-1812-1995] 소스 라우팅을 쓰지 않는 데이터그램에서 IP 헤더의 목적 주소는 최종 목적지의 주소다.[@ietf-rfc-1812-1995]

## OSI 참조 모델과의 차이

[[osi-model|OSI 참조 모델]]은 [[osi-model#일곱 계층|일곱 계층]]이다.[@itu-t-x-200-1994] RFC 1122는 인터넷 프로토콜 스위트의 응용 계층을 OSI 참조 모델의 맨 위 두 계층인 표현 계층과 응용 계층의 기능을 합친 계층으로 둔다.[@ietf-rfc-1122-1989]
