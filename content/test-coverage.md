**테스트 커버리지**(test coverage)는 테스트가 정해진 커버리지 항목을 얼마나 실행했는지를 백분율로 나타낸 정도다.[@istqb-glossary-coverage-2026][@ieee-cs-sevocab-2026] ISTQB(International Software Testing Qualifications Board) 용어집은 커버리지 항목을 테스트 기법으로 하나 이상의 테스트 조건에서 끌어낸 속성이나 속성의 조합으로 정의한다.[@istqb-glossary-coverage-item-2026] ISTQB CTFL(Certified Tester Foundation Level) 강의계획서에 따르면 달성한 커버리지는 테스트가 얼마나 철저한지 재는 척도이고, 테스트를 끝낼지 정하는 흔한 종료 기준 가운데 하나다.[@istqb-ctfl-syllabus-2024]

## 기법마다 다른 커버리지 항목

CTFL 강의계획서에 따르면 커버리지 항목은 테스트 기법마다 다르다. [[equivalence-partitioning|동치 분할]]은 분할을, [[boundary-value-analysis|경계값 분석]]은 경계값을, 구문 테스트는 구문을, 분기 테스트는 분기를 커버리지 항목으로 삼는다. 이 강의계획서가 다루는 [[black-box-testing|블랙박스]] 기법은 명세된 동작에서 고른 항목으로 커버리지를 재고, [[white-box-testing|화이트박스]] 기법인 구문 테스트와 분기 테스트는 코드의 구문과 분기로 커버리지를 잰다. 코드와 상관없는 커버리지를 쓰는 화이트박스 기법도 있다.[@istqb-ctfl-syllabus-2024]

이 강의계획서에 따르면 [[traceability|추적성]]은 커버리지 평가를 돕는다. 테스트 케이스와 요구사항 사이의 추적성으로 요구사항이 테스트 케이스로 다뤄졌는지 확인할 수 있다.[@istqb-ctfl-syllabus-2024]

ISTQB 용어집은 **구조적 커버리지**(structural coverage)를 구성 요소나 시스템의 내부 구조에 바탕을 둔 커버리지 척도로 정의한다.[@istqb-glossary-structural-coverage-2026]

## 조건과 결정

NASA가 펴낸 [[modified-condition-decision-coverage|MC/DC]] 튜토리얼에 따르면 구조적 커버리지 기준 몇 가지는 조건과 결정을 따로 다룬다. 이 튜토리얼에서 **조건**(condition)은 불 연산자를 담지 않은 불 식이다. **결정**(decision)은 조건과 0개 이상의 불 연산자로 이루어진 불 식이고, 불 연산자가 없는 결정은 조건이다. 결정은 `if` 같은 분기점과 같은 말이 아니어서, 분기점이 아닌 대입문에도 결정이 있다.[@nasa-tm-2001-210876-2001]

ISO/IEC/IEEE 24765 용어집은 결정 결과(decision outcome)를 실행할 분기를 정하는 결정의 결과로 정의한다.[@ieee-cs-sevocab-2026]

## 구조적 커버리지 기준

구조적 커버리지 기준마다 이루어야 하는 상태는 다음과 같다. 조건/결정 커버리지는 NASA의 MC/DC 튜토리얼이 정의한 대로 적는다.

| 기준                                                     | 이루어야 하는 상태                                                                                                                 |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 구문 커버리지(statement coverage)                        | 실행 가능한 구문이 모두 적어도 한 번 실행되었다.[@istqb-ctfl-syllabus-2024][@nasa-tm-2001-210876-2001]                             |
| 결정 커버리지(decision coverage)                         | 각 결정이 가능한 모든 결과를 적어도 한 번씩 가졌다.[@nasa-tm-2001-210876-2001][@istqb-glossary-decision-coverage-2026]             |
| 조건 커버리지(condition coverage)                        | 각 결정 안의 각 조건이 가능한 모든 값을 적어도 한 번씩 가졌다.[@nasa-tm-2001-210876-2001][@istqb-glossary-condition-coverage-2026] |
| 조건/결정 커버리지(condition/decision coverage)          | 결정 커버리지와 조건 커버리지의 요구를 모두 이루었다.[@nasa-tm-2001-210876-2001]                                                   |
| MC/DC                                                    | 조건/결정 커버리지에 더해, 각 조건이 결정의 결과에 독립적으로 영향을 준다는 것을 보였다.[@nasa-tm-2001-210876-2001]                |
| 다중 조건 커버리지(multiple condition coverage)          | 각 결정 안 조건 값의 모든 조합이 실행되었다.[@nasa-tm-2001-210876-2001][@istqb-glossary-multiple-condition-coverage-2026]          |

## 포함 관계

CTFL 강의계획서는 어떤 커버리지를 100% 이룬 테스트 케이스 집합이 언제나 다른 커버리지도 100% 이루는 관계를 포함한다(subsume)고 부른다. 이 강의계획서에 따르면 분기 커버리지는 구문 커버리지를 포함한다. 분기 커버리지 100%를 이룬 테스트 케이스 집합은 구문 커버리지도 100% 이루지만, 그 역은 성립하지 않는다.[@istqb-ctfl-syllabus-2024]

MC/DC는 조건/결정 커버리지의 요구를 모두 담으므로 조건/결정 커버리지를 포함한다. 다중 조건 커버리지는 결정 입력의 모든 조합을 실행하므로 대개 각 조건의 독립적인 영향도 보이게 된다. 그러나 이를 명시적으로 요구하지는 않고, 어떤 조건도 독립적인 영향을 가질 수 없는 논리식도 있다.[@nasa-tm-2001-210876-2001]

NASA의 MC/DC 튜토리얼에 따르면 조건/결정 커버리지는 결정 커버리지와 조건 커버리지의 요구를 모두 담지만, 결정 커버리지와 조건 커버리지는 어느 쪽도 다른 쪽의 요구를 담지 않는다. 결정 커버리지는 각 조건이 모든 값을 가질 것을 요구하지 않는다. 예를 들어 `A or B`에 (참, 거짓)과 (거짓, 거짓)을 주면 결정은 참과 거짓을 모두 가지지만, B의 영향은 시험되지 않는다. 조건 커버리지는 결정이 모든 결과를 가질 것을 요구하지 않는다. `A or B`에 (참, 거짓)과 (거짓, 참)을 주면 조건 커버리지는 이루지만, 결정은 두 번 모두 참이다.[@nasa-tm-2001-210876-2001]

## 결정 커버리지와 분기 커버리지

ISTQB 용어집은 결정 커버리지를 결정 결과의 커버리지로, **분기 커버리지**(branch coverage)를 제어 흐름 그래프의 분기의 커버리지로 따로 정의한다.[@istqb-glossary-decision-coverage-2026][@istqb-glossary-branch-coverage-2026]

## ISO 26262-6

ISO 26262-6:2018은 소프트웨어 유닛 검증을 9절에, 소프트웨어 통합과 검증을 10절에 둔다. 소프트웨어 유닛 수준의 구조적 커버리지 척도는 표 9에서, 소프트웨어 아키텍처 수준의 구조적 커버리지는 표 12에서 다룬다.[@iso-26262-6-obp-2018]
