**오류 추정**(error guessing)은 ISTQB CTFL v4.0.1 강의계획서가 [[exploratory-testing|탐색적 테스트]], [[checklist-based-testing|체크리스트 기반 테스트]]와 함께 [[software-testing#테스트 기법의 분류|경험 기반 테스트 기법]]으로 분류하는 기법이다. 오류 추정은 테스터의 지식으로 [[fault-error-failure|실수, 결함, 장애]](failure)가 일어날 것을 예상하는 기법이다.[@istqb-ctfl-syllabus-2024] 오류 추정에서는 테스터가 과거의 failure나 failure mode에 대해 아는 것을 바탕으로 [[test-case#테스트 조건|테스트 조건]]을 정한다.[@istqb-glossary-error-guessing-2026]

테스트 기법은 [[black-box-testing|블랙박스]], [[white-box-testing|화이트박스]], 경험 기반의 세 갈래로 나뉜다.[@istqb-ctfl-syllabus-2024]

## 근거가 되는 지식

오류 추정이 기대는 테스터의 지식은 다음과 같다.[@istqb-ctfl-syllabus-2024]

- 애플리케이션이 과거에 어떻게 동작했는지
- 개발자가 흔히 저지르는 실수의 종류와, 그 실수에서 생기는 결함의 종류
- 다른 비슷한 애플리케이션에서 일어난 failure의 종류[@istqb-ctfl-syllabus-2024]

실수, 결함, 장애는 대체로 다음 범주와 관련된다.[@istqb-ctfl-syllabus-2024]

| 범주       | 예                                                |
| ---------- | ------------------------------------------------- |
| 입력       | 올바른 입력을 받지 않음, 매개변수가 틀리거나 빠짐 |
| 출력       | 형식이나 결과가 틀림                              |
| 논리       | 빠진 경우, 틀린 연산자                            |
| 계산       | 틀린 피연산자나 계산                              |
| 인터페이스 | 매개변수의 불일치, 호환되지 않는 타입             |
| 데이터     | 초기화가 틀림, 틀린 타입                          |

## 결함 공격

**결함 공격**(fault attack)은 오류 추정을 실행하는 한 방법이다. 테스터는 일어날 수 있는 실수, 결함, 장애의 목록을 만들거나 구하고, 실수와 관련된 결함을 찾거나 결함을 드러내거나 장애를 일으키는 테스트를 설계한다. 목록은 경험, 결함과 장애의 데이터, 소프트웨어가 왜 실패하는지에 대한 일반 지식으로 만든다.[@istqb-ctfl-syllabus-2024]

## 다른 기법을 보완하는 자리

ISTQB CTFL v4.0.1 강의계획서에 따르면 경험 기반 기법은 블랙박스 기법과 화이트박스 기법이 놓칠 수 있는 결함을 찾을 수 있어서 그 기법들을 보완한다. 이 강의계획서에 따르면 경험 기반 기법의 효과는 테스터의 기량에 크게 달려 있다.[@istqb-ctfl-syllabus-2024]
