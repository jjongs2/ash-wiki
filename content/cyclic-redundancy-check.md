**CRC**(Cyclic Redundancy Check)는 순환 부호를 쓰는 오류 제어 방법으로, 주로 오류 검출에 쓴다. 보호할 데이터 블록의 비트를 다항식의 계수로 보고 정해진 생성 다항식으로 모듈로 2 나눗셈을 해, 그 나머지를 블록 검사 시퀀스로 데이터 블록에 붙인다.[@iec-60050-723-10-100-1997] 이 나머지 값도 CRC라 부른다.[@microchip-an730-2000][@autosar-cp-sws-crclibrary-2025]

CRC는 전송하거나 저장하는 데이터의 오류를 찾아내는 간단한 방법이다.[@microchip-an730-2000][@ti-spra530-1999]

## 다항식 나눗셈

IEC 60050-721은 **순환 부호**를 부호어를 순환 이동한 것도 늘 부호어인 부호로 정의한다.[@iec-60050-721-08-31-1991] TI 앱노트 SPRA530에 따르면 순환 부호는 선형 블록 부호의 한 갈래로, 부호화를 선형 피드백 시프트 레지스터로 구현할 수 있다. 부호어의 길이가 $n$비트이면 생성 다항식을 $x^n + 1$의 약수로 골라, 부호어를 순환 이동해도 부호어가 되게 한다.[@ti-spra530-1999]

CRC의 나눗셈은 모듈로 2 산술로 하며, 모듈로 2 덧셈과 뺄셈은 XOR다.[@microchip-an730-2000][@ti-spra530-1999]

생성 다항식의 차수가 $r$이면 송신 측은 데이터 뒤에 0을 $r$개 붙인 비트열을 생성 다항식으로 나누고, 나머지 $r$비트를 데이터 뒤에 붙여 보낸다. 이렇게 만든 비트열은 생성 다항식으로 나누어떨어진다.[@autosar-cp-sws-crclibrary-2025][@ti-spra530-1999]

수신 측은 받은 비트열 전체를 생성 다항식으로 나누어, 나머지가 0이 아니면 오류로 판정한다.[@microchip-an730-2000][@ti-spra530-1999] 받은 데이터로 CRC를 다시 계산해 받은 CRC와 비교하고, 다르면 오류로 판정하기도 한다.[@bosch-can-2-0-1991][@microchip-enc28j60-2012]

ENC28J60은 독립형 [[ethernet|이더넷]] 컨트롤러로, `ERXFCON.CRCEN`이 설정되어 있으면 CRC가 틀린 패킷을 버린다.[@microchip-enc28j60-2012] [[automatic-repeat-request|ARQ]]는 오류 검출 부호로 찾은 오류를 되돌림 통로로 알려, 송신 측이 다시 보내게 한다.[@iec-60050-721-08-21-1991]

[[autosar|AUTOSAR]] R25-11 CRC 라이브러리 규격은 32비트 다항식 `0xF4ACFB13`의 [[hamming-distance|해밍 거리]]를 CRC를 포함해 4096바이트까지 6으로 제시한다.[@autosar-cp-sws-crclibrary-2025]

생성 다항식이 추가로 대수적 성질을 가지면 오류 위치를 찾아 부호어를 고칠 수도 있다.[@autosar-cp-sws-crclibrary-2025]

## 하드웨어 구현

하드웨어에서는 CRC를 시프트 레지스터와 XOR로 계산한다. 시프트 레지스터의 비트 수는 생성 다항식의 차수와 같고, 데이터를 한 비트씩 밀어 넣으면서 생성 다항식의 계수가 1인 자리에서 XOR를 한다. 데이터를 모두 넣은 뒤 레지스터에 남은 값이 CRC다.[@microchip-an730-2000][@ti-spra530-1999] 아래 그림은 [[can|CAN]]이 쓰는 생성 다항식으로 그린 예다.

## 쓰는 곳

CRC는 이더넷 같은 LAN에서 쓰인다.[@microchip-an730-2000][@ti-spra530-1999] Microchip 앱노트에 따르면 CRC는 데이터 메모리·프로그램 메모리에 든 데이터가 올바른지 확인하는 데도 흔히 쓰이고[@microchip-an2632-2019], CAN과 이더넷을 비롯한 널리 쓰이는 통신 프로토콜 대부분이 CRC로 오류를 검출한다.[@microchip-an1148-2008]

CRC는 이웃한 비트들에 몰린 오류인 버스트 오류를 찾아내는 데 쓴다.[@microchip-an730-2000][@ti-spra530-1999] IEC 60050-721은 **오류 버스트**를 잇단 두 오류 자리 사이의 올바른 자리 수가 늘 정한 수보다 적은 자리 묶음으로 정의한다. 한 버스트의 마지막 오류 자리와 다음 버스트의 첫 오류 자리 사이에는 올바른 자리가 적어도 그 수만큼 있다.[@iec-60050-721-08-09-1991] 오류 버스트의 길이는 첫 오류 비트부터 마지막 오류 비트까지의 비트 수다.[@iec-60050-721-08-10-1991] ITU-T X.141에 따르면 X.25 등의 패킷 전송 절차가 쓰는 16비트 FCS(Frame Check Sequence)는 길이가 16비트를 넘지 않는 오류 버스트를 모두 찾아낸다.[@itu-t-x-141-1988]

![[diagrams/error-burst-definition.svg]]

소프트웨어 알고리즘은 데이터를 나눠 처리하므로 데이터에 경계가 생긴다. CRC를 직렬 전송에 쓸 때 데이터 비트를 선로로 보내는 순서와 다르게 처리하면, 이 경계에 걸친 버스트 오류는 길이가 FCS 길이여도 CRC 계산에서는 FCS 길이보다 멀리 떨어진 비트에 걸친 오류가 되어 검출되지 않을 수 있다. 이 비트 순서 문제는 버스트 오류 검출 성질만 해치고, 무작위 독립 비트 오류에 대한 보호에는 영향이 없다.[@ray-high-hamming-distance-2006]

Bosch CAN 2.0 규격은 CAN의 CRC 시퀀스를 15비트로 둔다.[@bosch-can-2-0-1991] 자세한 것은 [[can-crc|CAN CRC]]에서 다룬다.

모뎀의 오류 정정 절차를 정한 ITU-T V.42(03/2002)는 LAPM(Link Access Procedure for Modems)의 32비트 FCS 생성 다항식을 차수가 32, 26, 23, 22, 16, 12, 11, 10, 8, 7, 5, 4, 2, 1, 0인 항으로 정한다.[@itu-t-v-42-2002]

$$
x^{32} + x^{26} + x^{23} + x^{22} + x^{16} + x^{12} + x^{11} + x^{10} + x^{8} + x^{7} + x^{5} + x^{4} + x^{2} + x + 1
$$

[[ieee-802-3|IEEE 802.3-2022]]는 이더넷 MAC(Medium Access Control) 프레임의 FCS 필드에 32비트 CRC 값을 담도록 하고, 그 생성 다항식을 위와 같은 다항식으로 정한다. CRC 값은 목적지 주소, 출발지 주소, 길이/타입 필드, MAC 클라이언트 데이터, 패드로, 곧 FCS를 뺀 모든 필드로 계산한다.[@ieee-802-3-2022]

생성 다항식이 같아도 보장되는 해밍 거리는 CRC를 뺀 데이터 워드의 길이에 따라 달라서, 데이터 워드가 길수록 작아진다. 데이터 워드를 $k$비트라 하면, 위 다항식이 보장하는 해밍 거리는 $k \le 91$이면 8 이상, $k \le 171$이면 7 이상, $k \le 268$이면 6 이상, $k \le 2974$이면 5 이상, $k \le 91607$이면 4 이상이다.[@koopman-32-bit-crc-2002]

## 계산 매개변수

AUTOSAR R25-11의 CRC 라이브러리 규격은 CRC 알고리즘을 결과의 폭, 생성 다항식, 초기값, 입력 바이트의 비트를 반사하는지, 결과의 비트를 반사하는지, 마지막 레지스터 값에 XOR하는 값(XOR 값)으로 나타낸다. **반사**는 비트를 거꾸로 된 순서로 다시 쓰는 것이다. 구현이 맞는지 가늠하는 **check 값**은 문자 `123456789`의 바이트 `31 32 33 34 35 36 37 38 39`를 그 알고리즘에 넣어 얻은 CRC다. CRC를 검사할 때는 CRC 결과까지 포함한 데이터 블록 전체로 CRC를 계산하는데, 오류 없는 블록이면 데이터 내용과 상관없이 늘 같은 결과가 나온다. 이 결과에 XOR 값을 XOR한 상수를 **magic check**라 한다.[@autosar-cp-sws-crclibrary-2025]

이 규격은 아래 CRC 루틴을 정한다. 다항식은 최고차 비트를 뺀 normal representation으로 적고, 표기법으로는 이 밖에 최고차 비트를 넣은 꼴과 reversed reciprocal(Koopman 표기)도 든다.[@autosar-cp-sws-crclibrary-2025]

| 함수                    | 기반        | 다항식               | 초기값               | 입력·결과 반사 | XOR 값               |
| ----------------------- | ----------- | -------------------- | -------------------- | -------------- | -------------------- |
| `Crc_CalculateCRC8`     | SAE J1850   | `0x1D`               | `0xFF`               | 없음           | `0xFF`               |
| `Crc_CalculateCRC8H2F`  | —           | `0x2F`               | `0xFF`               | 없음           | `0xFF`               |
| `Crc_CalculateCRC16`    | CCITT-FALSE | `0x1021`             | `0xFFFF`             | 없음           | `0x0000`             |
| `Crc_CalculateCRC16ARC` | —           | `0x8005`             | `0x0000`             | 있음           | `0x0000`             |
| `Crc_CalculateCRC32`    | IEEE 802.3  | `0x04C11DB7`         | `0xFFFFFFFF`         | 있음           | `0xFFFFFFFF`         |
| `Crc_CalculateCRC32P4`  | —           | `0xF4ACFB13`         | `0xFFFFFFFF`         | 있음           | `0xFFFFFFFF`         |
| `Crc_CalculateCRC64`    | ECMA        | `0x42F0E1EBA9EA3693` | `0xFFFFFFFFFFFFFFFF` | 있음           | `0xFFFFFFFFFFFFFFFF` |

이 릴리스는 [[j1939|SAE J1939-76]] 기반 32비트 CRC 루틴 `Crc_CalculateCRC32P76`(다항식 `0x6938392D`, 초기값 `0xFFFFFFFF`, 입력·결과 반사 없음, XOR 값 `0x00000000`)도 두지만, 그 요구사항은 초안(draft) 상태다.[@autosar-cp-sws-crclibrary-2025]

초기값, XOR 값, 비트 반사 같은 계산 방식의 변형은 계산 성능을 높이려고 나온 것으로, 부호의 해밍 거리, 곧 오류를 검출하거나 고치는 능력을 높이지 않는다. 해밍 거리는 생성 다항식만으로 정해지고, 이런 변형은 구현하는 연산 장치에 맞춘 최적화일 뿐이다.[@autosar-cp-sws-crclibrary-2025]

ITU-T V.42(03/2002)는 LAPM의 16비트 FCS 생성 다항식을 차수가 16, 12, 5, 0인 항으로 정한다. 이 권고는 전형적인 구현으로, 송신 측이 나머지를 구하는 레지스터를 모두 1로 두고 시작해 얻은 나머지의 1의 보수를 FCS로 보내고, 수신 측도 레지스터를 모두 1로 두고 시작해 전송 오류가 없으면 최종 나머지가 `0001 1101 0000 1111`이 되는 방식을 제시한다.[@itu-t-v-42-2002]

Microchip 앱노트 AN1148에 따르면 CRC 계산은 그대로는 데이터 앞에 붙는 0에 대한 확실한 대책이 없다. 그래서 CRC를 먼저 특정 값으로 초기화하고, 계산한 CRC를 보수로 바꿔 메시지에 붙여 보낸다. 이렇게 하면 앞에 붙는 0 때문에 생기는 오류를 피할 수 있다.[@microchip-an1148-2008]
