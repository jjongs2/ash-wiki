**페어와이즈 테스트**(pairwise testing)는 두 매개변수 값의 가능한 모든 쌍을 적어도 한 [[test-case|테스트 케이스]]가 덮게 하는 [[black-box-testing|블랙박스]] 기법이다.[@istqb-glossary-pairwise-testing-2026][@nist-sp-800-142-2010] NIST SP 800-142에 따르면 페어와이즈 테스트는 두 매개변수의 조합(2-way 조합)을 덮는 조합 테스트이고, 조합 테스트에서 흔히 쓰는 방식으로 자리 잡았다.[@nist-sp-800-142-2010]

## 조합 테스트

**조합 테스트**(combinatorial testing)는 여러 매개변수 값의 특정 조합을 테스트 조건으로 삼는 블랙박스 기법이다.[@istqb-glossary-combinatorial-testing-2026]

[[iso-iec-ieee-29119|ISO/IEC/IEEE 29119]]-4:2021은 **조합 테스트 설계 기법**(combinatorial test design techniques)을 매개변수-값 쌍의 조합을 실행하는 데 바탕을 둔 명세 기반 테스트 케이스 설계 기법의 갈래로 정의하고, all combinations 테스트, 페어와이즈 테스트, each choice 테스트, base choice 테스트를 예로 든다. 이 표준은 **매개변수-값 쌍**(parameter-value pair)을 테스트 대상의 매개변수와 그 매개변수에 준 값의 조합으로 정의하고, 조합 테스트 설계 기법의 커버리지 항목으로 둔다. **base choice**(base value)는 base choice 테스트에 쓰는 입력 매개변수 값으로, 보통 그 매개변수의 대표값이나 전형값으로 고른다.[@iso-iec-ieee-29119-4-obp-2021]

이 표준은 **분류 트리**(classification tree)를 프로그램의 입력 데이터를 나타낸 계층형 트리 모델로 정의한다. 분류 트리에서 입력은 서로 구별되는 분류(관련된 테스트 측면)와 클래스(입력값)로 나타난다. **분류 트리 기법**(classification tree method)은 분류 트리의 클래스를 실행하는 데 바탕을 둔 명세 기반 테스트 케이스 설계 기법이다.[@iso-iec-ieee-29119-4-obp-2021]

특정한 매개변수 값의 조합에서 일어나는 failure를 **interaction failure**라 하고, 조합 테스트는 매개변수 값의 조합을 탐색해 이런 failure를 드러내려 한다. 조합 테스트의 테스트 조건은 대개 설정 매개변수나 입력 데이터 값을 조합하므로, 접근은 크게 둘이다. 첫째는 설정 매개변수의 조합을 쓰는 것으로, 조합마다 같은 테스트 케이스로 테스트할 수 있다. 둘째는 입력 데이터 값의 조합을 쓰는 것으로, 조합이 완전한 테스트 케이스의 일부가 되어 테스트 대상 시스템의 테스트 스위트를 이룬다.[@istqb-ctal-ta-syllabus-2025]

ISTQB CTAL-TA(Certified Tester Advanced Level Test Analyst) v4.0 강의계획서는 조합 커버리지 기준으로 다음 둘을 든다.[@istqb-ctal-ta-syllabus-2025]

- **base choice 커버리지**: 어떤 매개변수-값 쌍이 다른 쌍보다 중요하다고 가정한다. 매개변수마다 기준 매개변수-값 쌍을 하나 고르고, 기준 쌍들의 조합을 기준 커버리지 항목으로 삼는다. 나머지 커버리지 항목은 기준 커버리지 항목에서 매개변수 하나의 기준 쌍을 기준이 아닌 값 하나하나로 바꿔 만들고, 이를 매개변수마다 한다.
- **페어와이즈 커버리지**: 커버리지 항목은 임의의 두 매개변수에 대한 매개변수-값 쌍의 쌍이다. 커버리지 항목을 만드는 도구가 있지만, 페어와이즈 커버리지를 이루는 최소의 테스트 케이스 집합을 찾는 일은 대개 어렵다.[@istqb-ctal-ta-syllabus-2025]

![[diagrams/base-choice-coverage-items.svg]]

값이 많은 매개변수에는 먼저 [[equivalence-partitioning|동치 분할]]을 적용해 값과 그 조합의 수를 줄일 수 있다. 매개변수와 그 값을 분류 트리나 feature model로 정리하면 이 일에 도움이 된다. 최종 테스트 케이스 수는 매개변수-값 쌍 사이의 제약, 문제가 있다고 알려져 손으로 더한 조합, 무효하거나 실행할 수 없는 조합에 따라 달라질 수 있다.[@istqb-ctal-ta-syllabus-2025]

NIST SP 800-142에 따르면 매개변수 $t$개의 값 조합을 모두 덮는 테스트를 $t$-way 조합 테스트라 하고, $t$를 강도(strength)라고도 부른다. 페어와이즈 테스트는 $t = 2$인 경우다.[@nist-sp-800-142-2010]

소프트웨어 failure는 대부분 매개변수 하나의 값이나 두 매개변수의 상호작용으로 일어나고, 얽힌 매개변수가 많을수록 그런 failure는 드물어진다. NIST와 다른 연구자가 조사한 분야에서는 모든 failure가 많아야 매개변수 4개에서 6개의 상호작용으로 일어났고, 이 관찰이 조합 테스트의 근거다.[@nist-sp-800-142-2010]

## 케이스 수

값이 10개씩인 입력 $n$개를 모두 조합해 테스트하려면 입력 $10^n$개가 필요하다. 이 문서의 예에서 값이 둘인 매개변수 10개의 모든 조합은 $2^{10} = 1024$개지만, 그 3-way 조합은 모두 13개 케이스로 덮인다. 같은 매개변수 10개의 모든 쌍은 NIST의 ACTS(Automated Combinatorial Testing for Software)로 만든 커버링 배열이 10개 케이스로 덮었다. 값이 각각 3, 2, 2, 2, 3가지인 매개변수 5개의 구성 72가지는 10개 케이스로 모든 쌍을 덮는다.[@nist-sp-800-142-2010]

매개변수 $n$개가 각각 값 $v$개를 가질 때, $t$-way 조합을 모두 덮는 케이스 수는 $v^t \log n$에 비례한다. 그래서 케이스 수는 매개변수 수의 로그로만 늘어난다.[@nist-sp-800-142-2010]

## 직교 배열과 커버링 배열

조합 테스트의 핵심 요소는 모든 $t$-way 조합을 담은 커버링 배열이다. 커버링 배열에서 행 하나는 테스트 하나, 열 하나는 매개변수 하나다.[@nist-sp-800-142-2010]

두 배열의 정의는 다음과 같다.[@nist-sp-800-142-2010]

- **직교 배열**(orthogonal array): 어느 $t$개 열을 골라도 값의 모든 $t$-튜플이 정확히 같은 횟수씩 나오는 배열이다.
- **커버링 배열**(covering array): 어느 $t$개 열을 골라도 값의 모든 $t$-튜플이 적어도 정해진 횟수만큼 나오는 배열이다. [[software-testing|소프트웨어 테스트]]에서는 그 횟수를 1로 둔다.[@nist-sp-800-142-2010]

커버링 배열은 조합마다 같은 횟수씩 나와야 한다는 제약을 풀어서, 테스트가 겹칠 수는 있지만 직교 배열로는 다룰 수 없는 훨씬 큰 문제에도 계산할 수 있다.[@nist-sp-800-142-2010]

Kuhn, Kacker, Lei는 백과사전 항목에서, 값이 둘인 매개변수 4개와 셋인 매개변수 1개의 모든 쌍을 직교 배열을 고쳐 만든 배열로는 8행으로, 커버링 배열로는 6행으로 덮는 예를 들었다.[@kuhn-combinatorial-testing-2012]

## 도구

NIST SP 800-142에 따르면 모든 $t$-way 조합을 덮는 테스트 집합을 효율적으로 만드는 일은 어려운 수학 문제여서, 테스트 데이터 생성 도구로 정한 강도까지의 조합을 덮는다. NIST의 ACTS가 그런 도구다.[@nist-sp-800-142-2010] Microsoft의 PICT(Pairwise Independent Combinatorial Testing)도 테스트 케이스를 생성하는 도구다.[@microsoft-pict-2026]
