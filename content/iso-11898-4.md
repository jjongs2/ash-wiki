**ISO 11898-4**는 [[can|CAN]]의 시간 트리거 통신을 규정하는 국제 표준이다. 정식 제목은 "Road vehicles — Controller area network (CAN) — Part 4: Time-triggered communication"이고, ISO/TC 22/SC 31이 맡는다.[@iso-11898-4-2004]

## 범위

ISO 11898-4:2004는 CAN을 갖춘 도로 차량의 ECU 사이에서 디지털 정보를 시간 트리거 방식으로 주고받는 통신을 정한다. 이를 위해 [[iso-11898-1|ISO 11898-1]]을 따르는 LLC(Logical Link Control)와 MAC(Medium Access Control)의 동작을 조율해 시간 트리거 통신 일정을 만드는 FSE(Frame Synchronisation Entity)를 규정한다.[@iso-11898-4-obp-2004]

이 표준은 시간 트리거 CAN(time-triggered CAN)을 CAN 프로토콜에 더한 상위 프로토콜 계층으로 두고, CAN 프로토콜 자체는 바꾸지 않는다. 시간 트리거 통신은 메시지마다 지연 시간을 버스 부하와 상관없이 정해진 값으로 유지한다. 구현 수준은 둘이고, Level 1은 주기적 메시지 전송만 하고 Level 2는 여기에 전역 시스템 시간을 더한다.[@iso-11898-4-obp-2004]

시간 트리거 CAN의 주기 통신은 time master가 보내는 reference message를 기준으로 한다. reference message로 시작하는 한 주기를 **basic cycle**이라 하고, basic cycle은 여러 time window로 나뉜다. 모든 노드는 reference message로 자기 시간 기준을 time master에 맞추고 보정해, 망 전체가 전역 시간을 갖는다. time master가 고장 나면 다른 time master가 대신할 수 있다.[@iso-11898-4-obp-2004]

time window에는 정해진 메시지 하나가 다른 메시지와 겨루지 않고 주기적으로 쓰는 exclusive time window, 여러 메시지가 함께 쓰는 arbitrating time window, 메시지가 배정되지 않은 free time window가 있다. 이어진 arbitrating time window는 하나로 합칠 수 있다. 망의 모든 노드가 보내는 모든 메시지를 basic cycle을 행으로, transmission column을 열로 해 time window에 배정한 표를 **system matrix**라 한다.[@iso-11898-4-obp-2004]

모든 노드가 동기를 맞추면 메시지를 정해진 time slot에 다른 메시지와 버스를 겨루지 않고 보낼 수 있어, 중재에서 지는 일이 없고 지연 시간을 예측할 수 있다. 시간 트리거 CAN 망의 CAN 컨트롤러는 저마다 FSE를 갖는다.[@iso-11898-4-obp-2004]

## 개정 이력

- 2004년: 첫판이 8월에 나왔다.[@iso-11898-4-2004]
- ISO는 2025년 정기 검토에서 이 판을 그대로 유지하기로 확인했다.[@iso-11898-4-2004]

## 개발과 채택

CiA에 따르면 TTCAN(Time-triggered communication on CAN)은 2000년 초 여러 회사가 참여한 ISO 태스크포스에서 정의됐고, Bosch 직원들이 반도체 업계와 학계의 전문가와 함께 프로토콜을 만들었다. 자동차 업계는 TTCAN을 채택하지 않았고, 산업 분야 사용자도 거의 쓰지 않았다.[@cia-can-history-2026]

Bosch 논문에 따르면 TTCAN은 시간 트리거 메시지와 함께, 보통의 CAN 비트 단위 중재가 일어나는 arbitrating time window로 이벤트 트리거 메시지도 보낼 수 있다.[@bosch-icc-ttcan-2000]
