# 결정, 규칙, 근거를 잇는 추적성 관행은 무엇인가

티켓: #713

## 답

범위: 요구사항 추적표(추적 행렬) 문서 자체는 따로 보지 않았다. 행렬의 바탕인 항목과 링크를 데이터로 두고 검사하는 도구(Doorstop, OFT, Sphinx-Needs)로 대신 봤다.

**따라갈 수 있다와 양쪽에 적는다는 다르다.** 추적성은 앞뒤 두 방향으로 따라갈 수 있는 능력이다(C1). 그렇다고 링크를 양쪽에 적는 것은 아니다. 요구사항 도구에서는 아래 항목이 위 항목의 ID를 적고(C3, C7), 거꾸로 가는 링크는 도구가 계산한다(C10, C11). 추적성 문제의 대부분은 요구사항이 정해지기 전의 내력을 추적하지 못해서 생긴다(C2). 이 저장소로 옮기면 "이 규칙은 왜 생겼나"를 규칙에서 결정과 조사로 거슬러 가는 추적이 그 자리라고 이 기록은 본다(추론).

**대체 링크의 방향.** Nygard는 옛 ADR에 대체 표시를 두라고 하고 새 ADR 쪽은 말하지 않는다(C13). MADR 템플릿의 status도 옛 쪽에 적는다(C28). adr-tools는 도구가 양쪽을 한 번에 쓴다(C14). PEP 1에서는 옛 PEP에 `Superseded-By`를 둘 수 있고, 새 PEP는 `Replaces`를 반드시 둔다(C15). PEP 검사기는 값의 꼴만 보고 파일 하나씩만 읽어, 두 PEP의 짝은 보지 않는다(C16).

**규칙 ID와 그 문서.** ESLint 플러그인 쪽은 규칙 메타데이터에 문서 URL을 두게 하는 규칙으로 규칙에서 문서로 가는 링크를 강제한다(C29).

**기계로 검사하는 것.** 네 가지로 나뉜다. 고아와 덮음은 방향이 반대다.

| 검사 | 보는 것                                                | 예                                                                              | 근거                   |
| ---- | ------------------------------------------------------ | ------------------------------------------------------------------------------- | ---------------------- |
| 존재 | 링크의 대상(ID, 파일, 절, 바깥 URL)이 있다             | Doorstop의 모르는 UID, Sphinx nitpicky·linkcheck, remark-validate-links, lychee | C5, C17, C18, C19, C20 |
| 고아 | 아래 항목마다 위 항목을 가리키는 링크가 있다           | Doorstop의 링크 없는 하위 항목                                                  | C6                     |
| 덮음 | 위 항목마다 그것을 가리키는 아래 항목이 하나 이상 있다 | Doorstop `--strict-child-check`, OFT, Sphinx-Needs `back_links`                 | C7, C11, C30           |
| 낡음 | 링크가 적어 둔 대상의 판·지문과 지금 대상이 같다       | Doorstop의 suspect link, OFT의 revision                                         | C4, C8, C9, C27        |

이 도구들은 항목마다 고정된 ID를 둔다(C3, C8, C12). 낡음 검사는 정본이 바뀔 때 가리키는 쪽에 다시 보라고 알리지만, 사람이 그 표시를 지우거나(C27) 뜻이 바뀌었는지 판단해 판을 올려야 한다(C9).

MADR이 권하는 기계 검사는 서식 린트다(C21). Docs as Code는 문서에 자동 테스트를 붙이는 것을 원칙에 넣는다(C22).

**이 저장소의 현행.**

| 링크                      | 어떻게 적나                                     | 기계 검사                                   | 근거          |
| ------------------------- | ----------------------------------------------- | ------------------------------------------- | ------------- |
| 규칙 → 결정               | 운영 문서의 "까닭은 [ADR …]에" 문장             | 없다                                        | C24, C42      |
| 결정 → 규칙               | ADR이 운영 문서를 가리키면 그 문서를 따른다     | 없다                                        | C31           |
| 옛 결정 ↔ 새 결정         | 옛 ADR front matter, 새 ADR 본문, 색인의 세 곳  | 없다                                        | C32, C33, C34 |
| 규칙 → 검사기             | 규약 문서의 줄마다 `검사 <id>` 표지             | 없다. 표지와 검사 이름이 맞는지 보지 않는다 | C35, C36, C43 |
| 규약 문서 → 검사기        | 검사기가 규약 문서의 이름 붙은 표를 직접 읽는다 | 표나 열이 없으면 검사기가 멈춘다            | C37, C38      |
| 위키 페이지 → 위키 페이지 | 위키링크                                        | 대상 페이지와 앵커가 있는지 본다            | C39           |
| 대문 표 ↔ README 표       | 같은 표를 두 곳에 둔다                          | 둘이 같은지 본다                            | C40           |
| 주장 → 출처               | 조사 기록의 출처 ID                             | 출처 목록에 있는지 본다                     | C25           |

결정, 규칙, 근거 사이의 링크를 보는 기계 검사는 조사 기록 안의 ID 검사뿐이다(C25, C26). 다만 규약 문서와 검사기 사이에는 기계 연결이 이미 있다(C37, C38). 지도가 정한 "고칠 때 `git blame`으로 까닭 찾기"(C41)는 링크를 적지 않고 이력에서 계산하는 거꾸로 가는 추적으로, C10의 꼴이다.

**함의(선택지와 비용, 결정은 #714).**

- **존재 검사**: 운영 문서와 스킬의 상대 링크와 절 앵커를 `npm run check`에 더한다. 기존 도구(C19)나 짧은 스크립트로 되고, ID를 새로 매길 필요가 없다. 다만 스킬이 운영 문서를 부르는 자리는 대부분 링크가 아니라 백틱 경로라, 링크만 보는 검사는 그 자리를 놓친다([에이전트가 읽는 문서의 일관성](agent-doc-consistency.md)).
- **고아 검사("규칙마다 결정 기록이 있다")**: 규칙이 결정을 가리키는 꼴이라 C6에 해당한다. 관건은 규칙 ID보다 기계가 규칙 하나의 경계를 셀 수 있느냐다. 줄 끝 표지(C35)가 그 선례다. "기존 규칙은 미리 소급하지 않는다"와 부딪치므로, 걸려면 PR이 바꾼 줄에만 거는 범위가 필요하다.
- **덮음 검사("결정마다 그것을 따르는 규칙이 있다")**: ADR은 이미 번호가 있어(C32, C34) 위 항목의 ID는 따로 매기지 않아도 된다. 아래 쪽 링크(C24)를 셀 수 있어야 한다.
- **낡음 검사**: 가리키는 쪽이 대상의 판이나 지문을 함께 적는다. 정본이 바뀔 때 가리키는 곳을 모두 다시 보게 하지만, PR마다 표시를 지우는 손이 든다(C27, C9).
- **짝 검사**: ADR 대체는 이미 세 곳에 적힌다(C32, C33, C34). 셋이 맞는지 보는 검사를 두거나, adr-tools처럼 도구가 한 번에 쓰거나(C14), 한쪽만 적고 나머지를 계산한다(C10).
- **표지 검사**: `검사 <id>` 표지가 있는 검사 이름을 가리키는지 보는 존재 검사다(C35, C36). 이미 있는 링크라 새 ID가 필요 없다.
