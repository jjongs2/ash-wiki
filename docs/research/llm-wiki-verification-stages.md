# LLM으로 글을 쓰는 위키와 지식 기반은 어떤 검증 단계를 두는가

티켓: #718

## 답

견준 곳 가운데 쓴 글을 주장 단위로 출처와 대조해 뒷받침된 것만 내보내는 관문을 둔 것은 WikiChat 하나다(C10, C11). WikiChat은 위키가 아니라 대화 응답을 만든다(C12). STORM은 절마다 찾은 문서로 인용 달린 글을 쓰고 다듬을 뿐, 쓴 글을 출처와 대조하는 단계가 없다(C1, C2, C3). 인용 충실도와 사람 검토는 평가에서만 했고, 만든 글은 게시하지 않았다(C4, C8, C9). 위키백과는 2026년 3월부터 LLM으로 기사 글을 만들거나 고쳐 쓰는 것을 금지했다(C16). 허용한 두 쓰임인 자기 글의 교정과 다른 언어판의 번역도 사람이 검토한 뒤에만 넣는다(C17, C18). Karpathy의 LLM 위키는 ingest 때 사람이 요약을 읽기를 권하지만 사람 없이 몰아 넣는 것도 허용하고, 그 뒤는 주기적인 lint에 맡긴다(C23, C24). Grokipedia는 독자가 제안한 편집을 출처와 대조해 Grok이 승인한다고만 밝힌다(C25, C26, C27).

인용 충실도에서 많이 나온 문제는 지어낸 출처보다 출처를 넘어선 추론이다. STORM 글의 문장 가운데 84.83%가 인용으로 뒷받침되었고, 뒷받침되지 않은 문장은 주로 부적절한 추론 연결과 부정확한 풀어 쓰기에서 나왔다(C5, C6). 편집자가 매긴 낮은 검증 가능성 점수도 정보 사이의 검증할 수 없는 연결에서 왔고, 저자들은 이를 기본 fact-checking으로 풀 수 없는 문제로 본다(C7). 위키백과 AI Cleanup도 최근 모델은 실제 출처를 달지만 그 출처가 내용을 뒷받침하는지는 확인하지 않는다고 본다(C21). 존재하지 않는 출처는 판별하기 쉬운 징후로 따로 다룬다(C22). 그래서 물을 것은 출처가 있는지보다 인용한 자리가 주장을 직접 뒷받침하는지다. 위키백과의 "직접 뒷받침"이 이 기준이다(C20). 연구 쪽에서 FActScore는 글을 원자 사실로 쪼개 지식 출처가 뒷받침하는 비율을 재고(C13), 참·거짓 대신 정한 출처가 뒷받침하는지를 묻는다(C14). ALCE는 인용이 문장을 다 뒷받침하는지(citation recall)와 쓸데없는 인용이 없는지(citation precision)를 따로 잰다(C15).

이 저장소의 파이프라인은 견준 곳보다 게시 전 관문이 많다. 인제스트는 초안, 검증자 판정, 도해, 격리 자기 점검, 콘텐츠 검사, 검토를 거친다(C28). 페이지마다 검증자 하나가 브리프와 자기 몫만 받아(C29), 주장을 인용 위치에 적힌 것과만 대조한다(C30). 게시는 검증 완료만 한다(C31). 재조사 반영안은 표본이 아니라 모든 문장을 빈 컨텍스트의 검증자가 다시 대조한다(C32). 검증 뒤에는 표기, 도해, 독자 검토가 돌고(C33), 뜻을 바꾸는 반영은 재판정을 거친다(C34). STORM의 주된 오류인 출처 밖 추론은 판정 기준(C31)과, 원문에 없는 인과를 넣자는 독자 지적을 막는 거르기 규칙(C35)이 다룬다. 사람은 머지와 독자 검토 반영의 승인에 들어가고(C36, C37), 소유자의 승인도 검증자의 판정을 넘지 못한다(C38). 위키백과가 허용한 LLM 쓰임마다 사람 검토를 요구하는 것(C17, C18)과 달리, 이 저장소에서 주장과 원문의 대조는 에이전트가 맡는다. ALCE의 citation precision처럼 주장을 뒷받침하지 않는 군더더기 인용을 따로 거르는 규칙은 찾지 못했다(C39).

**선택지(결정은 뒤 티켓).**

- **현행 유지**: 견준 곳 가운데 게시 전 관문이 가장 많고(C28, C29, C30, C31, C32), 견준 관행이 짚은 주된 오류(출처 밖 추론)를 판정 기준과 거르기 규칙이 이미 다룬다(C31, C35). 이 기록이 찾은 근거 가운데 단계를 바꾸라고 가리키는 것은 없다.
- **인용 정밀도를 검증자 반환에 더한다**: 인용마다 그 주장을 뒷받침하는지를 적게 한다(C15, C39). 검증자의 몫과 반환이 늘어난다(추론). 군더더기 인용이 실제로 얼마나 나왔는지는 이 조사에서 세지 않았다. 바꿀 규칙은 검증자 agent 파일의 반환과 위키 검증의 판정 절이다.
- **사람의 표본 대조를 둔다**: 소유자가 검증 완료 주장 몇 개를 원문과 대조한다. 위키백과가 LLM 글을 막은 까닭은 사람 검토가 생산 속도를 따라가지 못해서다(C19). 표본의 크기와 자리를 정해야 한다. 바꿀 규칙은 위키 검증의 검토 절이다.
- **값싼 자동 대조를 앞에 둔다**: STORM과 ALCE처럼 작은 모델로 인용의 함의를 먼저 걸러 검증자의 몫을 줄인다(C4, C15). 다만 STORM이 짚은 문제는 함의 판정을 넘어선 추론 연결이었다(C7). 바꿀 규칙은 인제스트와 재조사 스킬의 검증 단계다.
