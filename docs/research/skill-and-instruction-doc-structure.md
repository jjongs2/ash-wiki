# 스킬과 지시 문서는 어떤 크기와 짜임으로 두는가

티켓: #720

## 답

범위: Agent Skills 명세와 Anthropic의 스킬 작성 지침, Claude Code(스킬, CLAUDE.md, 서브에이전트, 컨텍스트, Read 도구), Codex(스킬, AGENTS.md), Cursor 규칙의 문서와 Anthropic의 context engineering 글을 이 저장소의 `CLAUDE.md`, 스킬 8개, 에이전트 5개, 운영 문서와 견줬다. 여러 문서에 적은 지시의 일관성과 참조 깊이는 [에이전트가 읽는 문서의 일관성](agent-doc-consistency.md)이 다뤘으므로 다시 보지 않는다. 토큰은 재지 않고 줄과 글자로만 쟀다.

**바깥 관행은 늘 읽히는 층과 필요할 때 읽는 층을 가른다.** 늘 읽히는 것은 지시 파일과 스킬·서브에이전트의 설명이다. Claude Code는 CLAUDE.md를 200줄 아래로 두고, 코드에서 알아낼 수 없는 것만 적으라고 한다(C10, C12). 여러 단계의 절차나 일부에만 해당하는 지시는 스킬이나 경로 규칙으로 옮긴다(C11). import는 파일을 나눌 뿐 비용을 줄이지 않는다(C30). Codex는 합친 AGENTS.md가 32 KiB에 이르면 파일을 더 넣지 않는다(C13). 설명에도 상한이 있다(C8, C31, C32, C33). 사람만 부르는 스킬은 설명을 빼게 할 수 있다(C9). Cursor도 규칙을 늘 적용, 설명으로 고름, 파일 패턴, 손으로 부름으로 가른다(C35).

필요할 때 읽는 것은 스킬 본문과, 본문이 가리키는 스킬 폴더의 파일이다(C1, C3, C5, C6). 본문은 500줄과 5,000토큰 아래를 권한다(C1, C2). 한 번 읽힌 본문은 다음 턴에도 남고(C7), compaction 뒤에는 앞의 5,000토큰만 다시 붙는다(C17). 함께 쓰이지 않는 내용은 다른 파일로 나눈다(C4). 100줄이 넘는 참고 파일에는 머리에 목차를 둔다(C16). Claude Code의 Read는 한 번에 25,000토큰까지 돌려주고, 넘는 파일은 첫 쪽만 준다(C34). 짧음이 목적은 아니다(C15).

**이 저장소.** 스킬은 8개, 에이전트는 5개다(C18). `CLAUDE.md`는 29줄이고, 운영 문서를 import 없이 경로로 가리킨다(C21). 스킬 본문은 75\~245줄이다(C19). 넷은 사람만 부른다(C20). 규칙을 읽는 꼴은 둘이다.

- **단계마다 읽기**: 인제스트와 Reader Testing은 단계마다 "읽는다:"로 그 단계에 쓸 문서와 절을 적는다(C22, C23). #347이 비용을 줄이려고 인제스트에 들였고, 다른 스킬은 범위 밖으로 두었다(C24, C28).
- **머리에서 먼저 읽기**: 재조사, 보강, 린트, 주제 계획, 소식 조사와 agent 파일 넷은 머리의 "먼저 읽는다" 목록 하나로 시작한다(C36). 목록은 절을 적기도 하고 문서 전체를 적기도 한다. 재조사는 위키 검증 문서 전체를 먼저 읽는다(C37).

어느 꼴이든 단위는 여러 스킬이 함께 쓰는 운영 문서의 절과 문단이다(C27). 가장 큰 위키 검증 문서는 745줄이고(C26), 100줄이 넘는 참고 파일 12개 모두 머리에 목차가 없다(C38).

**선택지(결정은 뒤 티켓).**

- **현행 유지**: 줄 수로는 스킬과 `CLAUDE.md` 모두 바깥 문턱 아래다(C19, C21). 토큰은 재지 않았다. 필요할 때 읽게 하려는 뜻은 바깥과 같지만 단위가 다르다. 바깥의 셋째 층은 스킬 폴더 안의 파일이고(C2, C3), 여기는 여러 스킬이 함께 쓰는 큰 운영 문서의 절이다(C22, C27).
- **큰 참고 파일에 목차를 둔다**: 콘텐츠, ADR, 조사 기록, `.github/`, `SKILL.md`를 뺀 Markdown 가운데 100줄이 넘는 파일 머리에 절 목록을 둔다(C16, C38). 지금 목차가 없는 것은 12개다. 일부만 읽혀도 어떤 절이 있는지 보이게 된다(C34). 어느 파일이 Read 한도를 넘는지는 재지 않았다. 목차가 제목과 갈라지지 않게 지킬 방법도 정해야 한다.
- **단계별 읽기를 다섯 스킬로 넓힌다**: 재조사, 보강, 린트, 주제 계획, 소식 조사의 머리 목록을 단계마다의 "읽는다:"로 바꾼다(C23, C28, C36). Reader Testing은 이미 그렇다. 바꿀 파일은 그 다섯 `SKILL.md`다. 이 스킬들의 비용은 재지 않았다.
- **5,000토큰을 넘는 스킬을 단계별 파일로 나눈다**: 토큰을 재어 넘는 것이 있을 때만 해당한다. 명세의 권고(C1, C2, C4)대로, #347이 출처 경로의 규칙을 `drafter.md`로 옮긴 꼴(C39)을 따른다. 바꿀 파일은 넘는 `SKILL.md`다.
- **스킬 머리에 늘 지킬 규칙을 둔다**: compaction 뒤에 다시 붙는 것은 스킬의 앞부분이다(C17). 다만 #347이 잰 인제스트 세션 11개는 압축에 걸리지 않았고(C25), 규칙 문서에는 compaction을 다루는 줄이 없다(C29). 바꿀 파일은 각 `SKILL.md`다.
