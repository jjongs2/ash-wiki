# 작성자의 맥락을 넘기지 않는 검토는 같은 맥락의 자기 검토보다 나은가, 검토자에게 무엇을 넘기고 숨기는가

티켓: #719

## 답

**추론과 사실 과제에서 같은 맥락의 자기 검토는 약했다.** 아래 결과는 추론, QA, 사실 생성 과제에서 2023\~2024년 모델로 잰 것이다. 문체와 질을 다듬는 데는 자기 교정이 나아 보였다는 보고도 있다(C39). 바깥 피드백 없이 모델이 제 답을 다시 보고 고치게 하면 추론 과제의 정확도가 오히려 떨어졌다(C1, C2). 답을 바꾼 경우에는 맞는 답을 틀리게 바꾼 쪽이 더 많았고, 저자들은 모델이 제 추론의 옳고 그름을 가리지 못하는 것을 근본 원인으로 본다(C3). RCI, Reflexion 같은 앞선 연구가 보인 개선은 정답 표지를 쓴 덕이었다(C4). 서베이도 일반 과제에서 프롬프트한 LLM의 피드백만으로 자기 교정에 성공한 연구는 없고, 믿을 만한 바깥 피드백이 있는 과제에서는 통한다고 정리한다(C5). 응답을 쪼갤 수 있는 과제처럼 유리한 성질이 있으면 예외다(C6). 걸림돌은 고치기보다 찾기다. 오류 위치를 알려 주면 고치기는 잘한다(C7). 한번 자신한 답은 되짚어도 새 생각이 나오지 않는다는 관찰도 있다(C8).

**새 컨텍스트가 바꾸는 것.** 같은 모델이라도 원래 답을 보지 않고 판단하게 하면 나아졌다. CoVe는 검증 질문에 원래 답을 뺀 프롬프트로 답하게 했고(2-step, factored), 한 프롬프트에서 함께 답한 joint보다 나았다(C9, C10, C38). 이 실험은 도구 없이 같은 모델로만 했다(C11). LLM 판정자도 혼자서는 푸는 문제를 주어진 답에 끌려 틀리게 판정한 예가 있다(C12). 같은 프롬프트에서 먼저 혼자 풀게 해도 여전히 끌렸고, 따로 낸 자기 답을 참조로 보여 주자 오판이 가장 많이 줄었다(C13, C37). 쓴 쪽의 태도도 새어 든다. 사용자가 글을 좋아한다거나 자기가 썼다고 말하면 피드백이 더 긍정적이 된다(C14).

Claude Code 문서는 새 검토자가 쓴 쪽의 추론을 보지 않아서 도움이 된다고 하고, 같은 일을 서브에이전트에 넘기는 것만으로는 답이 나아지지 않는다고 가른다(C15, C16). 다만 이 권고는 측정치를 내지 않고, 에이전트가 코드나 문서를 검토하는 설정에서 두 방식을 견준 측정은 찾지 못했다(C35). 새 컨텍스트도 저절로 생기지 않는다. 서브에이전트는 대화 기록 없이 시작하지만 CLAUDE.md와 git status는 받고(C18, C42), fork는 대화 전체를 물려받으며, fork 모드는 기본으로 켜져 있어 Claude가 스스로 fork를 띄울 수 있다(C19).

**넘길 것과 숨길 것.** 출처들을 묶으면 아래와 같다. 찾으라고 시킨 검토자는 무엇이든 찾고, 긴 지적일수록 지어낸 결함과 사소한 트집이 늘어(C17, C20), 범위도 넘겨야 할 것에 든다.

**이 저장소의 현행.** 위키 콘텐츠의 검증과 검토는 쓴 쪽과 다른 agent가 맡고, 주는 것과 주지 않는 것이 문서에 있다. 검증자는 브리프와 자기 몫만 받고(C27), 출처 경로 검증자는 인용 위치에 적힌 것만 근거로 본다(C28). 표기·도해·독자 검토는 메인 세션의 결론을 받지 않고, 숨기는 까닭을 저마다 적는다(C24, C25, C26). 재조사 반영안은 그것을 쓰지 않은 빈 컨텍스트 에이전트가 모두 다시 대조한다(C29). 검토는 맡은 규칙만 보고 보고만 하며 고치는 쪽은 하나다(C23, C32). 찾기와 고치기를 가른 이 꼴은 C7의 관찰과 맞는다(추론). 검토는 두 회차에서 멈춘다(C33). 찾으라고 시키면 지적이 끝나지 않는다는 C17의 문제를 막는 장치로 읽힌다(추론).

하네스 쪽에서는 PR 전 두 축 리뷰가 축마다 새 컨텍스트 서브에이전트를 띄우고(C21, C22), 조사 기록은 조사 대화를 넘겨받지 않은 사실 확인 에이전트가 본다(C30). ticket-runner는 구현과 검증을 다른 Stage, 곧 다른 세션으로 돈다(C31). 숨길 것을 적은 곳은 위키 검토 절, 인제스트의 검증자와 도해 에이전트 단계, 외부 독자 지시다(C40). 주제 계획과 보강의 비평 단계는 빈 컨텍스트 비평가에게 줄 것만 적는다(C41). 조사 기록의 사실 확인도 대화를 넘기지 않는다는 것만 적고, 메인 세션의 가늠이나 조사 에이전트의 까닭을 브리프에서 뺄지는 적지 않는다(C34). 사실 확인 에이전트는 내장 general-purpose라 `omitClaudeMd`를 둘 수 없어 CLAUDE.md를 받는다(C30, C42). ticket-runner의 verify Stage가 무엇을 받는지는 이 저장소 문서에 없다(C36).

**선택지(결정은 뒤 티켓).**

- **현행 유지**: 위키 콘텐츠의 검증과 검토는 쓴 쪽의 추론과 결론을 숨기고 판정 기준과 출처를 준다(C24, C25, C26, C27, C28, C29). 문서가 띄울 agent를 이름으로 정해(C27, C29, C30) fork로 띄울 여지도 적다.
- **사실 확인과 비평의 브리프에 주는 것·주지 않는 것을 적는다**: 위키 검토 절처럼, 사실 확인에는 질문, README, 조사 기록, 출처 목록만 넘기고 조사 에이전트의 까닭과 메인 세션의 가늠은 넘기지 않는다는 줄이다. 근거는 C14, C15다. CLAUDE.md까지 숨기려면 `omitClaudeMd`를 둔 agent 파일이 따로 든다(C42). 바꿀 곳은 `docs/research/README.md`의 머지까지 2단계이고, 비평까지 넓히면 주제 계획 3단계와 보강 4단계다.
- **검증자가 인용 위치를 먼저 읽고 나서 초안 문장과 견주게 한다**: 같은 프롬프트에서 먼저 혼자 풀게 하는 판정자(C13)의 꼴이다. 다만 그 판정자는 여전히 주어진 답에 끌렸다(C37). 바꿀 곳은 `source-verifier`의 할 일 3, 4다.
- **초안 문장을 보지 않은 에이전트가 인용 위치의 내용을 먼저 뽑고, 검증자가 그것과 초안 문장을 견준다**: CoVe의 2-step·factored(C9, C38)와 따로 낸 참조 답(C13)의 꼴이다. 다만 두 실험은 목록 생성, closed-book QA(MultiSpanQA), 전기 생성(Llama 65B)과 수학 문제(GPT-4)에서 잰 것이고, 출처 대조 판정에서 잰 것은 아니다. 페이지마다 에이전트가 하나 더 든다. 바꿀 곳은 인제스트 2단계와 `source-verifier`의 할 일이다.
