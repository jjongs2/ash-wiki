# 같은 모델끼리 검증하는 데는 어떤 한계가 있고, 대안은 무엇을 얻고 무엇을 치르는가

티켓: #719

## 답

**한계.** 판정자는 제 글을 알아볼수록 제 글을 더 높게 쳤다. 미세 조정으로 자기 인식을 키우자 자기 선호도 선형으로 커졌다(C1). MT-Bench에서는 GPT-4와 Claude-v1이 제 답에 승률을 더 줬지만 다른 모델도 높게 줬고, 저자들은 결론 내지 못했다(C2). 참조 답을 쥔 QA 판정에서도 모델마다 자기를 판정할 때 점수가 가장 많이 올랐다(C35, C37). 자기에 그치지 않는다. 판정자는 능력을 통제해도 자기와 닮은 모델에 점수를 더 줬고, 다른 계열 쌍만 봐도 그랬으며, 32B보다 작은 판정자에서 더 컸다(C3, C4, C33). 같은 계열 모델끼리 더 닮았다는 관찰은 7B·8B 모델 몇 개로 본 부록의 분석이고, instruction-tuned 모델에서는 다른 계열 쌍이 가장 닮았다(C6). 토론에서 GPT-4 판정자는 GPT-4가 맡은 쪽을 더 골랐지만, GPT-4가 더 센 토론자이기도 해 자기 선호와 질이 갈리지 않는다(C7). Claude Code 문서도 서브에이전트는 기본으로 같은 모델이나 더 작은 모델이라, 새 눈은 얻지만 더 똑똑한 답은 얻지 못한다고 적는다(C9).

이 연구들은 쌍 비교, 점수 판정, 짧은 답의 QA 판정에서 쟀고, 긴 원문과 주장을 대조하는 판정에서 잰 것은 아니다. 닮음 편향(C3)은 판정자가 정답 없이 제 지식으로 판정한 설정에서 쟀다. 출처 대조로 옮기면, 쓴 쪽이 원문을 잘못 읽은 자리를 같은 모델이 같은 식으로 잘못 읽어 통과시키는 것이 위험이다(추론).

벤더 문서에서는 Anthropic의 채점 예시 코드가 만든 모델과 다른 모델로 채점하는 것이 대체로 좋다고 주석을 달지만, 그 예시는 생성과 채점에 같은 모델 ID를 쓴다(C16). 같은 모델을 여럿 두면 실수도 함께 닮을 것이므로, 여럿의 이득은 판정자끼리 다를 때 나온다고 읽힌다(추론).

**이 저장소의 현행.** 판정과 검토를 맡는 agent는 모두 Claude 계열이다. agent 파일은 두 검증자를 opus로(C24), 표기·도해 검토자와 외부 독자를 sonnet으로 정한다(C25). 다만 띄울 때 준 `model`이 agent 파일보다 앞선다(C41). agent 파일로 모델을 정하는 까닭은 판정 결과를 고정하려는 것이다(C42). 쓰는 쪽은 노트 경로에서는 메인 세션, 출처 경로와 재조사에서는 general-purpose 에이전트라 메인 세션의 모델을 따르고, 사실 확인 에이전트와 두 축 리뷰의 서브에이전트도 모델을 정하지 않는다(C18, C26, C27, C43, C44). 메인 세션이 opus면 인제스트 두 경로와 재조사에서 쓰는 쪽과 검증자가 같은 모델이 된다(추론). 대신 판정을 바깥 근거에 묶는다. 검증자는 출처의 인용 위치를 열어 거기 적힌 것만 근거로 보고(C28), PR 전에는 스크립트 검사를 통과시킨다(C29). 같은 주장을 일부러 둘이 판정하는 자리는 재조사다. 재조사 에이전트가 항목마다 라벨을 매긴 뒤 빈 컨텍스트 검증자가 반영할 문장을 모두 다시 대조하고(C45), 반영 뒤 재판정에서 두 판정이 갈리면 검증 완료로 치지 않는다(C31). 인제스트는 페이지마다 검증자 하나다(C30). 사람은 머지를 맡는다(C32).

**선택지(결정은 뒤 티켓).**

- **현행 유지**: 같은 계열의 약점(C1, C3)을 출처 원문과 스크립트라는 바깥 근거가 좁힌다(C8, C10, C28, C29). 다만 참조를 쥔 판정에서도 자기 선호가 남았고(C35, C37), 같은 모델이 같은 원문을 같은 식으로 잘못 읽는 위험도 남는다(추론).
- **쓰는 쪽과 판정하는 쪽의 모델을 다르게 둔다**: 계열 안에서 쓰는 쪽과 검증자의 모델이 겹치지 않게 agent 파일이나 띄울 때의 `model`을 정한다(C18, C41). 노트 경로의 쓰는 쪽은 메인 세션이라 바꿀 수 있는 것은 검증자 쪽이다(C43). 얻는 것은 작을 수 있다. 같은 개발사의 모델은 닮음 연구에서 일부러 뺐고(C5), 닮음은 구조보다 학습 자료와 후속 학습에 더 달렸을 수 있으며(C46), 판정자가 자기 계열의 다른 변형을 높이 친 예도 있다(C36). 한쪽이 작은 모델이 되면 판정의 질이 떨어지고 닮음의 효과도 커질 수 있다(C4). 바꿀 곳은 `.claude/agents/`의 `model`, 인제스트 1단계의 초안 에이전트, 재조사 2단계의 재조사 에이전트다.
- **다른 계열 판정자를 표본에 둔다**: PoLL의 꼴이다(C14, C15). Claude Code의 agent `model`은 Claude 모델의 별칭이나 ID를 받으므로(C18), 다른 계열은 하네스 밖의 API 호출과 키가 든다. 짧은 정답과 대조하는 QA 판정에서는 쟀지만, 긴 원문과 주장을 대조하는 판정은 재지 않았다(C15, C17, C40, 추론). 닮음 편향은 다른 계열 쌍에서도 나왔고(C33), 다른 개발사 모델끼리도 실수가 닮아 간다(C5, C34). 바꿀 곳은 `tools/` 아래 새 도구와 위키 검증의 검토 절이다.
- **전용 사실 확인 모델을 앞이나 옆에 둔다**: 근거 문서 대조를 따로 학습한 작은 모델(C49)은 그 과제 자체에서 잰 다른 모델이다. 하네스 밖 실행이 들고, 이 저장소의 긴 표준 원문에서는 재지 않았다. 바꿀 곳은 `tools/` 아래 새 도구와 인제스트 2단계다.
- **판정 전에 추론하게 한다**: Anthropic은 채점 모델의 thinking을 켜면 평가 성능이 오른다고 한다(C47). 다만 서브에이전트는 메인 대화의 thinking 설정을 물려받고 따로 정할 수 없어(C48), agent 파일로는 바꿀 수 없다. 바꿀 곳은 세션 설정이나 두 검증자의 지시다.
- **인제스트에도 독립 판정을 하나 더 둔다**: 재조사의 꼴(C45)을 인제스트로 넓혀, 첫 판정과 다른 빈 컨텍스트 검증자가 다시 대조하고 갈리면 미검증으로 둔다(C31). 토론이 아니라 독립 판정을 모으는 꼴이다(C19, C20). 판정 호출이 두 배가 되고, 같은 모델 둘이면 닮은 실수를 공유할 수 있다(추론). 바꿀 곳은 인제스트 2단계와 위키 검증의 판정 절이다.
