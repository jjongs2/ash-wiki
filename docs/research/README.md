# 하네스 조사

하네스의 설계 질문을 공개 출처로 조사해 남기는 자리다. 질문 하나에 조사 기록 하나를 `docs/research/<질문-slug>.md`로 두고, 출처는 모두 [출처 목록](sources.md)에 둔다. 형식은 `npm run check:research`가 검사한다.

## 데이터 경계

조사 기록과 출처 목록에는 공개 출처와, 그 출처로 확인한 사실을 자기 말로 다시 쓴 것만 들인다. 세션 기록, 회고 분석, 로컬 경로, 비공개 저장소와 개인 설정의 이름은 들이지 않는다. 저장소가 공개라 한 번 머지한 것은 이력에서 지울 수 없기 때문이다. 하네스의 지난 동작을 근거로 삼으려면 그 동작을 남긴 공개 기록(이슈, PR, 커밋)을 출처로 쓴다.

인용은 주장을 받치는 한두 문장만 원문 그대로 옮긴다.

## 조사 기록

아래 꼴을 복사해 채운다. `<…>` 자리를 남기면 검사가 실패한다.

```markdown
# <질문>

티켓: #<번호>

## 답

<질문에 대한 답. 주장의 ID를 가리킨다. 예: 대부분의 저장소는 ADR을 번호 파일로 둔다(C1, C2).>

## 주장

| ID  | 주장   | 출처      | 인용          | 신뢰도 |
| --- | ------ | --------- | ------------- | ------ |
| C1  | <주장> | <S101 §2> | <원문 그대로> | H      |
```

- **ID**: `C1`부터 기록 안에서 겹치지 않게 매긴다.
- **출처**: 출처 목록의 ID. 여럿이면 `;`로 가르고, 자리(절, 쪽, 줄)를 ID 뒤에 붙인다. 예: `S101 §2; S102`. URL은 여기 적지 않고 출처 목록에 등록한다.
- **인용**: 출처의 원문. 원어 그대로 둔다.
- **신뢰도**:

| 값  | 뜻                                           | 검사가 요구하는 것              |
| --- | -------------------------------------------- | ------------------------------- |
| H   | 1차 출처에서 인용했다                        | 1차 출처 하나 이상과 인용       |
| M   | 1차 출처를 풀어 쓰거나 1차 출처에서 끌어냈다 | 출처 하나 이상                  |
| U   | 확인하지 못했다                              | 없음. 출처 없는 주장은 U만 된다 |

셀 안의 `|`는 `\|`로 쓴다. 주장 표 밖의 표는 주장으로 읽지 않는다.

## 출처 목록

[출처 목록](sources.md)의 한 줄이 출처 하나다.

- **ID**: `S` 뒤에 숫자. 조사 티켓마다 본문에 적힌 범위(예: S100\~S199)에서 매겨, 나란히 도는 티켓끼리 겹치지 않게 한다.
- **판**: 판이나 개정일. 없으면 `없음`.
- **읽은 날**: `YYYY-MM-DD`.
- **종류**: `1차`는 그 장치나 관행을 만든 쪽이 낸 글(공식 문서, 명세, 원 논문, 저자의 글, 저장소). 그 밖은 `2차`.

한 URL은 한 ID로만 등록한다. `#` 뒤 조각과 끝의 `/`는 같은 URL로 본다.

## 머지까지

1. 조사 티켓 하나를 worktree 하나에서 조사하고, 질문마다 조사 기록 하나를 써서 PR 하나로 올린다. 동시에 진행하는 조사 티켓은 둘까지다.
2. 머지 전에, 조사한 세션의 대화를 넘겨받지 않은 새 에이전트가 사실을 확인한다. 출처를 모두 다시 열고, 인용을 원문과 대조하고, 수를 다시 세고, 결론에 반론한다.
3. 지적은 메인 세션이 가늠해 조사 기록을 쓴 에이전트에게 한 번 돌려보낸다. 그 에이전트는 출처를 다시 연 뒤에 고친다.
4. PR은 한 번에 하나씩 머지한다. base 브랜치로 rebase하고, base에 이미 있는 URL을 새로 등록했으면 base의 ID로 합치고, `npm run check`를 통과시키면 소유자가 머지한다.
