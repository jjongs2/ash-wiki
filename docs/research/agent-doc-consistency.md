# 에이전트가 읽는 문서의 일관성은 공개된 프로젝트와 도구에서 어떻게 관리하는가

티켓: #713

## 답

에이전트 지시 파일은 형식이 정해지지 않은 Markdown이다(C1). 도구마다 읽는 파일 이름과 합치는 방식이 달라(C2, C4, C7, C12) 여러 에이전트를 쓰는 프로젝트는 같은 지시를 여러 파일에 두게 되고, 이를 다루는 관행은 둘이다.

| 관행                  | 하는 일                                                                           | 기계 검사                                    | 근거                       |
| --------------------- | --------------------------------------------------------------------------------- | -------------------------------------------- | -------------------------- |
| 한 파일 + 링크·import | 정본 파일 하나를 두고 다른 이름은 심볼릭 링크나 `@path` import로 그 파일을 읽는다 | 없다. 사본이 없어 어긋날 것이 없다           | C3, C6, C11, C19, C20, C24 |
| 중앙 원본 + 생성      | 한 폴더의 규칙을 도구별 파일로 생성한다                                           | `--check`가 생성 결과가 최신인지 CI에서 본다 | C16, C17, C18              |

도구의 지침은 사본 대신 파일을 가리키라고 권한다(C13). 다만 가리킴에도 비용이 있다. import한 파일은 컨텍스트를 줄이지 않고(C8), 가리킨 파일이 다시 다른 파일을 가리키면 에이전트가 일부만 읽을 수 있어 한 단계만 두라고 권한다(C14).

뜻의 일관성을 보는 결정적 검사는 찾지 못했다. 스킬 검사기는 frontmatter와 이름 규칙만 본다(C21). 지시 사이의 모순과 없는 파일 참조는 Claude Code가 LLM 감사로 찾고, 그 결과는 고칠 안을 내는 보고서다(C9, C10). 같은 낱말을 한결같이 쓰라는 것도 작성 지침이다(C15).

**이 저장소에 주는 함의(결정은 #714).**

- 위 두 관행은 여러 에이전트에 같은 지시를 나눠 주는 문제를 푼다. 이 저장소의 어긋남은 스킬과 프롬프트가 운영 문서의 규칙을 다시 적는 데서 났고(C22), 두 관행 모두 그 꼴을 검사하지 않는다.
- 이 저장소가 스킬에서 운영 문서를 가리키는 구조(C23)는 C13의 권고와 맞지만, 스킬 → 운영 문서 → 다른 운영 문서로 이어지면 C14가 경고하는 중첩 참조가 된다. 가리킴의 깊이는 검사할 거리다.
- 기계로 검사할 만한 것은 스킬·에이전트 문서의 링크가 있는 파일과 절을 가리키는지(존재)다. 모순 찾기(C10)는 결정적이지 않아 CI 단계보다 리뷰 단계의 도구에 가깝다.
