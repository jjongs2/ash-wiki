# 일을 서브에이전트에게 나누는 기준은 무엇이고, 브리프는 어떤 꼴로 쓰는가

티켓: #720

## 답

범위: Anthropic(에이전트 설계 글, 다중 에이전트 조사 시스템, 다중 에이전트 지침, context engineering, 긴 작업 하네스), OpenAI의 에이전트 설계 지침, Cognition의 글 둘, Claude Code·Codex·Gemini CLI의 서브에이전트 문서를 이 저장소에서 에이전트를 띄우는 스킬 여섯(C53)과 agent 파일, 그 변경을 남긴 이슈와 PR과 견줬다. 판정자에게 무엇을 주고 숨기는지, 판정의 신뢰도는 #719가 다룬다.

**나누는 기준.** 출처들은 먼저 나누지 말라고 한다. 가장 단순한 것에서 시작하고(C1), 에이전트 하나를 먼저 끝까지 쓴다(C2). Anthropic은 여러 에이전트가 하나보다 나은 때를 셋으로 꼽고(C40), 다른 출처가 꼽는 때도 이 셋에 든다.

- **컨텍스트 오염**: 긴 출력을 메인 밖에 두고 요약만 돌려받는다(C8, C9, C16, C21, C22).
- **나란히 할 일**: 여러 방향을 넓게 훑는 조사다(C4, C9).
- **전문화**: 도구나 지시가 달라야 할 때다. 조건 분기나 비슷한 도구가 많을 때도 든다(C3, C9).

나누지 말아야 할 때도 분명하다. 여러 단계가 컨텍스트를 많이 나누거나 에이전트끼리 기대는 것이 많으면 맞지 않는다(C4, C8). 일의 종류가 아니라 컨텍스트의 경계로 나눈다(C41). 여럿이 나란히 쓰면 충돌할 수 있다(C10). Cognition은 저마다 암묵적으로 정한 것이 부딪친다고 보고(C6, C7), 2026년에는 쓰기를 한 갈래로 두고 다른 에이전트는 판단만 보탤 때 잘 된다고 한다(C43). 비용은 같은 일에 단일 에이전트보다 3\~10배, 대화보다 15배다(C42, C5). 같은 일을 맡긴다고 답이 나아지지는 않는다(C11).

**브리프의 꼴.** Claude Code의 서브에이전트는 대화를 보지 못하고, 자기 시스템 프롬프트, 위임 메시지, CLAUDE.md, git 상태로 시작한다(C17, C39). CLAUDE.md 없이 시작하는 서브에이전트에게는 꼭 지킬 규칙을 위임 프롬프트에 다시 적는다(C18). 브리프에는 목표, 출력 꼴, 쓸 도구와 출처, 맡은 일의 경계를 주고(C12), 나누는 법, 기다릴지, 돌려받을 것을 적는다(C14). 돌려받는 것은 1,000\~2,000토큰의 요약이 흔하고(C16), 큰 결과는 파일에 두고 참조만 넘긴다(C19, C20). 세부를 너무 일찍 정하면 그 오류가 뒤로 번진다(C15).

**이 저장소의 나누기.** 나누는 까닭을 적는 것은 인제스트다. 출처 원문을 메인 밖에 두고, 노트를 모르는 쪽이 도해를 그리게 하고, 검증자에게 자기 몫만 준다(C23, C28, C29). 다른 스킬은 나누는 단위만 적는다(C30, C31, C32, C45, C51, C52). 수의 규칙은 셋이다. 인제스트는 묶음의 제안 항목 15개에서(C25), 재조사는 사유 절의 항목 15개에서 나눈다(C30). 동시에 띄우는 수는 20까지로, Claude Code의 기본 한도다(C30, C44). 재조사의 15는 #296이 열 개에서 올린 것이고, 까닭은 실제 규모에서 단위가 맞지 않았다는 것뿐이다(C50). 인제스트의 15는 #347이 그것을 옮겼다(C24).

쓰는 에이전트 사이의 충돌은 미리 정해 줄인다. #347은 표기가 갈린다고 보고 초안 에이전트를 묶음마다 하나 두었다(C24). PR #373이 이를 병렬로 바꾸며 표기 표를 들였다(C26). 지금은 함께 쓸 표기를 먼저 적고, 묶음 밖 파일은 에이전트 하나에만 주고, 반환 뒤 새로 정한 표기를 맞춘다(C27, C49). 쓰기는 여전히 여러 갈래이므로, Cognition이 짚은 위험(C43)을 없애지는 못하고 줄인다.

**이 저장소의 브리프와 반환.** 프롬프트 파일의 꼴은 하나가 아니다(C34). 지시 블록, 띄우는 프롬프트, 반환 꼴을 둔 것이 셋이고, 지시 하나에 JSON 반환이 하나, JSONL 파일을 쓰는 브리프가 셋, 차례와 JSON 배열이 하나다. #347은 초안 프롬프트를 기존 꼴에 맞추게 했다(C46). 에이전트들이 함께 읽는 브리프 파일은 인제스트의 것이다(C33). 규칙은 정본을 가리키되, 묶음이 함께 쓸 표기 결정과 지시 블록은 브리프에 옮긴다(C35). 서브에이전트에게는 자기 몫만 준다(C28, C30). 반환을 확인해 빠진 것을 SendMessage로 돌려보내는 것은 인제스트이고(C36), B 반영도 같은 에이전트를 이어 쓴다(C48). Reader Testing은 끝난 Workflow 에이전트에 돌려보내지 않는다(C47). agent 파일은 검증자와 검토자에만 두어 도구와 모델을 고정하고(C37), 그 가운데 셋만 CLAUDE.md 없이 시작한다(C38).

**선택지(결정은 뒤 티켓).**

- **현행 유지**: 나누는 단위는 스킬마다 있고, 쓰는 에이전트 사이의 충돌은 표기 표, 파일 배정, 반환 뒤 맞추기로 줄인다(C27, C49). 쓰기가 여러 갈래라 위험이 남는다(C43).
- **브리프의 꼴을 한 곳에 적는다**: 지금 프롬프트 파일의 꼴은 넷이다(C34). `CONTRIBUTING.md`의 스킬과 에이전트 절에 하나를 정하거나, 반환을 메시지로 받을 때와 파일로 받을 때를 갈라 적는다. 기준은 바깥의 요소(C12, C14)다. 바꿀 파일은 `CONTRIBUTING.md`와, 꼴을 하나로 정하면 프롬프트 파일들이다.
- **나누는 수의 규칙을 한 곳에 모은다**: 두 15는 다른 단위를 세므로(C25, C30) 모으면 규칙 둘을 나란히 두는 것이다. 동시 한도와 주차마다의 검토도 함께 둔다(C44, C51). 15의 근거를 잰 기록은 없다(C50). 바꿀 파일은 인제스트, 재조사, 소식 조사의 `SKILL.md`와 옮겨 갈 운영 문서다.
