# 용어 표기 결정

위키 페이지의 용어 표기에 대한 소유자 결정의 목록이다. 표기를 고르는 순서와 결정을 더하는 절차는 [위키 규약](wiki-conventions.md#용어)에 있다.

약어를 풀이하느냐 마느냐와 조직 약어를 소개하느냐는 [위키 규약의 약어 절](wiki-conventions.md#약어)과 [풀이하지 않는 약어](wiki-abbreviations.md) 목록이 정한다. 조직 약어의 소개 구는 이 목록에 올리지 않는다. 이 목록은 풀이할 때 어느 풀이 문자열을 쓰는지와, 원어·한국어·음차 가운데 무엇을 쓰는지를 정한다. 풀이는 주장이라 판정을 거치는데, 이 목록의 풀이 결정은 그 판정의 근거가 된다. 어느 결정이 근거가 되는지는 [위키 검증의 판정](wiki-verification.md#판정)에 있다.

한 줄에 결정 하나를 `- <쓰는 표기>: <쓰지 않는 표기> (#<결정 이슈나 PR>)`로 적는다. 조건이나 예외가 있으면 줄 끝에 `. <조건이나 예외>`를 붙인다.

- 약어의 풀이는 쓰는 표기를 `<약어> 풀이 <풀이>`로 적는다.
- 통일하지 않기로 한 결정은 쓰는 표기 칸에 원어를, 쓰지 않는 표기 칸에 `통일하지 않음`을 적고, 어디에 무엇을 쓰는지를 조건에 적는다.
- 버린 표기가 기록되지 않은 결정은 쓰지 않는 표기 칸을 `-`로 둔다.
- `aliases`와 인용한 문서의 제목은 이 목록에 걸리지 않는다. alias는 다른 표기로도 찾아오게 하는 자리이고, 문서 제목은 원문 그대로 쓴다.

줄은 쓰는 표기의 가나다순으로 둔다. 라틴 문자는 한글보다 앞에 두고 대소문자를 가리지 않으며, 기호와 공백은 글자보다 앞에 둔다. 결정을 더하는 PR끼리 같은 줄을 고치지 않게 하려는 꼴이다.

- (informative): (참고), 참고 Annex (#566). 표준의 informative Annex와 절. 꾸밈말 꼴도 같다. 예: "informative Annex로". 원문이 다른 말로 적으면 그 말. 예: 원문이 non-normative라 적은 장은 "(non-normative)". 조사는 괄호 앞의 Annex 이름이나 절 번호에 맞춘다. 예: "Annex U(informative)는"
- adaptive update: - (#432)
- Annex: 부속서, 부록 (#301). 원문이 Annex일 때. 원문이 Appendix인 "부록"은 그대로
- aperiodic: 비주기 (#350). 합성어 포함. 예: aperiodic 태스크, aperiodic server. CANopen PDO의 주기·비주기 송신처럼 통신의 송신 방식은 예외
- ASPICE: Automotive SPICE, A-SPICE (#231). 판을 붙이면 `ASPICE 4.1` 꼴. 정식 이름은 `automotive-spice` 머리말의 풀이에만, A-SPICE는 그 페이지의 alias로만. 문서 이름 "Automotive SPICE for Cybersecurity"와 슬러그는 예외
- baud: 보드레이트 (#496). 기호는 Bd. 음차 "보"도 쓰지 않는다. "Baud Rate Prescaler" 같은 이름은 그대로
- CAN CC 풀이 CAN classic: CAN CC(CC: classic), CAN CC(Classical CAN), CAN classic(CC) (#564)
- cascading failure: 연쇄 고장 (#291)
- CDD 풀이 Complex Driver: Complex Device Driver (#440). 근거는 SWS BSWGeneral R25-11 [SWS_BSW_91001]과 FO TR Glossary R25-11 4.72. SW-C 종류 이름 "Complex Device Driver"(`autosar-software-component`)는 예외
- channel: 채널 (#257). MCAL I/O 드라이버(ADC·DIO·ICU·OCU·PWM)의 channel일 때. 그 밖의 채널은 "채널". 예: ComM·NM의 채널, FlexRay 채널
- classic: classical (#311). ISO 11898-1:2024를 주어로 한 문장에서 이 판의 이름(약어 CC)을 쓸 때. 위키의 개념 이름 "Classical CAN"은 그대로
- common cause failure: 공통 원인 고장 (#291)
- Communication Management: 통신 관리 (#359). AUTOSAR Adaptive Platform의 functional cluster일 때
- content addressing: 통일하지 않음 (#441). 인용한 출처의 이름대로. CiA의 content addressing은 "내용 주소 지정", Bosch의 content based addressing은 "내용 기반 주소 지정". node addressing도 CiA는 "노드 주소 지정", Bosch는 "노드 기반 주소 지정"
- context: 문맥 (#142)
- context switch: 문맥 전환 (#142)
- counter: 카운터 (#257). OSEK·AUTOSAR OS 객체일 때. 다른 counter는 이 결정에 들지 않는다.
- Cyber Resilience Act: EU 사이버 회복력법 (#438)
- cybersecurity goal: 사이버보안 목표 (#288)
- data-based, behavior-based, rule-based: 데이터 기반 (#385). CTAL-TA 강의계획서의 블랙박스 기법 세 갈래일 때. "데이터 기반 테스트"는 data-driven testing
- Diffie-Hellman: Diffie–Hellman (#288)
- dominant: 도미넌트 (#165). 조사는 원어의 발음대로. 예: "dominant가"
- EdDSA 풀이 Edwards-Curve Digital Signature Algorithm: Edwards-curve Digital Signature Algorithm, Edwards Curve Digital Signature Algorithm (#528)
- edge: 에지 (#257). AUTOSAR 드라이버가 설정과 API로 다루는 edge일 때. 그 밖의 신호 에지는 "에지". 예: CAN 동기화의 에지
- event-triggered: 이벤트 트리거 (#564)
- failure: 실패, 고장, 장애 (#291). 합성어 포함. 예: dependent failure, failure mode, target failure measure. 동사("고장 나다", "실패하다"), 테스트의 pass/fail, 일반 낱말 "실패"는 그대로. ISTQB의 error·defect와 같은 문장, 곧 "실수"나 "결함"과 같은 문장에서는 "장애", 페이지에서 처음 쓸 때 "장애(failure)"
- false positive: 거짓 양성 (#291). ISTQB 용어 이름은 false-positive result
- fault seeding: 결함 심기 (#385)
- GMII 풀이: 통일하지 않음 (#196). 페이지마다 그대로. `mii`는 Gigabit MII, `1000base-t1`은 Gigabit Media Independent Interface
- hardware architectural metrics: 하드웨어 아키텍처 메트릭 (#396). 하위 용어(single-point fault, latent fault 등)도 원어로
- Kanban: 칸반 (#393)
- KDF 풀이 Key Derivation Function: Key-Derivation Function (#498)
- KEM 풀이 Key-Encapsulation Mechanism: Key Encapsulation Mechanism (#498)
- LdCom 풀이 Large Data COM: - (#440). 근거는 SWS BSWGeneral R24-11 부록 A
- MAC 풀이 Medium Access Control: Media Access Control (#165). 출처마다의 풀이를 비교하는 문장은 예외
- notification: 통지 (#257). AUTOSAR 모듈이 부르는 notification 콜백일 때. 동사로 쓴 자리("통지받는다")와 그 밖의 통지는 "통지"
- OBD 풀이 On-Board Diagnostics: On-Board Diagnosis (#496)
- OOPSLA 풀이 Object-Oriented Programming, Systems, Languages, and Applications: Object-Oriented Programming, Systems, Languages & Applications (#291)
- OSEK OS: OSEK/VDX OS (#257). OS를 가리킬 때. 명세를 가리키는 "OSEK/VDX OS"는 그대로. 예: "OSEK/VDX OS 2.2.3 명세"
- PKI: 공개 키 기반 구조 (#498). 제목과 본문은 약어, 한국어 이름은 `public-key-infrastructure`의 alias로만
- prototyping: 프로토타이핑 (#291). prototype도 같다. AUTOSAR의 prototype은 이 결정에 들지 않는다.
- PWM 풀이: 통일하지 않음 (#441). 인용한 출처의 풀이대로. AUTOSAR 명세를 인용하면 Pulse Width Modulation, ISO 11898-1을 인용하면 Pulse-Width Modulation
- recessive: 리세시브 (#165). 조사는 원어의 발음대로. 예: "recessive이고"
- Reed-Solomon: Reed–Solomon (#498)
- resource: 리소스 (#165). OSEK 객체일 때. 일반적인 뜻이면 "자원"
- root of trust: 신뢰의 뿌리 (#288)
- RSA 풀이 Rivest-Shamir-Adleman: Rivest–Shamir–Adleman (#288)
- safety case: - (#396)
- syntax testing: 구문 테스트, 문법 테스트 (#385). "구문 테스트"는 statement testing
- systematic fault: 체계적 fault (#578). systematic failure도 같다. 일반 낱말 "체계적으로"는 그대로
- TDC 풀이 Transceiver Delay Compensation: Transmitter Delay Compensation (#311)
- time-triggered: 시간 트리거 (#564)
- Timing Analysis and Design 보고서: AUTOSAR 타이밍 분석 보고서 (#257). 본문에서 AUTOSAR 문서를 부르는 이름
- Timing Extensions 명세: 타이밍 확장 명세 (#257). 본문에서 AUTOSAR 문서를 부르는 이름. "명세" 없이 쓴 "Timing Extensions"도 그대로
- USART 풀이 Universal Synchronous/Asynchronous Receiver/Transmitter: Universal Synchronous and Asynchronous Receiver Transmitter (#196)
- use case: 유스케이스 (#394). 합성어 포함. 예: use case 테스트
- V2X 풀이 Vehicle-to-X: Vehicle-to-Everything (#257)
- validation: 통일하지 않음 (#288). "확인"과 원어 cybersecurity validation을 맥락에 따라. 페이지 `cybersecurity-verification-and-validation`의 title과 정의는 "확인"
- Virtual A/B: - (#432)
- wakeup: 웨이크업 (#257). AUTOSAR가 다루는 wakeup일 때. 예: EcuM에 알리는 wakeup. 트랜시버와 버스의 웨이크업은 "웨이크업"
- 개인 키: 개인키 (#288)
- 결정 테이블: 결정표 (#441)
- 결함 허용: - (#223)
- 공개 키: 공개키 (#288)
- 기법: technique (#431). Automotive Threat Matrix의 technique일 때
- 길쌈 부호: convolutional 부호, 컨볼루션 부호 (#498). 페이지에서 처음 쓸 때 원어를 병기
- 난수 생성기: random bit generator (#498). RBG는 `random-bit-generator`의 alias로만. DRBG·NRBG 같은 약어의 풀이는 그대로
- 단계적 배포: phased rollout (#432)
- 단위 테스트: 유닛 테스트 (#291)
- 대칭 키: 대칭키 (#288)
- 리스크: 위험 (#441). risk를 옮길 때. 합성어 포함. 예: 리스크 평가, 리스크 주도, 리스크 등급. hazard("위험원", "해저드")와 일반 낱말("위험하다", "충돌 위험", "단편화 위험")은 그대로
- 리프 노드: 잎 노드 (#250)
- 메타모픽 테스트: 변성 테스트 (#385). metamorphic testing일 때. metamorphic relation은 "메타모픽 관계"
- 무작위 테스트: 랜덤 테스트 (#385)
- 변이 테스트: 뮤테이션 테스트 (#385). mutation testing일 때. mutant는 "변이체", equivalent mutant는 "동등 변이체". "뮤테이션 테스트"는 alias로만
- 분류 트리 기법: 분류 트리 방법 (#385)
- 비대칭 키: 비대칭키 (#288)
- 비밀 키: 비밀키 (#288)
- 사용자 스토리: user story (#394). 합성어 포함. 예: 사용자 스토리 매핑
- 사이버보안 속성: cybersecurity property (#252)
- 사전 등록(备案): 备案 (#432). 원문의 간체를 쓴다.
- 생명주기: 수명주기 (#288)
- 서명 키: 서명키 (#288)
- 소스: 원천 (#346). 신호나 사건을 내는 하드웨어·기능일 때. 예: 인터럽트 소스, 클록 소스, 트리거 소스. 802.1AS의 timing source는 원어로. 기원을 뜻하는 일반 낱말 "원천"(원천 문서, 원천 모델)과 검증 자료인 "출처"는 그대로
- 송신 정지: 서스펜드 트랜스미션 (#68). 원어는 병기하지 않는다.
- 신뢰성 성장 모델: 신뢰도 성장 모델 (#385)
- 실수: 오류 (#291). ISTQB의 error(사람의 실수)일 때. 기법 이름 "오류 추정"과 일반적인 error는 "오류"
- 안전 메커니즘: 안전 기제 (#223)
- 암호 primitive: 암호 프리미티브 (#169)
- 에지: 엣지 (#441). 예: DoIP 에지 노드, 에지 브리지
- 엔드 스테이션: 종단국 (#196)
- 오브젝트 코드: 목적 코드 (#401)
- 오브젝트 파일: 목적 파일 (#401)
- 운용 프로파일: 운영 프로파일 (#385)
- 위협 시나리오: threat scenario (#252)
- 인수 기준: 인수 조건 (#385)
- 자산: asset (#252)
- 저속 내결함성 CAN: 저속 결함 허용 CAN (#441). ISO 11898-3의 low-speed, fault-tolerant 매체와 그 트랜시버일 때. 개념 fault tolerance는 "결함 허용"(#223)
- 전술: tactic (#431). Automotive Threat Matrix의 tactic일 때
- 정의의 주석: Note (#566). ISO/IEC Directives를 따르는 문서의 용어 항목에 단 주석(Note # to entry)일 때. 번호는 "정의의 둘째 주석"처럼 쓴다. 본문 NOTE와 ASPICE의 BP·GP Note는 그대로
- 차량 사이버보안: 汽车信息安全 (#431). GB 44495의 汽车信息安全일 때
- 추적표: 추적 매트릭스, 추적성 매트릭스 (#441). traceability matrix일 때. 합성어 포함. 예: 요구사항 추적표
- 취약점 공개: vulnerability disclosure (#431)
- 취약점 처리: vulnerability handling (#431)
- 카나리 릴리스: canary release, 카나리 배포 (#499)
- 타원 곡선 암호: ECC (#289). 타원 곡선 암호를 가리킬 때. ECDSA·ECDH 같은 알고리즘 이름은 그대로. 예: SP 800-56A의 ECC CDH는 "타원 곡선 CDH"
- 태스크 그룹: 태스크 묶음 (#349). OSEK OS 명세의 group of tasks일 때
- 테스트 기준: test basis (#291)
- 테스트 케이스: 시험 사례, 시험 케이스 (#291)
- 트랜시버 지연 보상: 송신 지연 보상 (#311). 약어와 함께 쓰면 `트랜시버 지연 보상(TDC, Transceiver Delay Compensation)`
- 특별특성: special characteristics (#394). 처음 쓸 때 "특별특성(special characteristics)". ASPICE 정보 항목 이름 17-57(Special characteristics)은 그대로
- 특정개조 등: 特定改造等 (#432). 처음 쓸 때 원어를 병기
- 프레임 간 공간: 인터프레임 공간 (#68). 원어는 병기하지 않는다.
- 플래시: Flash (#257). 일반 낱말일 때. 모듈과 구성 요소의 이름(Fls(Flash Driver), Flash EEPROM Emulation, Flashing Adapter)은 예외
- 하위 호환: 역호환 (#257)
- 행위 주도 개발: 행동 주도 개발 (#385)
- 형식 오류: 폼 오류 (#441). CAN의 form error일 때
- 획득자: 구매자 (#394). acquirer일 때. ISO/IEC/IEEE 29148이 acquirer의 다른 이름으로 드는 "구매자"는 그대로
