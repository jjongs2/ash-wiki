# 결정 로그

ADR의 세 기준에 못 미치는 결정과 버린 대안을 한 항목씩 남긴다. 무엇을 쓰는지는 도메인 문서의 [결정 로그](agents/domain.md#결정-로그)가 정한다. 꼴은 `npm run check:trace`가 검사한다.

## 꼴

항목 하나가 불릿 하나다. 새 항목은 끝에 더하고, 지우지 않는다. 표로 두지 않는다. prettier가 열 너비를 맞추며 모든 행을 다시 써서 나란한 PR끼리 충돌하기 때문이다.

```markdown
- D12 채택: <고른 것>. 기각: <버린 것>.
  까닭: <고른 까닭>.
  규칙: [<절>](<경로>#<앵커>). 근거: #<PR이나 이슈>, [<조사 기록>](경로)
```

| 필드    | 쓰는 것                                                                                                                                                                    |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 결정    | ID 뒤에 고른 것. ID는 `D1`부터 매기고, 겹치면 나중에 머지하는 쪽이 고친다. 조사 질문의 판정은 `채택:`·`기각:`·`보류:` 구절로 쓰고, 한 항목에 여럿을 쓸 수 있다             |
| 버린 것 | 고르지 않은 대안. 결정에 `기각:` 구절이 있으면 그것이 대신한다                                                                                                             |
| 까닭    | 고른 까닭. 보류는 다시 볼 조건을 적는다. ADR이나 항목이 없던 규칙을 바꾸면 [원래 까닭](agents/domain.md#결정-로그)을 함께 적는다                                           |
| 규칙    | 바꾸거나 확인한 규칙의 절 링크. 없으면 `없음`                                                                                                                              |
| 근거    | PR, 이슈, 조사 기록 가운데 하나 이상                                                                                                                                       |
| 대체    | 이 항목이 대체한 항목. `대체: D<n>`으로 쓰고, 대체된 항목의 머리에 `(D<m>이 대체)`를 단다. ADR이 항목을 대체하면 `(ADR <n>이 대체)`를 단다. ADR을 뒤집는 결정은 ADR로 쓴다 |

필드는 줄 머리나 문장 끝(`. `) 뒤에 `<필드>: `로 쓴다. 대체된 항목의 머리 표시는 ID 바로 뒤에 둔다. 예: `- D3 (D12이 대체) 채택: …`

## 항목

- D1 채택: ADR의 꼴, 현행 규칙의 정본을 운영 문서에 두는 분리, 세 기준을 그대로 두고, 세 기준에 못 미치는 결정은 결정 로그에 둔다. 기각: ADR 문턱을 "실제 대안 사이에서 골랐다" 하나로 낮추기.
  까닭: 하네스 결정은 문턱과 상관없이 ADR로 오지 않았다. 기록할 대상은 문턱을 낮춰도 같고, 결정마다 ADR 파일을 두면 엔지니어링 스킬이 매번 읽는 색인이 불어난다.
  규칙: [ADR과 운영 문서](agents/domain.md#adr과-운영-문서), [결정 로그](agents/domain.md#결정-로그). 근거: #714, [ADR이 이 저장소의 하네스 결정에 맞는가](research/adr-fit-for-harness-decisions.md)
- D2 채택: ADR의 대체 처리를 그대로 둔다. 기각: 0001\~0006에 정본 줄, 부분 변경 칸, `deprecated` 상태 두기.
  까닭: 0002·0005·0006은 #191이 그대로 두었고, 0001·0003·0004는 #470이 범위 밖에 두었다. 이 길로 들어오는 독자가 적고, 부분 변경 표시에 누락이 없다.
  규칙: [대체됨](adr/README.md#대체됨). 근거: #714, [대체되거나 폐기된 결정](research/superseded-decisions-and-canonical-docs.md)
- D3 채택: 실제 대안 사이에서 고른 규칙 변경은 결정 로그에 남긴다. 기각: squash 메시지에 대안 옮기기.
  까닭: #609 뒤 머지된 docs·feat PR 23건(#710 포함)의 본문에 대안이 없다. 커밋 메시지는 이력이라 찾으러 가야 보이고 검사할 링크가 없다.
  규칙: [ADR과 운영 문서](agents/domain.md#adr과-운영-문서), [결정 로그](agents/domain.md#결정-로그). 근거: #714, [작은 결정과 그 대안](research/minor-decisions-and-alternatives.md)
- D4 채택: 결정 로그 안의 검사와, `content/` 밖 Markdown의 상대 링크·앵커 존재 검사를 `npm run check`에 둔다. 기각: `검사 <id>` 표지 짝 검사, PR 본문의 `결정 로그:` 줄을 CI로 보는 검사.
  까닭: 조사 기록의 인용 셀에서 깨진 상대 링크 3곳이 나왔다. 표지 13종은 검사 id와 모두 맞는다. 본문 검사는 `CONTRIBUTING.md`의 "PR 제목·본문 검사는 두지 않습니다"와 부딪치고, 규칙 파일을 고치는 content PR과 Dependabot PR을 막으므로 그 줄은 리뷰가 본다.
  규칙: [결정 로그](agents/domain.md#결정-로그). 근거: #714, [결정, 규칙, 근거를 잇는 추적성](research/decision-rule-traceability.md)
- D5 채택: 목록 사본은 정본 표를 코드가 읽는 기존 방식을 쓴다. 기각: 사본 찾기와 생성.
  까닭: 산문 사본은 결정적으로 잡지 못하고, 조사가 든 줄 사본의 어긋남은 #451 직전의 것이다.
  규칙: [원칙](../CONTRIBUTING.md#원칙). 근거: #714, [같은 규칙의 사본](research/rule-copy-drift.md)
- D6 기각: 백틱 경로, 참조 깊이, 모순 검사.
  까닭: 스킬과 에이전트 문서의 백틱 경로 154곳에 없는 경로가 없고, 깊이 때문에 규칙을 놓친 사례가 없다. 모순 검사는 오탐을 내고 보고만 한다.
  규칙: 없음. 근거: #714, [에이전트가 읽는 문서의 일관성](research/agent-doc-consistency.md)
- D7 하네스 조사의 조사 기록과 출처 목록은 공개 저장소의 `docs/research/`에 둔다.
  버린 것: 저장소 밖의 비공개 자리에 두기.
  까닭: 독자는 규칙을 고치려는 사람과 에이전트라, 결정 로그와 규칙이 링크로 가리키고 검사기가 볼 수 있는 자리여야 한다. 들일 수 있는 것은 데이터 경계가 정한다.
  규칙: [데이터 경계](research/README.md#데이터-경계). 근거: #711, #710
- D8 기존 규칙에 결정 기록을 미리 소급하지 않는다. 항목을 쓰는 변경이 ADR이나 항목이 없는 규칙을 바꿀 때만 `git blame`으로 원래 까닭을 찾아 적는다.
  버린 것: 기존 규칙의 일괄 소급.
  까닭: 까닭은 규칙을 바꿀 때 필요하고, 바꾸지 않는 규칙의 까닭은 읽힐 일이 없다. 대안 없는 문구 고침에는 찾은 까닭을 적을 자리가 없어 원래 까닭 찾기를 걸지 않는다.
  규칙: [결정 로그](agents/domain.md#결정-로그). 근거: #711, #714
- D9 결정 로그, 원래 까닭 찾기, 추적성 검사는 콘텐츠 규칙을 포함한 모든 규칙 변경에 쓴다. 표기 결정은 [용어 표기 결정](wiki-terms.md)이 그대로 맡는다.
  버린 것: 하네스 규칙에만 쓰기.
  까닭: 콘텐츠 규칙도 실제 대안 사이에서 고르고, 세 기준에 못 미치면 하네스 규칙과 같이 대안이 남지 않는다. 분야마다 기록 자리를 따로 두면 규칙을 바꾸는 사람이 어디를 볼지 갈린다.
  규칙: [결정 로그](agents/domain.md#결정-로그). 근거: #711
