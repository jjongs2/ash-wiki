# 팔레트

사이트의 색과 폰트, 도해 팔레트를 고른 근거와 대비 실측입니다. 값은 여기에 옮겨 적지 않고, 정본이 있는 곳을 토큰 이름으로 가리킵니다.

| 값                                   | 정본                                                   |
| ------------------------------------ | ------------------------------------------------------ |
| 사이트 색, 폰트 이름                 | `quartz.config.yaml`의 `configuration.theme`           |
| 도해 색                              | [위키 규약](wiki-conventions.md#도해)의 도해 팔레트 표 |
| 웹 폰트 파일의 출처, Pretendard 버전 | `quartz/util/localFonts.ts`                            |

## 방향

`/design-taste-frontend`로 시안 셋(청사진, 신호등, 계기판)을 만들고, 라이트·다크로 나란히 그린 아티팩트로 보여 드려 소유자가 청사진을 골랐습니다(2026-09-25).

- 긴 한국어 기술 문서를 읽는 사이트라 장식보다 읽기를 앞에 둡니다.
- 무채색은 푸른 기가 조금 도는 슬레이트입니다. 순백과 순흑 대신 슬레이트 쪽으로 기운 흰색과 검정을 씁니다.
- 강조색은 코발트 하나이고, 링크와 인용 번호에 씁니다.
- 다크 테마는 반전이 아닙니다. 같은 색상에서 밝기만 옮기고, 강조색은 어두운 배경에서 읽히도록 밝힌 코발트를 씁니다.

## 토큰

| 토큰            | 쓰는 곳                              |
| --------------- | ------------------------------------ |
| `light`         | 페이지 배경                          |
| `lightgray`     | 테두리, 구분선, 인라인 코드 배경     |
| `gray`          | 보조 글자(날짜, 캡션, 경로 표시)     |
| `darkgray`      | 본문                                 |
| `dark`          | 제목, 인라인 코드 글자               |
| `secondary`     | 링크, 인용 번호, 주간 소식의 주요 칩 |
| `tertiary`      | 링크 hover                           |
| `highlight`     | 내부 링크와 태그의 배경(반투명)      |
| `textHighlight` | 형광펜 표시(`==`)의 배경(반투명)     |

## 구역 색

구역마다 색 토큰 하나(`region-<구역>`)를 두고, 구역에 들지 않는 것(주간 소식의 기타 묶음 등)에는 중립색 `region-other`를 씁니다. 값의 정본은 `quartz.config.yaml`의 `theme.colors`이고, 사이트에는 CSS 변수(`--region-<구역>`)로 실립니다. 구역은 태그 경로의 첫 마디이고, 토큰이 없는 구역은 `region-other`로 칠합니다.

| 토큰                    | 구역              |
| ----------------------- | ----------------- |
| `region-network`        | 네트워크          |
| `region-platform`       | 소프트웨어 플랫폼 |
| `region-security`       | 보안·업데이트     |
| `region-sw-engineering` | 소프트웨어 공학   |
| `region-other`          | 기타              |

- 대문의 구역 표(`plugins/front-page`), 주간 소식의 구역 칩·거르기 칩(`plugins/weekly-news`, 구역 칩은 대문의 주간 소식 칸에도 보임), 그래프의 노드(`plugins/graph`)가 씁니다. 같은 구역은 어디서나 같은 색입니다.
- 색상은 도해의 범주 색(청록, 자주, 다홍, 호박)에서 가져오고, 밝기만 옮겨 글자로 읽히게 했습니다. 링크 색인 코발트는 쓰지 않아 구역 이름이 링크 색과 섞이지 않습니다. `region-other`는 보조 글자(`gray`)와 같은 값입니다.
- 구역 이름은 글자이므로 링크와 같은 4.5:1을 하한으로 둡니다. 그래프 노드처럼 글자가 아닌 쓰임은 3:1이면 되므로 이 하한으로 함께 덮입니다.
- 색만으로 구역을 가르지 않습니다. 구역 표와 칩에는 구역 이름이 함께 적힙니다. global graph는 구역 영역에 구역 이름을 적습니다. local graph 노드의 색은 덧붙인 길잡이이고, 노드는 페이지 제목으로 알아봅니다.

### 새 구역에 색을 더할 때

1. `quartz.config.yaml`의 `theme.colors`에서 `lightMode`와 `darkMode`에 `region-<구역>`을 하나씩 더합니다. `<구역>`은 태그 경로의 첫 마디(`content/tags/<구역>.md`의 파일 이름)입니다.
2. 색상은 다른 구역 색, 링크 색(`secondary`)과 떨어진 것을 고르고, 밝기는 `light` 대비가 하한을 조금 넘도록 맞춥니다. 라이트는 어둡게, 다크는 밝게 옮깁니다.
3. `npm run palette`를 돌립니다. 대비 하한 표의 `<구역>` 줄이 새 토큰을 함께 잽니다. 하한을 넘기면 이 문서의 실측 표를 출력으로 바꾸고, 위 토큰 표에 한 줄을 더합니다.
4. 빌드한 대문에서 두 테마의 구역 표를 봅니다.

## 대비 하한

`npm run palette`가 이 표를 읽어 두 테마에서 대비를 재고, 하한에 못 미치면 exit 1입니다. CI는 돌리지 않습니다. 색을 바꿀 때 사람이 돌립니다. `전경`과 `배경`은 theme 색 토큰이거나 도해 팔레트 표의 이름입니다. `<색>`은 범주 색 다섯(`-tint` 짝이 있는 이름)으로, `<구역>`은 theme의 구역 색(`region-`으로 시작하는 토큰)으로 풀고, 한 줄의 두 칸에 모두 있으면 같은 색끼리 짝지어 잽니다. 반투명한 배경은 `light` 위에 합성해서 잽니다. `<토큰> 8%`는 그 색을 8% 불투명도로 깐 배경(`color-mix(in srgb, <색> 8%, transparent)`)입니다.

- 본문, 제목, 코드는 7:1(WCAG 1.4.6, AAA)입니다. 긴 글을 읽는 사이트라 AA보다 높게 둡니다.
- 링크와 보조 글자는 4.5:1(WCAG 1.4.3, AA)입니다. 구역 이름, 구역 칩, 주제 칩의 페이지 수도 같습니다.
- 구역 칩의 바탕은 구역 색 8%입니다. 12%에서는 라이트 테마의 `region-security`와 `region-other`가 4.37:1로 하한에 못 미쳐, 내부 링크 바탕(`highlight`)과 같은 불투명도로 낮췄습니다. 같은 까닭으로 주간 소식의 거르기 칩은 hover에서 바탕을 진하게 하지 않습니다(16%에서 라이트 테마의 구역 색 다섯이 4.12\~4.26:1).
- 도해의 선, 외곽선, 테두리는 3:1(WCAG 1.4.11, 비텍스트 대비)입니다. 테두리는 배경과 제 면 모두에 대해 3:1을 넘어야 도형의 경계가 보입니다.
- 도해 글자는 본문처럼 7:1입니다. 도해가 테마마다 값을 받으므로(`plugins/diagram-theme`), 한 색으로 두 배경을 버틸 때의 상한(약 4.2:1)에 묶이지 않습니다.
- 콜아웃(`note`, `warning`)의 색은 엔진(`quartz/styles/callouts.scss`)의 기본값을 그대로 쓰고, 이 표에 넣지 않습니다. 설정의 색 토큰에는 경고색 자리가 없고, 소유자가 지금 모양을 유지하기로 했습니다(2026-09-25). 라이트 테마의 제목 글자 대비는 `note` 3.18:1, `warning` 2.62:1입니다.
- 탐색기에서 페이지가 없는 구역과 주제의 이름은 `gray`를 투명도 0.6으로 흐려 보조 글자의 하한에 못 미칩니다. 라이트 테마에서 `gray`와 `darkgray`가 잘 갈리지 않아, 소유자가 굵기 대신 투명도로 구별하기로 했습니다(2026-09-30). 대비는 라이트 2.41:1, 다크 3.09:1입니다.

## 폰트

제목과 본문은 Pretendard, 코드는 IBM Plex Mono입니다.

- 시안 청사진은 IBM Plex Sans KR이었습니다. 그런데 Google Fonts판에는 `Æ`와 `Ω`가 없어, 빌드한 OG 이미지에서 사이트 이름이 ` wiki`로 찍혔습니다. 소유자가 Pretendard로 바꿨습니다.
- Pretendard는 한글 11,172자와 `Æ`, `Ω`를 모두 가집니다. 라틴 글자는 Inter를 바탕으로 합니다.
- IBM Plex Mono에는 한글이 없습니다. 코드 안의 한글(주석 등)은 시스템 폰트로 대체됩니다.

폰트 파일은 두 경로로 받습니다.

- 웹: `theme.fontOrigin`이 `local`이라 코어는 폰트를 불러오지 않습니다. `Head`가 `theme.typography`의 폰트마다 CSS를 겁니다(`quartz/util/localFonts.ts`). Pretendard는 Google Fonts에 없어 공식 배포처인 jsDelivr에서, 나머지는 Google Fonts에서 받습니다.
- OG 이미지: 생성기(`@quartz-community/og-image`)는 `theme.typography`의 `header`(700)와 `body`(400)를 Google Fonts에서만 받고, 받기 전에 `quartz/.quartz-cache/fonts/<이름>-<굵기>`를 먼저 읽습니다. prebuild의 `npm run og-fonts`(`tools/og-fonts.ts`)가 `header`나 `body`가 Pretendard이면 웹 폰트와 같은 버전의 OTF를 그 자리에 둡니다. 없으면 한글이 없는 시스템 폰트로 넘어가 두부가 찍힙니다.

`@quartz-community/quartz-fonts` 플러그인은 끕니다. 이 플러그인은 `theme.typography`를 읽지 않고 자기 기본값(Schibsted Grotesk 등)으로 제목의 `font-family`를 덮어써, 폰트의 정본이 둘이 됩니다.

## 도해 팔레트

도해는 배경이 투명한 SVG 한 벌을 라이트·다크 두 테마에서 함께 씁니다. 규칙은 [위키 규약](wiki-conventions.md#도해의-색)에 있습니다.

- 도해는 `<object>`로 들어가 사이트 테마를 모릅니다. 로컬 플러그인(`plugins/diagram-theme`)의 스크립트가 도해 문서의 루트에 현재 테마의 토큰 값을 넣습니다. 칠하는 때는 도해를 불러올 때(첫 로드, SPA 이동, 팝오버), 테마를 바꿀 때(`themechange`), SPA 이동이 끝날 때(`nav`)입니다. 칠하기 전의 도해는 가려서, 대체값으로 먼저 그려진 모습이 보이지 않게 합니다.
- 예전에는 한 색이 두 배경을 함께 버텨야 해서 대비 상한이 약 4.2:1이었고, 도형 밖의 글자가 보조 글자(`gray`)보다도 흐렸습니다. 이제 도해 글자는 본문 글자 색(`darkgray`)을 씁니다.
- 예전에는 범주를 진한 면에 흰 글자로 칠했습니다. 면이 두 배경에서 3:1을 넘고 흰 글자가 면 위에서 4.5:1을 넘는 밝기는 좁은 띠(상대 휘도 약 0.13\~0.17)여서, 다섯 색의 밝기가 같았습니다. 그래서 색각 이상에서는 범주가 거의 갈리지 않았습니다.
- 이제 범주는 옅은 면과 색 테두리로 칠합니다. 글자 대비는 옅은 면이 맡으므로, 테두리의 밝기는 색마다 벌릴 수 있습니다. 가장 가까운 두 범주 색의 거리(Machado 2009 시뮬레이션, 심도 1, OKLab 거리의 100배)는 아래와 같습니다. 제3색각 이상은 여전히 가깝지만, 드문 유형이고 범주는 라벨로도 적습니다.

| 색                  | 제1색각 이상 | 제2색각 이상 | 제3색각 이상 |
| ------------------- | ------------ | ------------ | ------------ |
| 예전 채움           | 3.1          | 4.3          | 2.7          |
| 테두리, 라이트 테마 | 9.7          | 9.0          | 3.6          |
| 테두리, 다크 테마   | 9.6          | 11.4         | 4.0          |

- 범주 색은 Okabe-Ito 계열(호박, 파랑, 청록, 다홍, 자주)입니다. 토큰 이름(`orange`, `blue`, `green`, `red`, `violet`)은 도해를 고치지 않도록 그대로 둡니다.
- 라이트 테마의 `orange`는 제 면(`orange-tint`)과의 대비가 2.95:1이어서, 소유자가 조금 어둡게 해 3:1을 넘기기로 했습니다(2026-09-30).
- 대체값은 예전 팔레트입니다. 스크립트가 돌지 않는 곳에서 도해가 예전 모습으로 그려지게 합니다. 그래서 `surface`의 대체값은 `none`이고, 범주 면의 대체값은 예전 채움 색입니다.
- `text`, `on-fill`, `surface`는 사이트 색 토큰(`darkgray`, `lightgray`)을 가리킵니다. 스크립트가 사이트 문서의 계산된 CSS 변수에서 읽으므로 값을 옮겨 적지 않습니다.

## 바꿀 때

1. `quartz.config.yaml`의 `theme`나 위키 규약의 도해 팔레트 표를 고칩니다.
2. `npm run palette`로 하한을 확인하고, 이 문서의 실측 표를 출력으로 바꿉니다.
3. `npm run build` 뒤 로컬 프리뷰에서 두 테마를 보고, `public/`의 OG 이미지(`*-og-image.webp`)에 두부가 없는지 봅니다. `--serve`로 볼 때는 `OG_IMAGES=1`을 줍니다([배포](deploy.md#로컬-프리뷰)). 폰트를 바꿨다면 한글, `Æ`, `Ω`가 폰트에 있는지도 봅니다.
