# 팔레트

사이트의 색과 폰트, 도해 팔레트를 고른 근거와 대비 실측이다. 값은 여기에 옮겨 적지 않고, 정본이 있는 곳을 토큰 이름으로 가리킨다.

| 값                                  | 정본                                                     |
| ----------------------------------- | -------------------------------------------------------- |
| 사이트 색, 폰트 이름                | `quartz.config.yaml`의 `configuration.theme`             |
| 도해 색                             | [도해 규약](wiki-diagrams.md#도해의-색)의 도해 팔레트 표 |
| 웹 폰트 파일의 출처                 | `quartz/util/localFonts.ts`                              |
| 코드 폰트의 버전, 저작권과 라이선스 | `quartz/static/fonts/monoplex-kr/`                       |

## 방향

`/design-taste-frontend`로 시안 셋(청사진, 신호등, 계기판)을 만들고, 라이트·다크로 나란히 그린 아티팩트로 보여 주자 소유자가 청사진을 골랐다(2026-09-25).

- 긴 한국어 기술 문서를 읽는 사이트라 장식보다 읽기를 앞에 둔다.
- 무채색은 푸른 기가 조금 도는 슬레이트다. 순백과 순흑 대신 슬레이트 쪽으로 기운 흰색과 검정을 쓴다.
- 강조색은 코발트 하나이고, 링크와 인용 번호에 쓴다.
- 다크 테마는 반전이 아니다. 같은 색상에서 밝기만 옮기고, 강조색은 어두운 배경에서 읽히도록 밝힌 코발트를 쓴다.

대문 시안 일곱을 견줘, 소유자가 지금 꼴을 유지하고 왼쪽 사이드바를 남색 면으로 칠하는 안을 골랐다(2026-10-25). 칩 바탕을 빼거나 무채로 덜어 낸 넷보다 지금 꼴이 낫고, 힘을 준 셋(코발트로 채운 칩, 구역 색 칩, 남색 사이드바) 가운데 남색 사이드바를 골랐다.

## 토큰

| 토큰            | 쓰는 곳                                                             |
| --------------- | ------------------------------------------------------------------- |
| `light`         | 페이지 배경                                                         |
| `lightgray`     | 테두리, 구분선, 인라인 코드 배경                                    |
| `gray`          | 보조 글자(날짜, 캡션, 경로 표시)                                    |
| `darkgray`      | 본문                                                                |
| `dark`          | 제목, 인라인 코드 글자                                              |
| `secondary`     | 링크, 인용 번호, 주간 소식의 주요 칩, 도착한 카드의 막대, 포커스 링 |
| `tertiary`      | 링크 hover                                                          |
| `highlight`     | 칩 모양 링크와 태그의 배경(반투명)                                  |
| `textHighlight` | 형광펜 표시(`==`)와 검색어 강조의 배경(반투명)                      |
| `narrow-toc`    | 좁은 화면 목차 바의 배경([목차 바](#목차-바))                       |

## 구역 색

구역마다 색 토큰 하나(`region-<구역>`)를 두고, 구역에 들지 않는 것(주간 소식의 기타 묶음 등)에는 중립색 `region-other`를 쓴다. 값의 정본은 `quartz.config.yaml`의 `theme.colors`이고, 사이트에는 CSS 변수(`--region-<구역>`)로 실린다. 구역은 태그 경로의 첫 마디이고, 토큰이 없는 구역은 `region-other`로 칠한다.

| 토큰                    | 구역              |
| ----------------------- | ----------------- |
| `region-network`        | 네트워크          |
| `region-platform`       | 소프트웨어 플랫폼 |
| `region-security`       | 보안·업데이트     |
| `region-sw-engineering` | 소프트웨어 공학   |
| `region-other`          | 기타              |

- 대문의 구역 표(`plugins/front-page`), 주간 소식의 구역 칩·거르기 칩(`plugins/weekly-news`, 구역 칩은 대문의 주간 소식 칸에도 보임), 그래프의 노드(`plugins/graph`)가 쓴다. 같은 구역은 어디서나 같은 색이다.
- 색상은 도해의 범주 색(청록, 자주, 다홍, 호박)에서 가져오고, 밝기만 옮겨 글자로 읽히게 했다. 링크 색인 코발트는 쓰지 않아 구역 이름이 링크 색과 섞이지 않는다. `region-other`는 보조 글자(`gray`)와 같은 값이다.
- 구역 이름은 글자이므로 링크와 같은 4.5:1을 하한으로 둔다. 그래프 노드처럼 글자가 아닌 쓰임은 3:1이면 되므로 이 하한으로 함께 덮인다.
- 색만으로 구역을 가르지 않는다. 구역 표와 칩에는 구역 이름이 함께 적힌다. global graph는 구역 영역에 구역 이름을 적는다. local graph 노드의 색은 덧붙인 길잡이이고, 노드는 페이지 제목으로 알아본다.

### 새 구역에 색을 더할 때

1. `quartz.config.yaml`의 `theme.colors`에서 `lightMode`와 `darkMode`에 `region-<구역>`을 하나씩 더한다. `<구역>`은 태그 경로의 첫 마디(`content/tags/<구역>.md`의 파일 이름)이다.
2. 색상은 다른 구역 색, 링크 색(`secondary`)과 떨어진 것을 고르고, 밝기는 `light` 대비가 하한을 조금 넘도록 맞춘다. 라이트는 어둡게, 다크는 밝게 옮긴다.
3. `npm run palette`를 돌린다. 대비 하한 표의 `<구역>` 줄이 새 토큰을 함께 잰다. 하한을 넘기면 이 문서의 실측 표를 출력으로 바꾸고, 위 토큰 표에 한 줄을 더한다.
4. 빌드한 대문에서 두 테마의 구역 표를 본다.

## 사이드바 면

왼쪽 사이드바(폰에서는 머리 줄)는 남색 면이다. 면 안에서는 `sidebar-<토큰>`이 토큰 표의 `<토큰>`을 대신한다. 값의 정본은 `quartz.config.yaml`의 `theme.colors`이고, 사이트에는 CSS 변수(`--sidebar-<토큰>`)로 실린다.

- 값은 대문 시안의 값이다. 면(`sidebar-light`)은 라이트에서 짙은 남색이고, 다크에서는 페이지 바탕과 갈리도록 한 단계 밝은 남색이다. 다크의 면은 시안 값(페이지와 1.20:1)이 잘 갈리지 않아, 소유자가 면 위 쌍이 하한을 넘는 안에서 더 밝히기로 했다(2026-10-25, 페이지와 1.38:1). `sidebar-lightgray`도 함께 올려 면과의 단차를 지켰다.
- 면이 두 테마 모두 어두워, 면 위의 글자는 밝게 쓰고 두 테마에 같은 값을 쓴다. 면 위 링크(`sidebar-secondary`)는 페이지 링크와 색상이 같은 코발트를 밝힌 것이고, 면 위 회색 토큰은 면의 남색 쪽으로 기운다.
- 탐색기의 주제 이름과 페이지 항목은 본문색(`sidebar-darkgray`)이 아니라 제목색(`sidebar-dark`)으로 쓴다. 본문색은 면 위에서 한 단계 흐려 사이트 이름과 구역 이름 아래의 항목이 묻혀, 소유자가 흰색으로 바꿨다(2026-10-25).

## 페이지 바깥

넓은 화면(1500px 초과)에서는 사이드바 면, 본문, 오른쪽 사이드바가 1500px 페이지 하나로 화면 가운데에 서고, 페이지 바깥은 `outside`로 칠한다. 값의 정본은 `quartz.config.yaml`의 `theme.colors`이고, 사이트에는 CSS 변수(`--outside`)로 실린다.

- 시안을 견줘 소유자가 골랐다(2026-10-27). 위키백과처럼 테두리와 그림자 없이 톤 차이로만 페이지를 가른다. 면을 화면 왼쪽 끝부터 칠하던 배치는 1920px에서 본문 왼쪽에 245px, 오른쪽에 37px이 비어 본문이 오른쪽 사이드바에 붙어 보였다. 바깥을 면의 남색으로 칠하지 않아, 페이지를 가운데로 모아도 왼쪽에 빈 남색 띠가 생기지 않는다.
- 두 테마 모두 페이지 바탕(`light`)보다 한 톤 어둡다. 대비는 `light`와 라이트 1.15:1, 다크 1.05:1이고, 사이드바 면(`sidebar-light`)과 12.18:1, 1.45:1이다.
- 대비 하한 표에는 넣지 않는다. 바깥은 글자나 경계가 아닌 빈 바탕이라, 내용을 알아보는 데 필요한 비텍스트 대비(WCAG 1.4.11)에 들지 않는다.

## 목차 바

데스크톱보다 좁은 화면(폰, 태블릿)의 목차 바는 `narrow-toc`로 칠하고, 아래 1px `lightgray` 테두리로 본문과 가른다. 값의 정본은 `quartz.config.yaml`의 `theme.colors`이고, 사이트에는 CSS 변수(`--narrow-toc`)로 실린다.

- 그림자 없이 톤으로만 가른다(소유자 결정, 2026-11-06). 라이트는 페이지 바탕(`light`)보다 한 톤 어둡고(`light`와 `lightgray`의 중간), 다크는 한 톤 밝다. `light`와의 대비는 라이트 1.09:1, 다크 1.09:1로, 다크에서도 라이트만큼 갈린다.
- 바 위의 글자는 보조 글자색의 `목차` 이름표와 제목색의 지금 절 이름이다. 열린 목록의 항목도 같은 두 색이라, 대비 하한 표의 두 쌍이 함께 잰다.

## 대비 하한

`npm run palette`가 이 표를 읽어 두 테마에서 대비를 재고, 하한에 못 미치면 exit 1이다. CI는 돌리지 않는다. 색을 바꿀 때 사람이 돌린다. `전경`과 `배경`은 theme 색 토큰이거나 도해 팔레트 표의 이름이다. `<색>`은 범주 색 다섯(`-tint` 짝이 있는 이름)으로, `<구역>`은 theme의 구역 색(`region-`으로 시작하는 토큰)으로 풀고, 한 줄의 두 칸에 모두 있으면 같은 색끼리 짝지어 잰다. 반투명한 배경은 그 배경이 놓인 면에 합성해서 잰다. `sidebar-`로 시작하는 토큰은 사이드바 면(`sidebar-light`) 위, 나머지는 `light` 위다. `<토큰> 8%`는 그 색을 8% 불투명도로 깐 배경(`color-mix(in srgb, <색> 8%, transparent)`)이다.

- 본문, 제목, 코드는 7:1(WCAG 1.4.6, AAA)이다. 긴 글을 읽는 사이트라 AA보다 높게 둔다. 면 위 쌍과 목차 바 위 쌍도 페이지의 같은 쌍과 하한이 같다.
- 링크와 보조 글자는 4.5:1(WCAG 1.4.3, AA)이다. 구역 이름, 구역 칩, 주제 칩의 페이지 수도 같다.
- 구역 칩의 바탕은 구역 색 8%이다. 12%에서는 라이트 테마의 `region-security`와 `region-other`가 4.37:1로 하한에 못 미쳐, 칩 바탕(`highlight`)과 같은 불투명도로 낮췄다. 같은 까닭으로 주간 소식의 거르기 칩은 hover에서 바탕을 진하게 하지 않는다(16%에서 라이트 테마의 구역 색 다섯이 4.12\~4.26:1).
- 포커스 링과 도해의 선, 외곽선, 테두리는 3:1(WCAG 1.4.11, 비텍스트 대비)이다. 테두리는 배경과 제 면 모두에 대해 3:1을 넘어야 도형의 경계가 보인다.
- 도해 글자는 본문처럼 7:1이다. 도해가 테마마다 값을 받으므로(`plugins/diagram-theme`), 한 색으로 두 배경을 버틸 때의 상한(약 4.2:1)에 묶이지 않는다.
- 콜아웃(`note`, `warning`)의 색은 엔진(`quartz/styles/callouts.scss`)의 기본값을 그대로 쓰고, 이 표에 넣지 않는다. 설정의 색 토큰에는 경고색 자리가 없고, 소유자가 지금 모양을 유지하기로 했다(2026-09-25). 라이트 테마의 제목 글자 대비는 `note` 3.18:1, `warning` 2.62:1이다.
- 탐색기에서 페이지가 없는 구역과 주제의 이름은 `sidebar-gray`를 투명도 0.6으로 흐려 면 위 보조 글자의 하한에 못 미친다. 보조 글자색과 본문색이 잘 갈리지 않아, 소유자가 굵기 대신 투명도로 구별하기로 했다(2026-09-30). 그때는 라이트 테마의 `gray`와 `darkgray`가 둘 다 어두웠고, 면 위의 `sidebar-gray`와 탐색기 항목의 `sidebar-dark`는 둘 다 밝다. 대비는 라이트 3.35:1, 다크 3.21:1이다.

## 폰트

제목과 본문은 IBM Plex Sans와 IBM Plex Sans KR, 코드는 Monoplex KR이다. 다른 문서와 견준 시안에서 소유자가 골랐다(2026-10-27).

- 라틴, 그리스 문자, 기호는 IBM Plex Sans로, 한글은 IBM Plex Sans KR로 그린다. Google Fonts판 IBM Plex Sans KR에는 `Æ`, `µ`, `Ω`, `Δ`, `≈`와 라틴 악센트 글자가 없다. 두 폰트의 ASCII 글자는 폭과 모양이 같다.
- 숫자는 고정폭(0.6em)이다. IBM Plex는 700까지만 있어 사이트 이름도 700이다.
- Monoplex KR은 IBM Plex Mono(라틴)와 IBM Plex Sans KR(한글)을 합친 고정폭 폰트로, 한글 폭이 라틴의 두 배다. 라틴 폭은 IBM Plex Mono의 0.88배다.
- 1배 화면의 Linux에서는 브라우저가 글자 폭을 정수 px로 반올림해 영문 사이가 조금 벌어진다(16px의 `tttt`가 22.05px 대신 24px, 보통 단어는 1% 안). 눈으로 갈리지 않아 본문에 `text-rendering: geometricPrecision`을 걸지 않는다.

예전 결정은 아래와 같았다.

- 시안 청사진은 IBM Plex Sans KR이었다. 그런데 Google Fonts판에는 `Æ`와 `Ω`가 없어, 빌드한 OG 이미지에서 사이트 이름이 ` wiki`로 찍혔다. 소유자가 Pretendard로 바꿨다.
- Pretendard는 한글 11,172자와 `Æ`, `Ω`를 모두 담고 있었다. 코드 폰트 IBM Plex Mono에는 한글이 없어, 코드 안의 한글(주석 등)은 시스템 폰트로 대체됐다.

폰트 파일은 세 경로로 받는다.

- 웹: `theme.fontOrigin`이 `local`이라 코어는 폰트를 불러오지 않는다. `Head`가 `theme.typography`의 폰트마다 CSS를 건다(`quartz/util/localFonts.ts`). 제목과 본문 폰트는 Google Fonts에서 받는다.
- 코드 폰트: Monoplex KR은 Google Fonts에도 jsDelivr에도 없고, GitHub 릴리스의 zip(TTF)만 있다. 릴리스 v1.1.0의 TTF를 WOFF2로 압축만 해(fontTools `woff2.compress`) 코드가 쓰는 굵기 400, 600, 700을 `quartz/static/fonts/monoplex-kr/`에 싣는다.
- OG 이미지와 도해 여백 검사: 생성기(`@quartz-community/og-image`)는 `theme.typography`의 `header`(700)와 `body`(400)를 Google Fonts에서 받고, 받기 전에 `quartz/.quartz-cache/fonts/<이름>-<굵기>`를 먼저 읽는다. prebuild의 `npm run og-fonts`(`tools/og-fonts.ts`)가 웹과 같은 css2 API에서 굵기별 TTF를 받아 그 자리에 둔다. 받은 주소에 판이 들어 있어, Google Fonts가 판을 올리면 새로 받는다. 이름이 여럿인 역할은 생성기가 모두 싣도록 패치했다.

Monoplex KR의 라이선스는 SIL OFL 1.1이고, "Monoplex", "Plex", "PlemolJP"가 예약 폰트 이름이다. 폰트 데이터를 바꾸지 않고 WOFF2로 압축만 한 파일은 수정본이 아니어서 이름을 그대로 쓴다([OFL FAQ 2.2.1](https://openfontlicense.org/ofl-faq/)). 다시 풀면 `head`의 checkSumAdjustment와 flags 11번 비트(WOFF2 규격이 압축할 때 고치는 값) 말고는 원본과 같다. 서브셋으로 쪼개면 수정본이 되어(FAQ 2.6) 예약 이름을 쓸 수 없으므로 쪼개지 않는다.

`@quartz-community/quartz-fonts` 플러그인은 끈다. 이 플러그인은 `theme.typography`를 읽지 않고 자기 기본값(Schibsted Grotesk 등)으로 제목의 `font-family`를 덮어써, 폰트의 정본이 둘이 된다.

## 도해 팔레트

도해는 배경이 투명한 SVG 한 벌을 라이트·다크 두 테마에서 함께 쓴다. 규칙은 [도해 규약](wiki-diagrams.md#도해의-색)에 있다.

- 도해는 `<object>`로 들어가 사이트 테마를 모른다. 로컬 플러그인(`plugins/diagram-theme`)의 스크립트가 도해 문서의 루트에 현재 테마의 토큰 값을 넣는다. 칠하는 때는 도해를 불러올 때(첫 로드, SPA 이동, 팝오버), 테마를 바꿀 때(`themechange`), SPA 이동이 끝날 때(`nav`)이다. 칠하기 전의 도해는 가려서, 대체값으로 먼저 그려진 모습이 보이지 않게 한다.
- 예전에는 한 색이 두 배경을 함께 버텨야 해서 대비 상한이 약 4.2:1이었고, 도형 밖의 글자가 보조 글자(`gray`)보다도 흐렸다. 이제 도해 글자는 본문 글자 색(`darkgray`)을 쓴다.
- 예전에는 범주를 진한 면에 흰 글자로 칠했다. 면이 두 배경에서 3:1을 넘고 흰 글자가 면 위에서 4.5:1을 넘는 밝기는 좁은 띠(상대 휘도 약 0.13\~0.17)여서, 다섯 색의 밝기가 같았다. 그래서 색각 이상에서는 범주가 거의 갈리지 않았다.
- 이제 범주는 옅은 면과 색 테두리로 칠한다. 글자 대비는 옅은 면이 맡으므로, 테두리의 밝기는 색마다 벌릴 수 있다. 가장 가까운 두 범주 색의 거리(Machado 2009 시뮬레이션, 심도 1, OKLab 거리의 100배)는 아래와 같다. 제3색각 이상은 여전히 가깝지만, 드문 유형이고 범주는 라벨로도 적는다.

| 색                  | 제1색각 이상 | 제2색각 이상 | 제3색각 이상 |
| ------------------- | ------------ | ------------ | ------------ |
| 예전 채움           | 3.1          | 4.3          | 2.7          |
| 테두리, 라이트 테마 | 9.7          | 9.0          | 3.6          |
| 테두리, 다크 테마   | 9.6          | 11.4         | 4.0          |

- 범주 색은 Okabe-Ito 계열(호박, 파랑, 청록, 다홍, 자주)이다. 토큰 이름(`orange`, `blue`, `green`, `red`, `violet`)은 도해를 고치지 않도록 그대로 둔다.
- 라이트 테마의 `orange`는 제 면(`orange-tint`)과의 대비가 2.95:1이어서, 소유자가 조금 어둡게 해 3:1을 넘기기로 했다(2026-09-30).
- 대체값은 예전 팔레트다. 스크립트가 돌지 않는 곳에서 도해가 예전 모습으로 그려지게 한다. 그래서 `surface`의 대체값은 `none`이고, 범주 면의 대체값은 예전 채움 색이다.
- `text`, `on-fill`, `surface`는 사이트 색 토큰(`darkgray`, `lightgray`)을 가리킨다. 스크립트가 사이트 문서의 계산된 CSS 변수에서 읽으므로 값을 옮겨 적지 않는다.

## 바꿀 때

1. `quartz.config.yaml`의 `theme`나 도해 규약의 도해 팔레트 표를 고친다.
2. `npm run palette`로 하한을 확인하고, 이 문서의 실측 표를 출력으로 바꾼다. 화면에 칠해진 색은 [접근성 자동 검사](engine.md#화면을-고칠-때)로 본다.
3. `npm run build` 뒤 로컬 프리뷰에서 두 테마를 보고, `public/`의 OG 이미지(`*-og-image.webp`)에 두부가 없는지 본다. `--serve`로 볼 때는 `OG_IMAGES=1`을 준다([배포](deploy.md#로컬-프리뷰)). 폰트를 바꿨다면 한글, `Æ`, `Ω`가 폰트에 있는지도 본다.
