## 고친 파일

고친 파일 목록은 따로 적지 않고 기준선과의 `git diff`로 계산합니다. 고친 이유는 각 파일 안의 주석에 있습니다.

```sh
git fetch https://github.com/jackyzha0/quartz.git 97a2d05f80c4c50534959b1d0d41cc4b3895625e
git diff --name-only --diff-filter=M 97a2d05f80c4c50534959b1d0d41cc4b3895625e HEAD -- . ':!README.md'
```

`README.md`는 이 저장소의 소개라 엔진 파일로 보지 않고 뺍니다. 엔진 트리(`quartz/`) 안에 더한 파일은 `--diff-filter=A`로 봅니다. 더한 이유는 파일 맨 위의 주석에 있습니다.

```sh
git diff --name-only --diff-filter=A 97a2d05f80c4c50534959b1d0d41cc4b3895625e HEAD -- quartz
```

JSON 파일은 주석을 달 수 없어서, npm 관례에 따라 최상위 `"//"` 키에 이유를 적습니다. `tsconfig.json`은 주석을 허용하는 JSONC라 주석으로 적습니다.

이미지도 주석을 달 수 없어서 이유를 여기 적습니다.

- `quartz/static/icon.png`: 소유자의 손글씨 아이콘입니다(#85). favicon과 OG 이미지가 이 파일을 읽습니다.

## 설정

사이트 설정은 `quartz.config.yaml`에 둡니다. 업스트림 기본값인 `quartz.config.default.yaml`은 고치지 않고, 설정 로더가 `quartz.config.yaml`을 먼저 읽습니다. 기본값과 다르게 둔 항목 가운데 값만 봐서 이유를 알 수 없는 것은 `quartz.config.yaml`의 주석에 이유를 적습니다.

## 태그 목록

태그 목록 페이지는 tag-page 플러그인이 만듭니다. 태그의 한국어 표시 이름은 `content/tags/<구역>.md`, `content/tags/<구역>/<주제>.md`의 `title`로 주고, 본문은 비워 둡니다.

- 표시 이름 파일이 있으면, 그 태그를 쓰는 페이지가 없어도 태그 목록 페이지가 생깁니다. 이때 목록은 비어 있습니다.
- 상위 태그 목록(`tags/network`)은 하위 태그 목록(`tags/network/can`)으로 링크하지 않습니다. 대문이 두 층을 모두 직접 링크하는 이유입니다.
- 대문의 링크는 `[[tags/network|네트워크]]`처럼 표시 이름을 한 번 더 적습니다. 별칭이 없는 위키링크는 대상 페이지의 `title`이 아니라 경로의 마지막 부분(`network`)을 보여 주기 때문입니다.
- 표시 이름 파일은 태그 경로를 따라 `content/tags/` 아래 폴더에 둘 수밖에 없습니다. 슬러그를 폴더 없는 한 네임스페이스로 두는 규칙에서 `tags/`는 예외입니다.
- `content/tags/index.md`의 `title`은 브레드크럼에서 태그 목록으로 가는 마디의 이름입니다. 없으면 경로 이름(`tags`)이 나옵니다.

## 대문

대문(`content/index.md`)의 본문은 위키 링크로 쓴 구역 표 하나입니다. 행은 구역, 둘째 칸의 링크는 주제이고, 표 위에 제목을 두지 않습니다. 대문만 그리는 로컬 페이지 타입(`plugins/front-page`)이 빌드할 때 구역 이름을 구역 색으로 칠하고, 주제 칩마다 그 주제의 페이지 수를 붙입니다.

- 새 주제는 그 구역 행에 링크를 하나 더하고, 새 구역은 행을 하나 더합니다. 페이지 수와 탐색기 순서는 따라오고, 구역 색은 [팔레트](palette.md#새-구역에-색을-더할-때)의 절차로 더합니다.
- 페이지 수는 태그 목록 페이지와 같은 규칙으로 셉니다. 계산 규칙은 `plugins/front-page`에 있습니다.
- 본문 아래는 2단입니다. 왼쪽은 주간 소식, 오른쪽은 최근 변경입니다. 좁은 화면에서는 1단으로 쌓고, 비어 있는 칸은 숨깁니다.
- 주간 소식 칸은 최신 호의 주요 소식을 최근 변경과 같은 타임라인으로 보입니다. 발행일마다 최근 날부터 마디를 두고, 그 아래 원문을 새 탭으로 여는 원어 제목과 제목 아래의 구역 칩을 둡니다. 칸 제목 줄에는 그 호로 가는 "N건 모두 보기"(N은 그 호의 소식 항목 수)와 지난 호 링크가 있습니다. 주간 소식 플러그인(`plugins/weekly-news`)이 파일마다 읽어 둔 소식 항목에서 고릅니다. 주요 소식이 없는 호면 그렇다는 한 줄과 제목 줄 링크만 두고, 주간 소식이 없으면 칸을 비워 둡니다. 주요 소식을 고르는 기준은 [소식 조사](../.claude/skills/wiki-news/SKILL.md#6-주요-소식)에, 형식과 노출 범위는 [주간 소식](weekly-news.md)에 있습니다.
- 최근 변경은 `content:` 커밋을 PR 단위로 묶어 날짜별 타임라인으로 보이고, 묶음 제목은 그 PR로 링크합니다. 묶는 규칙과 개수는 `plugins/front-page`에 있습니다. 빌드할 때 git 기록에서 읽으므로 배포 빌드도 전체 기록을 받습니다([배포](deploy.md#커밋-기록)).

## 탐색기

탐색기는 폴더 대신 태그로 구역 › 주제 › 페이지 트리를 그립니다. 트리 규칙과 탐색기에 잇는 방식은 `plugins/explorer-tree`에 있습니다.

- 구역과 주제의 이름은 표시 이름 파일의 `title`에서, 구역 순서는 대문에서 옵니다. 새 태그는 표시 이름 파일과 대문 구역 표의 링크만 더하면 트리에 따라옵니다.
- 구역 순서는 대문에서 구역 링크(`tags/<구역>`)가 처음 나온 순서로 읽습니다. 대문의 구역 표 위에 구역 링크를 두면 탐색기의 구역 순서가 바뀝니다.
- 주제와 페이지는 한국어 정렬(가나다 뒤에 로마자)의 오름차순이라, 대문에 적은 주제 순서와 다를 수 있습니다.

## locale

사이트 locale(`quartz.config.yaml`의 `locale`)은 `ko-KR`이고, 참고문헌의 CSL만 `en-US`입니다([ADR 0021](adr/0021-ui-locale-and-csl-locale.md)).

- UI 문구, 화면의 날짜, 문서의 `lang`이 사이트 locale을 따릅니다.
- 읽는 시간은 본문 위에도 OG 이미지에도 보이지 않습니다. 까닭은 `quartz.config.yaml`의 content-meta 주석에 있습니다.
- 참고문헌의 고정 문구(`Accessed`, `[Online]. Available` 등)와 인용 번호는 CSL의 `en-US`로 냅니다. 빌드는 CSL locale 파일을 원격에서 받지 않습니다.
- 화면의 날짜 하나는 ISO 8601(`2026-10-05`)로 씁니다. 폭이 늘 같아 목록에서 세로로 맞고, 프론트매터와 인용하는 표준 문서의 꼴과 같습니다. 기간은 `10월 5일 ~ 10월 11일`로 쓰고, 기준 해와 다른 날짜에만 연도를 붙입니다(`2025년 12월 29일 ~ 1월 4일`). RSS의 `pubDate`는 RFC 822라 영어 그대로입니다.
- UI 이름은 [위키 규약의 용어](wiki-conventions.md#용어) 순서로 고릅니다. 검색, 탐색기, 그래프 뷰, 목차, 백링크 같은 이름은 기술 용어가 아니라 화면의 안내 말이라, 한국어 화면에서 원어가 자연스럽지 않아 한국어로 씁니다. 원어로 두는 것은 고유 이름(Æ wiki, Quartz, GitHub)과 푸터의 출처 표시 줄(`Created with Quartz`)입니다. 출처 표시 줄은 한국어 사이트에서도 원어로 두는 일이 흔하고, 한국어 문구(`제작:`)를 앞에 붙이면 Quartz가 사이트를 만든 주체로 읽힙니다.

### npm 플러그인 패치

npm 플러그인은 저마다 번역 사본을 품고 있어, 엔진의 번역 파일을 고쳐도 플러그인 문구는 바뀌지 않습니다. 사본이 영어이거나 영어를 코드에 박아 둔 곳은 `patches/`의 패치로 고칩니다. `npm ci`의 `postinstall`이 patch-package로 입힙니다. 고친 플러그인은 `ls patches/`로 보고, 고친 이유는 패치가 더한 `// ash-wiki:` 주석에 있습니다.

- 패치는 `node_modules`의 파일을 고친 뒤 `npx patch-package <패키지>`로 만듭니다.
- 플러그인을 올려 패치가 맞지 않으면 `npm ci`가 실패합니다. 새 버전에서 같은 자리를 다시 고쳐 패치를 만듭니다. 업스트림이 번역을 고쳤으면 그 패치를 지웁니다.
- 엔진의 번역(`quartz/i18n/locales/ko-KR.ts`)은 엔진 파일이라 패치 없이 직접 고치고, 이유를 주석에 적습니다([고친 파일](#고친-파일)).

## 인용

`[@키]`를 citations 플러그인이 IEEE 스타일의 번호로 바꾸고, 페이지 하단에 참고문헌을 붙입니다([ADR 0003](adr/0003-engine-and-citation-stack.md)). 표기 규칙은 [위키 규약](wiki-conventions.md)에 있습니다.

- `npm run build`의 prebuild(`npm run bib`)가 `bib/`의 엔트리 파일을 합본 `bibliography.bib`로 합칩니다. 합본은 추적하지 않습니다.
- citations 플러그인은 참고문헌의 URL을 텍스트로 둡니다. 그 뒤에 도는 로컬 플러그인(`plugins/bibliography-links`)이 참고문헌 항목 안의 URL을 새 탭 링크로 바꿉니다. 본문의 외부 링크는 crawl-links의 `openLinksInNewTab`이 새 탭으로 엽니다. 위키링크, 인용 번호 같은 내부 링크는 같은 탭에서 열립니다.
- 페이지 설명(메타 설명, OG 이미지, 피드)과 검색 본문에는 인용 표시가 없습니다. 로컬 플러그인(`plugins/citation-free-description`)이 인용 표시를 뺀 본문 글로 만듭니다. 까닭은 `quartz.config.yaml`의 주석에 있습니다.
- 인용 번호는 대괄호째 위첨자로 보이고, 참고문헌은 "참고문헌" 라벨 아래 번호 열과 항목 열로 보입니다. 모양은 `quartz/styles/custom.scss`가 맡습니다.
- CSL은 저장소가 소유합니다(`csl/ieee.csl`). 고치지 않고 가져온 그대로 둡니다.
